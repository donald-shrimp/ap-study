01 / 開始ボタン

始める前に、問題数を選ばなくていい。

1／3／5問の選択は、今の実装では学習内容をほとんど変えません。通常学習の入口は、「とりあえずはじめる」ひとつを推奨します。

開始

押すと1問目を表示。設定や確認画面を挟みません。復習日が来た問題・未着手など、現在の出題優先順位を保ちます。

回答後

「次の問題」と「今日はここまで」。自動で次に進めず、いつでも終えられます。回答途中は「中断」で保存します。

自由に続けることと、終えやすいことを両立。

「今回4問」は表示できますが、「あと1問」「目標未達」は通常学習には出しません。回答後の終了ボタンは、次へ進むボタンと一緒に残します。

分野別演習も、分野を選んだら「この分野をはじめる」に統一します。分野内を一巡した後も、その分野で解き直せる現在の挙動を保ちます。

実際に、1／3／5問で何が違う？
  • session.goal と次回用の目安を保存する。
  • 上部の「今回○問・目安○問」が変わる。
  • 目安に到達すると「○問の目安完了」を表示する。

出題順は基本的に同じです。目安を超えても「次の問題」は押せます。上部が「中断」から「ホーム」になるのは、問数ではなく回答確定の前か後かで決まります。

確認箇所：src/ui/views.js の sessionMilestoneHTML・studyHTML、src/app.js の start-session・pickQuestion。

一本化するときに整理するデータ

通常学習の session.goal と settings.sessionSize、目安完了表示を廃止します。まとまりとしての attemptIds と分野指定は、今回の取り組み数や同じ問題の連続出題を避けるために残します。

診断の固定問題数や計画の目標回数は、通常セッションとは別に保存します。既存の履歴・ヒント・学習中の問題は保持します。

02 / ホーム

開始ボタンが、いつも最優先。

診断と計画を大きなカードで並べると、始める前に読む量が増えます。現在のホームを土台に、下側にコンパクトな入口をひとつ追加します。

  • 中断中：「続きから」を最上部に表示。新しい問題もすぐ始められます。
  • 未登録：下側に「受験日・計画を登録」「10問で今の状態を確認」の入口。案内は閉じられます。
  • 登録済み：同じ位置を、試験までの日数と現在のフェーズ・実績に置き換えます。
  • 診断済み：大きな案内を繰り返さず、結果・再診断は詳細画面に置きます。

初回ウィザードなし。登録・診断・ログインは任意。

計画の読み込みや通信の完了も、開始ボタンの待ち時間にしません。ホームに週別グラフやフェーズ一覧を展開しません。

ホームで増やさないもの

新しい上部ナビを一度に増やさず、計画の詳細画面から診断・AI入出力へ進める形にします。達成の詳細や履歴は現在の入口を使います。

「今日のおすすめ」は後の段階で、理由が分かる任意の入口として追加します。計画の都合で通常の開始ボタンの出題を勝手に変更しません。

03 / 実力診断

測るのは、今回確認できた範囲。

通常学習と診断では、「終わり」の意味が違います。診断には専用の記録を作り、問題表示・採点・ヒントは今の部品を使います。

通常学習

問題数は決めず、1問ずつ続ける。いつ終えても完了です。

診断

開始時に10問／30問の一覧を確定。「7／30問」の途中状態でも結果を確認できます。

出題と結果のルール

  • 現在の17分野を10問で網羅できないため、クイック診断は「一部の分野の確認」と明示する。
  • 30問は複数分野から抽出する。配分は資格定義に置き、通常の復習優先の出題処理と分ける。
  • 未着手を優先する。既出が含まれたら、その件数を表示する。別年度の類似問題まで初見とは断定しない。
  • ヒントは使える。答えを明かすヒントは、既存どおり「解答閲覧」に分類する。
  • 診断中の解説が後続問題に影響するため、解説は終了後にまとめて読む案を基本とする。
  • 未回答は不正解にしない。オフラインで問題が足りない場合、出題範囲を黙って変更しない。

今回確認した30問：自力18、ヒント付き6、不正解4、解答閲覧2。

データベース：5問中2問自力正解。未出題の分野は「未確認」。合格可能性や、分野全体の習熟は断定しません。

診断結果と、普段の復習をどう共存させる？

診断での不正解・ヒント利用なども通常の復習候補に入れます。後で解き直しても、過去の診断結果は変えません。診断結果はその回の出題枠と試行IDから集計し、問題ごとの最新結果から再計算しません。

診断記録には、ID、対象パート、出題方針の版、確定した問題一覧・版、各枠の試行ID、途中／完了、開始・完了日時を保存します。別端末での継続が分かれたときも、同じ出題枠を二重に数えない設計が必要です。

「回答した件数」は選択して確定した件数。「確認済み」は自力・ヒント付き・不正解・解答閲覧の合計。自力正答率は確認済み件数を分母とし、件数を併記します。未回答は分母に含めません。

04 / 受験日・学習計画

日々のノルマではなく、期間の目安を持つ。

計画は「フェーズ＋目標」が基本です。1日休んでも、その日の未達を翌日に積み上げる仕組みにはしません。診断を受けずに計画を登録しても構いません。

まず表示する

現在のフェーズ、期間、目標回数、実績、残り回数、重点分野。

次の段階で追加する

明示的な週別目標、外部模試・教科書の読了など、手動で完了にするマイルストーン。

「300問」の意味を先に決める

初期版の目標は、解き直しを含む「取り組み300回」を推奨します。既存の完了4状態を数える場合、解答閲覧も含むと明記し、内訳を見られるようにします。「異なる問題300問」は別の指標です。

重点分野はおすすめの対象であり、実績の集計条件とは分けます。初期版では、対象パート内の取り組みを数え、重点分野以外を解いても実績になります。

計画の目標は、開始前に選ぶ問題数ではありません。

「今の期間で120回」を目指していても、今日は1問だけで終了できます。計画達成のために学習セッションを強制継続させません。

受験日・科目・複数資格

試験パートのIDと表示名は資格定義の examParts に置きます。問題にも examPartId を付けます。年度・春秋の教材パックとは別概念です。

受験日は利用者がパートごとに登録。同日でも別日でも扱えます。教材を提供していないパートは、日付と手動マイルストーンを登録できても、アプリ内診断の対象にはしません。

APの制度や日付を共通コードに固定しません。残日数は計画のタイムゾーンの暦日で計算します。過去の日付の計画も履歴として読めます。

週別目標と、実績の数え方

「12日間で300回」だけでは「今週120回」は決まりません。初期版はフェーズ単位。次段で週別目標を明示的に登録します。日数で配分するなら「按分した目安」と表示します。

開始・終了日は両端を含み、初期版はフェーズの重複を認めません。実績は完了日時・対象パート・タイムゾーンから集計します。進捗カウンター自体は保存・同期せず、履歴から再計算します。計画の編集で履歴をリセットしません。

別パートの重複フェーズや複数の有効計画は初期版の範囲外にし、同時に数えるルールが必要になってから追加します。

05 / AI入出力

AIとの往復は、公開JSONで。

AI APIへの直接接続は後回しにします。公開フォーマットとJSON Schema、例、プロンプトを用意し、ChatGPT・Claude・Geminiなどから同じ形で取り込めるようにします。

ひと問の状況をコピー → AIへ相談 → 計画JSONを貼る → 検証 → プレビュー → 登録

  • プロンプトに、その資格で有効なパートID・分野ID・対応版を含める。
  • JSON Schemaで型・必須項目・長さ・件数を検証する。
  • 別途、参照ID、実在する日付、期間の逆転・重複、ID重複を検証する。
  • 未知の版・項目は黙って捨てない。エラーは場所と直し方を表示する。
  • 登録前に、変更する受験日・フェーズ・目標を人間向けに見せる。

検証に失敗しても、現在の計画と学習記録は変更しません。

計画importは、既存の学習記録バックアップの読み込みとは別の入口にします。

提案する StudyPlan JSON を見る

まだ公開仕様ではなく設計例です。morning は説明用の仮ID、日付も仮値です。初期版の目標は取り組み回数のみ。版1を公開する前に、必須・任意項目をSchemaで確定します。

{
  "format": "hitomon-study-plan",
  "version": 1,
  "qualificationId": "ap",
  "timeZone": "Asia/Tokyo",
  "examDates": [
    { "examPartId": "morning", "date": "2026-11-04" }
  ],
  "phases": [
    {
      "id": "foundation",
      "name": "基礎確認",
      "start": "2026-10-07",
      "end": "2026-10-18",
      "examPartIds": ["morning"],
      "targets": { "completedAttempts": 300 },
      "focusTopicIds": ["security", "network", "database"]
    }
  ]
}

公開用JSONにUID・端末ID・同期の版番号・計算済み実績は入れません。公開形式の version と、内部の更新競合に使う revision は別です。

将来、週別目標などを追加する際は、公開済みの版を無断で読み替えず、Schemaの版と対応機能を明示します。初期版ではAIに未対応項目を作らせません。

AIへ渡す学習状況と、エラー表示の例

学習状況は別の hitomon-study-summary 形式で出します。資格、集計日時・タイムゾーン、受験日と残日数、累計・直近7日／28日の取り組み回数、異なる問題数、結果の内訳、分野別の母数・自力正解数、復習候補数、現在の計画と実績を含めます。

診断結果は診断日時・確認済み件数とともに分離します。通常履歴の正答率は「解き直しを含む値」であることを明示。集計の定義を画面とExportで共有します。メール・UID・問題本文・個人メモは、相談用Exportには入れません。

フェーズ2の終了日が開始日より前です。

phases[1].end を、開始日以降の日付に変更してください。

将来の調整案は、根拠となる件数・期間とともに提案します。母数の少ない48%だけでDBを苦手と決めず、ユーザーが採用した案だけ計画に反映します。

06 / 保存・内部構造

受験日と計画は、利用者ごと・資格ごと。

今の利用者×資格の保存単位を使います。ログイン前も端末内で利用でき、ログイン時の取り込みは明示的に行います。

受験日と有効な計画は、初期版では同じ更新単位にまとめます。import時の「日付だけ登録されて計画が失敗する」を避けます。古い計画の比較・複数の有効計画は後回しです。

既存コードで先に整えるべきところ
  • 共通集計：通常演習では attempt.topicId が空になる場合があります。分野集計には記録時点の questionSnapshot.topicId を使います。
  • 問題の所属：資格定義だけでなく、教材・軽量インデックス・試行スナップショットへパートIDを通します。
  • 通常セッション：目安を廃止するため、保存検証とバックアップの形も見直します。診断を既存の最大5問の制約へ押し込みません。
  • 同期：現状は試行専用の送信待ち・カーソル・Firestore Rulesです。計画や診断を自動で同期できる状態ではありません。
  • 競合：計画は版番号で検出し、クラウドと端末の案を選べるようにします。試行用の別記録作成を流用すると、有効計画が二つになるため避けます。

既存の学習記録は保持します。後方互換・大規模な移行機構は目的にせず、今回の変更に必要な保存処理だけ整えます。

確認箇所：試行、端末保存、保存検証、同期、Rules、資格定義。

どのレイヤーを変える？
  • 資格定義・教材生成：試験パート、所属、診断配分。共通コードにAPの条件を書かない。
  • 共通ドメイン：集計、計画検証、実績計算、診断の出題・結果。画面や通信なしで計算できる形。
  • 保存・同期：新しい保存先、送信待ち、更新競合、所有者検証、Rules。
  • 共通UI：一本化した開始、下側の入口、診断・計画詳細、importプレビュー。
  • アプリ制御：操作を各機能につなぐ。計画や集計を src/app.js に詰め込まない。

P0-1 · 通常学習

開始ボタンを一本化

全分野・分野別の1／3／5問を廃止。今回の回数、次の問題、中断、終了、保存・再開を維持します。

P0-2 · 土台と受験日

共通集計とパート定義 → 任意の受験日

集計の定義を統一し、利用者×資格の計画用保存・同期を用意。ホーム下側に日付登録と簡潔な残日数を追加します。

P0-3 · 計画とAI

フェーズ計画と公開JSONの往復

Schema・仕様・サンプル、プロンプトコピー、貼付検証、プレビュー、登録、Export。最低限の手動登録・編集も用意し、AIを必須にしません。実績はフェーズ単位で表示します。

P1 · 診断と週別目標

10問診断 → 30問診断

専用の診断記録、中断・端末間再開、結果、復習連携。その後、週別目標と手動マイルストーンを追加します。

P2 · 調整と本番チェック

80問チェック・調整案・計画履歴

対応教材のあるパートで80問チェック。根拠付きの調整提案を、採用操作を経て反映します。AI APIやMCPの直接接続はこの計画の必須範囲にしません。

診断より先に計画を使える理由

既にある学習履歴からAIへ相談できます。診断の新しい出題・再開・同期を完成させるまで、受験日と計画を待たせる必要はありません。

各段階で確認すること
  • 未登録・未診断・未ログインでも、開始は1操作。
  • 計画の読込失敗やオフラインが通常学習を止めない。
  • 回答後に終了でき、途中の選択・ヒントも再開できる。
  • 既存800問の教材、回答表示、PWAのID・スコープ・オフライン動作を保つ。
  • 不正な計画importで既存計画・履歴が変わらない。
  • 別資格・別利用者のデータを混ぜない。端末間の計画競合を黙って上書きしない。
  • 診断の問題一覧を途中で変更せず、未回答や継続記録を誤集計しない。
  • 小さい画面・大きな文字でも開始が探しやすく、結果の母数が読める。
  • 画面、StudyPlanの実績、AI用Summaryで同じ集計定義を使う。
