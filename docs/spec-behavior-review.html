P0 · S02 · 通常操作で再現

計画の別ブロックを開くと、入力中の文章が消える

「まだ保存していない計画の理由」が空欄になる。保存済みの前提は残るが、入力途中の文章は失われる。

再現・原因・修正案を見る

再現

計画の前提に理由を入力する → 保存せず「AIに相談・JSONを登録」を押す。

原因

open-ai/open-editorで画面全体を再描画する。同期受信時の入力保護はあるが、同じ画面の操作には適用していない。

修正案

ブロックを開くだけなら既存DOMを保持する。編集内容はフォームごとの下書きとして保持し、保存・明示破棄のときだけ消す。

修正後に確認すること

前提・受験日・フェーズ・週別目標・予定の入力を、別ブロックの開閉、エラー表示、同期通知で消さない。

P0 · S05 · 容量不足を注入して再現

バックアップ復元が、失敗時に途中まで反映される

受験日2026-11-04は保存済みになる一方、通常記録は元のまま。画面内の通常記録は取り込んだ内容に変わり、端末の保存内容と一致しない。保存失敗の表示は出る。既存の通常記録は削除されていない。

再現・原因・修正案を見る

再現

受験日を含む学習記録バックアップを取り込む。その後の通常記録の保存だけをQuotaExceededErrorで失敗させる。

原因

workspaceの復元を先に確定し、その後で別DBの通常記録を置換する。失敗時に両者の復元をまとめて戻せない。

修正案

復元対象を先に検証・ステージし、確定単位を揃える。全体の原子的な保存を採用するならDB構成を含めて検討する。部分完了を許すなら項目別の結果を表示し、未保存の候補へ画面を切り替えず、再試行を冪等にする。

修正後に確認すること

計画・診断・通常記録の各段階の保存失敗を注入する。失敗前後のDB、画面、再読込、再試行、同時同期が一致する。

P1 · S01 · 容量不足を注入して再現

紙ペン指定は、保存に失敗してもホームへ移る

画面はホームへ移り、「書いて考える」の続きとして扱う。しかしDBには机指定がなく、元の問題画面の状態が残る。最終的には保存失敗の警告が表示されるが、成功したような遷移と食い違う。事前に保存された回答候補・ヒントは保持されている。

再現・原因・修正案を見る

再現

「身軽に1問」で選択肢とヒントを保存する → 保存処理を失敗させて「この問題は紙ペンが必要」を押す。

原因

await save()の真偽を確認せず、状態変更後にgo(home)する。「あとで解く」の失敗ロールバックとは実装が異なる。

修正案

保存成功後だけホームへ移る。失敗時は机指定・入口・currentIdを戻して、元の問題と回答候補・ヒントを表示する。同様の保存必須操作も点検する。

修正後に確認すること

容量不足でも同じ問題画面を保ち、保存を復旧してから指定し直せる。通常の指定・解除・再開も維持する。

調査時点のコード

P1 · S06 · 実機能＋合成同期イベントで再現

「入力を破棄して最新版を表示」でもJSON入力が残る

更新通知は表示されるが、JSON「{"still":"unsaved JSON"}」は実行後もそのまま。手動編集の状態とプレビューは解除される。

再現・原因・修正案を見る

再現

AI用JSONを入力中に新しい計画の受信イベントを与える → 「入力を破棄して最新版を表示」を実行する。

原因

reload-planningは編集IDとpreviewを初期化するが、jsonInputを消していない。

修正案

破棄する対象を明確にし、JSONも含めた全下書きを一括クリアする。消える内容が複数ある場合は、対象が分かる表示にする。

修正後に確認すること

JSON・プレビュー・手動フォームの全下書きが明示破棄後に消え、受信済みの計画と一致する。同期受信だけでは入力を消さない。

P1 · S04 · UTC端末・時刻固定で再現

記録画面だけ「今日」と学習日が端末の時差に左右される

ホームは今日0回、AI集計も今日0回だが、記録画面は「今日1問」。記録画面の7日カレンダーと「2日以上学習」も端末の暦日を使う。通常の日本時間端末では、この境界のずれは発生しない。

再現・原因・修正案を見る

再現

現在をJST10/8 00:30、回答をJST10/7 23:30に設定し、端末のタイムゾーンをUTCにする。

原因

ホーム・計画・復習はdateInZoneを使うが、motivationHTML/achievementsはutils.dayと端末ローカルの日付を使う。

修正案

記録画面の今日・7日カレンダー・達成日数も、計画のタイムゾーンまたは資格の既定に揃える。診断を含めるかなど、集計対象の違いは日付の問題とは別に維持する。

修正後に確認すること

UTC/JST/ニューヨーク端末で深夜境界を照合。ホーム・記録・AI・復習で日付の基準が一致する。

仕様の改善候補

以下は、今回の5件とは分けて判断したいものです。

I01 · バックアップ取り込みの結果を、項目別に知らせる

仕様どおりの挙動への改善候補・コード確認

既存計画がある場合、その計画は保持され、バックアップの計画は置換しない。取り込み前の説明にも「既存のものは残す」とあるので、上書きしないこと自体はバグではない。完了時に「通常記録は置換／既存計画は保持／診断を○件追加」の結果があると、受験日が戻らなかった理由が分かる。

I02 · 端末の時計ずれによる未来の回答をどう扱うか決める

合成時刻で確認・仕様の判断が必要

同じ日の現在より2時間先にある完了記録は、通常グラフ0件、AIの今日1件、フェーズ実績1件になる。グラフの未来除外は仕様どおりだが、計画・AIは除外しない。全画面で除外するか、時計ずれの目印を添えるかを決めたい。記録を黙って削除しない。
