# 資格・科目をヘッダから選ぶ改修計画

保存日：2026-10-15（JST）。状態：実装・ローカル検証済み。main反映とPages公開確認へ進む。
確認したmain：`d8c99263ff2db383f4edb92e918828929f6b3c43`。関連：[科目A/Bと共通計画](ap-subject-b-plan.md)。

## 目指す使い方

ヘッダに現在の学習対象を「応用情報・科目A ▼」「応用情報・科目B ▼」「AB-730 ▼」と表示する。押すと資格・科目の選択画面へ移動し、学びたい対象を選ぶ。科目Aの受験までAに専念する場合、次回起動でもAを開き、そのまま学習を始められる。

学習・記録画面上部のA/B切替ボタンは外す。選択後のホームでは、現在対象の「はじめる／続きから」を最上段に保つ。

## 選択画面

見出しは「資格・科目を選ぶ」。応用情報を1グループとしてまとめ、その中に2行を並べる。

| グループ | 選択項目 | 教材数の表示 |
| --- | --- | --- |
| 応用情報技術者試験 | 応用情報－科目A | 800問 |
| 応用情報技術者試験 | 応用情報－科目B | 大問1題 |
| Microsoft | Microsoft AI Business Professional（AB-730） | 174問 |

数値は現時点の確認済み教材に対応する。実装では生成されたカタログから表示し、画面へ固定値を書かない。Aの通常問題数に派生・模試を加算せず、Bに資格全体の800問を表示しない。選択中の行を枠色とアクセシブルな属性で示す。デバッグ用IDや繰り返しの説明を足さない。

1科目だけの資格は資格名の1行だけを表示する。将来の資格・科目も定義から生成し、AP専用の分岐を増やさない。提供できる学習対象だけを選択できるようにする。

## 遷移・記憶・保存

1. 学習対象は `qualificationId + examPartId` で扱う。既存の資格ID `ap`、科目ID `objective/written`、資格別保存領域を維持する。
2. ヘッダから選択画面へ出る前に、通常記録・記述入力・メモ・計画の保存を待つ。保存失敗、保存処理中、未保存の計画入力があれば現在画面へ留まり、入力を保持する。
3. 選択リンクは資格の既存URLに科目を指定する。例：`ap/?part=objective`、`ap/?part=written`。直接リンクでも選んだ科目を開けるようにする。
4. 選択画面からの遷移はその科目のホームを開く。入口からホームを開く指定は初回だけ適用・消費し、ページの再読み込みで解答中の画面がホームへ戻ることを防ぐ。
5. 科目がURLで明示されていれば、以前の記憶より優先する。通常起動は前回の資格とその資格の前回科目、初回は資格の有効な既定科目を使う。
6. 既存の「前回資格」「資格別前回科目」の端末保存を共通の関数から読む・書く。対象が有効で教材の準備ができたときに記憶する。選択中の対象は端末の表示設定として扱い、同期の受信で切り替えない。
7. URLに明示された科目が無効なら選択画面へ案内する。無効になった保存済み科目は有効な既定科目へ戻す。localStorageが使えなくてもURL指定で選択できるようにする。
8. A→B→A、AP→AB-730→APでも、それぞれの中断記録を保持する。新しいタブで別対象を開いても、既に開いたタブの対象や入力を変更しない。
9. ブラウザの戻る／進むは選択画面と対象画面を往復する。復元時にはURLの科目と表示・機能が一致することを確認する。

## 共通計画と記録

計画・受験目標は応用情報として共通。計画画面は同じ計画を参照し、Aの問数とBの大問数を別の目標・実績として表示する。記録・復習・集計・中断・AI質問・出題は選んだ科目に対応させる。

科目Bのホームに科目Aの診断・模試・単語帳入口を表示しない。科目Aの復習へBの自己評価を混ぜない。対象選択の変更では学習記録version 2、Firestoreの保存先・Rules、バックアップ形式を変更しない。未実施の本人アカウントへの移行は、引き続き別の進捗として管理する。

## 改修箇所と順序

| 順序 | 対象 | 変更内容 |
| --- | --- | --- |
| 1 | 共通の学習対象処理 | 候補生成、対象の検証、URL指定の優先、端末記憶、表示名を集約する |
| 2 | `tools/build-content.py`、資格カタログ、`src/content/catalog.js` | 選択に必要な有効科目・ラベル・単位別教材数をカタログに生成する。選択画面のために全資格の問題本文を読み込まない |
| 3 | `src/ui/qualification-navigation.js`、`styles.css` | APのグループと科目別リンク、現在対象のヘッダ、幅・間隔・操作領域を実装する |
| 4 | `src/app.js` | `targetControls()`の画面出力・旧切替イベントを外し、初期対象の解決とヘッダ・ホーム・記録の対象を揃える。保存してから選択画面へ出る処理を共通化する |
| 5 | 既存テスト・仕様書・PWA | 旧A/Bボタン操作のテストを新しい導線へ移し、URL・再読込・中断・保存失敗を検査。公開シェルを更新する |

既存の科目別学習処理・教材レビュー・採点は再利用する。共通計画や各保存領域を複製しない。

## 見た目

- 「ひと問」、対象選択、設定の間隔を維持する。▼はそのまま使う。
- 小さな画面でも「科目A／科目B」が読めるよう、資格名と科目表示を分けて制御する。省略が必要なら資格名を優先して省略する。
- 選択画面は既存のPC用中央1列・最大幅を維持し、細い縦長カードへ戻らない。
- 行全体を押せるようにし、キーボード操作・選択状態・フォーカスを扱う。遷移するリンクとして実装し、展開メニューのようなARIA属性は付けない。

## 今回の計画作成で確認したこと

資格カタログには現状、資格全体の名前・URL・800/174問の件数だけがあり、科目別候補はない。科目はAP manifestに定義され、アプリが資格別localStorageから読む。画面の先頭へA/Bボタンを追加し、そのボタンが状態を切り替える構成になっている。ヘッダから出る処理には既に保存待ちと計画草稿の保護があるため、これを活用する。実装ではヘッダとひと問リンクへ同じ保存ガードを適用し、URL指定・ホーム入口の一回適用・前回の記憶を共通化した。Bの本文はBを開くときに読み込み、Bが未保存でもキャッシュ済みのAを開ける。記録・Rules・バックアップの契約と教材本文は変更していない。
