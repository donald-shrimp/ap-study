# AIに聞く — 実装・レビュー記録（2026-10-12）

回答後に理解できなかった問題を、ChatGPT・Gemini・Claudeへ相談するための質問文にまとめる。解説の下に控えめな「AIに聞く」を置き、通常学習の開始・継続を優先する。診断・模試の受験中には表示しない。

## 動作

- 採点・解答閲覧後の問題と教材スナップショットを使用し、本文・4択・正解・本人の回答・解説・選択肢理由・教材ヒント・任意の質問をまとめる。
- 文字起こし済みの本文を使用し、本文がない問題の検索用OCRは渡さない。原本・図のURLと画像を開く導線を提供し、同じURLは重複させない。画像の添付は利用者が行う。
- 「質問文をコピー」の成功を表示し、同じボタンを「ChatGPTを開く」等へ切り替える。利用者がもう一度押したときに端末内への学習記録の保存成功を待ち、同じタブで外部AIへ移動する。コピー直後に自動移動しない。コピー拒否・未対応時は移動せず、手動コピー欄を表示する。質問文だけをコピーすることもできる。手動コピー後のリンクも保存完了を待ち、保存失敗時は問題画面に留まる。
- コピー中は宛先・質問文を固定し、閉じる／Escapeでキャンセルした処理は後から遷移しない。開き直したダイアログへ旧処理の結果を反映しない。
- 学習記録・Firebase・教材・資格定義は変更しない。AI API・自動送信・Intentによるアプリ起動は使用しない。

## PR #1のレビュー

作者のPRを主担当/rootがコードレビューし、最新main（文字表示498問＋原本保持2問）を取り込んで検証した。元PRでコピー待ちに閉じても遅れてChatGPTへ移動する不具合を実ブラウザで再現し、キャンセル判定と処理中の入力固定で修正。原本URLの重複除去も追加した。

PRのE2Eテストは2枚目のタブが保存済み演習画面へ戻ることを考慮しておらず、ホームボタン待ちで停止していた。保存後の再開状態からも開始できるよう修正し、AIから戻った後の記録保持・3宛先・ネイティブクリップボード・キャンセル／再表示・キーボード操作を追加。既存E2Eの文字起こし後の折りたたみ原本参照と、PWAテストのチェックアウト名への依存も修正した。

PR #1の公開確認後、端末保存を意図的に遅延させて、採点直後にAIへ移動すると戻った画面で採点前の記録になることを再現した。質問文は先にコピーし、その後に既存の保存処理の完了を待ってから移動するよう修正。失敗時は移動せず、記録の書き出しを案内する。手動コピー後のリンクにも同じ条件を適用する。

`tests/ai-handoff-saving.py`で遅延保存・保存中の閉じる／開き直し・保存失敗と再試行・手動リンクの保存待ちを確認。31ドメインテスト、AI E2E、実教材／オフライン、PWA更新、複数資格／文字起こし検査も再実行して成功。教材・データ形式・Firestore Rulesは変更せず、PWAシェルは`20261012-ai-handoff2`へ更新する。


## Androidの貼付報告を受けた改修（2026-10-12 JST）

利用者から、Androidでコピー後すぐに移動すると貼付が前回の内容になる一方、OSクリップボードには正しい内容があるとの報告。受信側AIやキーボードの状態はこの環境で再現・断定できていない。コピー完了Promiseだけでは受信側の貼付候補更新を確認できないため、コピー直後の自動遷移を取りやめた。同じ主ボタンの1回目は「質問文をコピー」、成功後は「ChatGPTを開く」等となり、2回目の明示操作で移動する。保存完了待ち・失敗時停止・キャンセル判定は維持。詳細文を変更したらコピー待ちへ戻す。コピー後の宛先変更は質問文に影響しないのでコピー済みを保持する。コピーだけ・失敗時の手動欄も維持。

入口ボタンを初期のdocs/ai-explanation-mock.htmlに合わせ、横幅いっぱい・淡い緑・吹き出しアイコン・中央の短い補助文へ戻した。通常演習の継続操作を妨げず、診断・模試中は表示しない。教材と学習記録の形式・Firebase Rulesは変えない。PWA版は20261012-ai-handoff3。Android実機で報告症状が解消したかは利用者の再確認が必要。

この改修ではtests/ai-handoff-e2e.pyの実クリップボードと2操作・編集後再コピー・全3宛先、saving/content、NodeのAI/通常学習、PWA更新、生成/複数資格検査が成功。入口とコピー前後のスマホ幅画面も主担当が目視確認した。コピー検証のAndroid UAはChromiumのエミュレーションであり、Gboard等の実機貼付候補は確認していない。
