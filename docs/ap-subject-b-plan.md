# 応用情報の科目A／B分離と科目B学習の実装計画

保存日：2026-10-14。状態：ユーザーの実装指示とバックアップ済みの確認を受け、2026-10-15 JSTに実装中。進捗はap-subject-b-progress.jsonを参照。公開・本人記録の取り込みを未実施のまま完了扱いにしない。

## 合意した方針

- 応用情報の学習画面と記録を科目A／科目Bに分ける。受験目標・計画は応用情報として共通化し、受験日は科目別に登録する。
- 表示名はIPAの「科目A」「科目B」を使う。科目Bは旧午後試験に相当する記述式。資格を別々に複製する必要はなく、共通の応用情報配下で科目を識別する。
- 最優先は「開いたら迷わず、すぐ始められる」。現在の学習対象に対応する「はじめる／続きから」を最上段に置く。
- 現ユーザーは1人。旧保存形式・旧StudyPlanを新アプリで読み続ける後方互換性は不要。新形式に統一し、移行は保存されたファイルを一度変換して登録する。
- 旧コードとデータは移行確認まで保管する。後方互換性を省くことと、教材・レビュー根拠・記録を失うことを混同しない。
- 計画保存後、ユーザーから実装開始の指示と記録バックアップ済みの確認を受けた。旧DBは削除せず、新形式の別保存領域へ切り替える。本人バックアップの変換・取り込みはファイル受領後に行う。

## 現状の足場と不足

`content/ap/qualification.json` は資格ID `ap` に `objective`（選択式）と `written`（教材未対応）のパートを持つ。受験日は科目別に保存可能。内部IDの採用方針は新形式の確定時に決め、変更する場合は変換表を残す。

現状のホーム出題や一部集計は科目未指定、記録画面への遷移でもパート指定が解除される。科目Bのフラグを有効にするだけでは混在する。`freeText` は未確認草稿の保管のみ。公開生成・学習・採点・同期は選択問題を前提にしている。

計画目標は `completedAttempts`（取り組み回数）だけ。Aの四択1問とBの長文1題を足さず、科目・単位を識別する目標が必要。既存の良い機能・教材は新形式へ引き継ぐ。

## 新基盤の共通概念

1. **学習対象**：資格＋科目。選択中の対象を出題・記録・復習・中断再開・今日の実績・機能表示へ一貫して渡す。1対象だけの資格には追加選択を強制しない。
2. **教材**：単独問題、または共通本文を持つ大問。元の言い回し・図表・条件を保つ。
3. **学習記録**：回答・支援利用・日時・教材版などの共通項目を揃える。四択の回答と大問内の回答に必要な情報はそれぞれ定義する。
4. **評価**：自動判定・自己評価・将来のAI評価を識別。回答済みと評価済みを分ける。
5. **計画**：共通のフェーズ・前提と、科目別の単位付き目標。週別目標・履歴・AI Exportも同じ新形式に統一する。

旧新の検証器・計画形式をアプリ内で並行運用しない。旧形式の変換はアプリの通常処理から分離した専用ツールに置く。選択問題では位置番号などの冗長な回答表現を整理し、安定した選択肢IDで扱う。

## 科目Bの大問構造と画面

- 大問：共通本文・図表・出典・教材版。
- 小問：設問文・本文参照・解説。
- 解答欄：回答形式・字数制限・解答例・採点観点。小問内に複数欄を持てる。
- 共通本文を各小問へ複製しない。大問の関連付けには大問用のIDを使い、派生問題の親IDとは区別する。
- スマホは小問と入力欄を中心に、本文を見に戻れる画面。PCは本文と入力欄の左右表示を候補にする。実装前に代表大問でモックを確認する。
- 入力途中の回答・本文位置・次の小問を自動保存。AとBの中断をそれぞれ維持する。別端末の同期で、今開いている科目を勝手に切り替えない。
- 学習では小問ごとの解説確認、本番練習では大問終了まで解答を伏せる。支援閲覧を記録し、同じ大問の解答から後続小問への影響も設計時に扱う。

## 採点と集計

- 選択肢・記号：通常の自動判定。
- 用語：独立確認した正答候補・表記揺れを登録。未登録表現を要確認にできる。
- 数値：問題固有の単位・許容範囲を定義。
- 説明文：まず解答例と問題固有の確認ポイントを示して自己評価。「要点を満たした／一部足りない／解けなかった／判断に迷う」を候補とする。
- キーワードや文字類似度だけで説明文の正誤を断定しない。否定・因果関係などを落とす危険がある。
- IPAの解答例・採点講評から学習用の観点を作り、別担当が確認する。本番と同じ部分点を保証しない。過去問道場の独自解説・採点コードを教材へコピーしない。
- Aの自力正答率と、Bの自動判定／自己評価／将来のAI評価は分ける。問題数・回答欄数・大問数も区別する。
- 大問途中の取り組みを完了1題と数えない。完了・部分終了・評価待ちの定義を実装前に決める。

## 共通計画

同じフェーズに「科目A：100問」「科目B：大問3題」を持つ。科目・単位・目標数を目標に保存し、週別目標と実績も対応させる。

表示例：

> 今週：科目A 100問中73問／科目B 大問3題中1題。
> 次はセキュリティ設問2の続き。

計画編集・履歴・AIプロンプト・Summary Export・バックアップ・Firebase Rulesを新形式で揃える。変換時は、昔の取り組み回数を大問数へ読み替えず、過去の意味と評価方法を保持する。

## 推奨する実装順

1. 新しいデータ形式と「資格＋科目」の管理を確定する。
2. 科目AとAB-730を新基盤へ載せ、既存の学習体験を検証する。
3. 科目Bのセキュリティ大問1つを独立確認し、本文・小問・入力・自己評価・中断再開を試す。
4. 共通計画・同期・バックアップ・AI質問を新形式で揃える。
5. 切替直前の保存ファイルを変換・取り込みして本番を切り替える。旧コードはGitタグ等で保存、新しい保存領域を使って旧データを移行確認まで残す。
6. 短答の自動判定・教材拡充・5大問を通す本番練習へ広げる。

## ユーザーが保管するファイル

切替直前にGoogleログインし、「今すぐ同期」で完了を確認してから保存する。既存UIの場所は「設定 → 記録・教材の管理」。

1. 応用情報：「学習記録を書き出す」。
2. AB-730：「学習記録を書き出す」。
3. 応用情報：「個別の書き出し・取り込み → 単語帳の記録を書き出す」。

現在の学習記録書き出しは、受験日・計画・計画履歴・診断・模試・学習設定も含む。単語帳イベントは別ファイル。ログイン前の記録や端末固有の教材編集も残す場合は、その端末からも書き出す。重複と編集の競合は変換時に整理し、曖昧な選択は確認する。

変換は担当アシスタントが行う。個人の記録ファイルを公開リポジトリへ追加せず、変換結果を本人アカウントへ取り込める導線を用意する。本人のブラウザ操作・本番DB書込みが可能かは移行時に実際の接続から判断し、未実施を完了扱いにしない。

## 確認すること

- AからBの出題／復習／診断へ意図せず移らない。B画面にAの診断・単語帳を自動表示しない。
- A／Bの中断を両方保存でき、別端末でも回答・本文位置・教材版を維持する。
- 同じ大問の未解答部分を先の解説が漏らさない。支援なしの受験では解答・解説・AIを出さない。
- 自己評価をAの正答率へ加算しない。A／Bの目標単位を混ぜない。
- 旧記録の変換で件数・日時・正誤・支援・計画・履歴・模試・カード・教材編集を照合する。
- AP800問、681カード、180派生、固定模試、AB-730174問と既存確認根拠を保つ。
- スマホ320／390px、PC、保存失敗・競合・中断・再開・オフライン・バックアップ・同期を確認する。
