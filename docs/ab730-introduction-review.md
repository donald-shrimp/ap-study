## 資格追加より先に整える共通仕様

| 共通仕様 | 整える内容 |
|---|---|
| 診断・模試の実行 | 同じ受験セッションの仕組みで、問題数・支援の可否・採点のタイミング・固定順／抽出をモード設定から扱う。普段の学習、診断、模試の集計と表示上の区別は保つ |
| 問題数と配分 | 診断30問・模試80問を共通コードから設定へ移す。分野均等／重み付きの配分、専用教材の優先と上限も資格側の出題方針に置く。APの設定は30問／80問のまま |
| 教材の用途と由来 | 通常学習・診断・模試の用途と、公式原本・独自・派生という由来を分ける。確認済み独自問題を診断・模試へ直接登録できるようにする。実際の派生問題だけ母問題参照を必須にし、母問題のない独自問題に架空の親を付けない |
| 重複回避 | 同一の問題IDを重複させない。母問題や共通シナリオがある場合は資格内の問題ファミリーで重複を避け、独立した問題は自身のIDで区別する |
| 版・言語・根拠 | 対象範囲の版、言語、出題目標、出典、確認日、教材ハッシュの共通作成形式を決める。公開対象と過去の保存スナップショットを区別し、対象版変更で既存記録を消したり読み替えたりしない |
| 検証・同期 | 生成・読込・実行・保存検証・Firestore Rules・テストの制約を揃える。問題数を任意値として無制限に許可せず、上限、slotsの件数、回答範囲、所有者、資格の一致を検査する |
| 画面と追加手順 | 公開済み教材と対応形式から入口を表示する。資格を増やす際は定義と教材を追加し、共通UIに資格IDの条件分岐を増やさない |

共通化の完了条件は、APの30問診断・80問模試・既存記録を保持したまま、架空の資格で別の問題数、母問題のない独自問題、異なる出題配分、同じ問題IDの記録分離を検証できること。開始済みセッションの問題・対象版・配分・問題数は開始時に固定し、現在の資格設定が変わっても受験途中の内容や採点を変えない。

複数選択や並べ替えなどは追加方法の契約を整理するが、今回すべてを実装する必要はない。必要な形式が決まったとき、問題の表示・採点・保存を共通側で拡張できるようにする。単一選択の既存処理を活かし、共通整備の範囲を上記の具体的な制約に絞る。

## 何を学ぶ資格か

正式名称はMicrosoft Certified: AI Business Professional。AB-730はその試験コード。生成AIとMicrosoft 365 Copilotを仕事に活用する初級の資格で、コードを書く技能を前提にしていない。Word・Excel・PowerPoint・Outlook・Teamsなどの利用経験が想定されている。日本語受験に対応し、試験時間は公式ページで45分と案内されている。本番の問題数・形式の内訳は、この調査でAB-730固有の確定値を確認していない。[公式資格ページ](https://learn.microsoft.com/ja-jp/credentials/certifications/ai-business-professional/)

2026-10-13に開いた資格ページの分野表示は次の3つ。

1. 生成AIの基礎
2. プロンプトと会話の管理
3. ビジネスコンテンツの作成・分析

基礎用語だけでなく、「この業務でどの機能を使うか」「どんな情報をプロンプトに含めるか」「生成結果をどう確認するか」を判断する練習が向いている、というのが本調査からの設計判断。

## 問題はどう用意するか

APの年度別過去問PDFとは教材供給の仕組みが違う。Microsoftの本試験問題は受験者契約で機密として扱われ、公式の無料Practice Assessmentは本試験の問題ではない。ひと問では**公式Learnの説明を根拠とする独自の学習問題**を作る。公式評価は外部へのリンクを置き、問題・解説の転載を前提にしない。[受験者契約](https://learn.microsoft.com/en-us/credentials/support/certification-exam-candidate-agreement)、[公式Practice Assessmentの説明](https://learn.microsoft.com/en-us/credentials/certifications/practice-assessments-for-microsoft-certifications)

各問に、問題文・単一選択の4択・3段階ヒント・解説・各選択肢の理由を付ける。教材を作る際の確認は次を必須とする。

- 出題目標とMicrosoft公式資料の該当箇所を結び付ける。
- 正解の一意性と、他の3択が不適切な理由を公式資料から確認する。
- Copilot Chat／Microsoft 365 Copilotの違い、ライセンス、参照できる情報など、正解を変える前提だけを短く書く。
- 画面の位置を暗記させる問題や、根拠のない「いつでも・必ず」を避ける。
- ヒントは問題の目的・制約・参照資料などから、具体的な最初の判断を示す。
- 作者と異なる確認者、公式資料の確認日、対象版、完成教材ハッシュを残す。確認できない問題は公開しない。

実際のCopilotで操作する体験は公式学習リンクを使う。ひと問内でCopilot環境やMicrosoft Learnの履修状態を再現・同期する機能は初期版に含めない。[公式コース](https://learn.microsoft.com/ja-jp/training/courses/ab-730t00)、[公式ラーニングパス](https://learn.microsoft.com/ja-jp/training/paths/transform-business-workflows-with-ai/)

## データの置き方

以下は提案。ファイルはまだ登録していない。

```text
content/ab730/
  qualification.json       # 資格・分野・1つの試験パート
  questions.json           # 通常演習用の独自問題
  flashcards.json           # 用語・機能の違い
  syllabus.json             # 対象言語・版・出題目標の対応表（新規提案）
  sources.json              # 公式URL・確認日・資料の版（新規提案）
  question-reviews.json     # 独立確認の根拠と教材ハッシュ（新規提案）
  diagnostic-questions.json # 診断教材の確認後。通常問題とは別ファイル
  diagnostic-reviews.json   # 共通の確認形式に対応
  mock-sets.json            # 共通整備と教材確認の後
```

識別子は`qualificationId: ab730`とし、問題は`ab730-study-001`など安定したIDを使う。表示名や対象範囲を変更しても資格IDを変えない。`correctChoiceId`は既存形式を使い、出典ラベルは「公式資料に基づく独自問題」とする。「公式問題PDF」「公式解答PDF」ではなく「参考資料」などを設定する。

出題目標・資料確認・版の監査情報は共通の作成形式に合わせる。既存の同期payloadへ未対応の項目を追加しない。通常教材の`reviewed`という文字列だけでは独立確認を保証しないため、共通のレビュー・完成ハッシュ検査と、AB-730固有の資料確認を組み合わせる。
