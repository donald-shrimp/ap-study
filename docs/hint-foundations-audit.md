# 初学者向けヒントの土台点検基準

目的は、**対象論点の用語や仕組みを知らない人が、問題とヒントから必要な足場を学べるか**を、一問ずつ根拠付きで点検すること。候補抽出と編集上の優先順位を揃える基準であり、学習効果の測定、内容不具合の確定、改稿の承認ではない。

品質の正本は[ヒントの共通ルール](hint-authoring.md)。この基準は初学者の足場に点検の焦点を絞る。既存のヒント品質承認を、この観点の確認済みへ読み替えない。担当・保存先・一つのPRへの追記・集計手順は[点検作業の入口](../work/ap/hint-foundations/README.md)に従う。

この土台の作成時点では800問の実点検は0件。以後の実数は個別記録と最新集計で確認する。既存の40組×20問のID分割を再利用しても、各問の新観点の状態は未点検から始める。本文・ヒントの改稿や公開は、この土台整備に含めない。

## 一問の読み方

読者は通常の日本語と日常的な四則計算を使えるが、対象論点の用語・仕組みは知らないものとする。設問自体が教えている情報は使ってよい。設問に専門語が出ているだけで、その意味を知っているとは仮定しない。

問題本文、全選択肢、必要な図表の内容と、H1、H1＋H2、H1＋H2＋H3を順に読む。各段階で「何を新しく学べるか」「その情報でどの判断・操作ができるか」を実際に辿る。回答後の解説を、回答前の足場として数えない。必要な図表や本文が欠ける場合は、断片から点数を確定しない。

- 用語を全て列挙する点検ではない。解答・理解に必要なものに絞る。具体例・対比・図・途中式で意味や働きが伝わるなら、辞書的な定義がないだけでは不足としない。
- H1で定義を教える、各段に同じ役割を割り当てる、といった全問共通の型は設けない。H2やH3で必要な知識を無理なく教える構成も成立する。
- 答えを強く教えることは許容する。`revealsAnswer:true`自体は加点しない。名称や正答を渡す場合も、意味・仕組み・根拠を学べるかを見る。開示フラグの正否は別のレビュー事項。
- [PR #112](https://github.com/donald-shrimp/ap-study/pull/112)のr04h-q18は、用語中心の入口を同じ数値例の問いかけへ替え、現象名を後で教えた点を評価の見本とする。問いかけ・数値例・名称の後置を全問へ強制せず、同PRの承認を新観点での自動承認にもしない。

## 3軸の不足点：各0〜2

点数が高いほど、編集で優先して検討する不足が大きい。3軸は、対象の理解、指示の実行、情報の導入順を区別する。

| キー | 観点 | 0 | 1 | 2 |
| --- | --- | --- | --- | --- |
| `foundation` | 対象そのものの足場：何を表すか、どう働くか、何と何を比べるかを初めて学べるか | 設問と累積ヒントから、必要な意味・仕組み・関係を説明・例・対比等で学べる | 必要な足場の一部が薄い、または導入が遅く、初学者が補う推測を要する。ただし最終段までに基本像は得られる | 最終段後も、理解・解答に必要な対象の意味・仕組み・関係に大きな穴が残る。名称の置換や答えの断定だけでは埋まらない |
| `prerequisites` | 指示を実行するための足場：「計算する」「分類する」「対応させる」等に必要な前提が渡されるか | 必要な式・変数対応・条件・読み方・操作が、使う時までに示され、次の行動を辿れる | 実行に小さな未説明の橋渡しを要する、または後段の情報に戻る必要がある。ただし最終段で手順は回復できる | 必須の式・対応・判定基準・操作等が最後までなく、要求された主要な行動を実行できない |
| `progression` | 導入順と負荷：足場を使って段階的に進めるか | 必要な順序で情報が加わり、各段の役割と次の行動を追える。説明の配分は問題に合っている | 一部の先取り、まとめ過ぎ、重複で行き来を要するが、累積すると筋道を回復できる | 複数の未導入概念・操作を一度に要求する、段間で必須の橋を飛ばす、または同義反復・結論への飛躍により、累積しても主要な筋道を追えない |

同一句・同じ不足を言い換えて複数軸へ二重加点しない。例えば「公式を使おう」だけで公式がないという根拠は、まず`prerequisites`に置く。`foundation`や`progression`にも加点するなら、それぞれ別の不足と、その根拠を示す。未知語が一つあるだけで全軸を加点しない。H1でまだ定義していないことだけを理由に2としない。

## 合計と優先度

判定可能な一問は、全3軸を0〜2の整数で埋める。`total = foundation + prerequisites + progression`で、合計は0〜6。

| `total` | `severity` |
| --- | --- |
| 0 | `none` |
| 1〜2 | `low` |
| 3〜4 | `medium` |
| 5〜6 | `high` |

`criticalOverride:true`の場合だけ、合計にかかわらず`severity:"critical"`とする。元の3軸の点数と合計は保持する。次の条件を**全て**満たす場合に限る。

1. `foundation`または`prerequisites`が2である。
2. 設問・全肢とH1〜H3を全て読んでも、対象の基本的な意味・仕組みへの入口も、理解に基づく最初の具体的な一歩も得られず、対象全体が初学者に閉ざされている。
3. H1・H2・H3それぞれの根拠引用を残し、全段を累積しても足場がない理由を説明している。

全段が未知語を言い換えるだけ、または名称・正答だけを渡して意味や根拠を教えない場合などが該当し得る。局所的な語句不足や一段目の弱さだけでは使わない。「最後まで何が理解できず、どの一歩を取れないか」を上書き理由に明記する。

## 判定状態

| `assessment` | 条件と記録 |
| --- | --- |
| `clear` | 必要な文脈を全て読み、全軸0、`total:0`、`severity:"none"`、`criticalOverride:false`。足場として有効だったヒントのH番号・正確な短い引用と、実際に辿った次の判断を`support`へ残す |
| `candidate` | 必要な文脈を全て読み、1軸以上が1以上。上記の合計表またはcritical条件で優先度を決める。修正検討候補であり、内容不具合の確定・改稿承認ではない |
| `uncertain` | 図表・本文・選択肢・ヒントの欠落、版の不整合、十分な足場か判断が割れる等。全3軸を`null`、`total:null`、`severity:"unassessed"`、`criticalOverride:false`とする。未解決点と必要な追加確認を記録し、仮点は付けない |

`uncertain`を欠陥やclearとして数えず、優先度の点数集計から除く。追加確認で解消するまでは未確定のまま保持する。`clear`も、原本照合・独立承認・初学者による効果測定を済ませた意味ではない。

## 一件に必要な証拠

機械的な語彙抽出や単語の印象だけを候補として投入しない。基本レコードの項目・保存形式は[作業の入口](../work/ap/hint-foundations/README.md)に従い、少なくとも次の内容を一問・対象版へ結び付ける。

- 対象ID、担当者、実際の確認日時、基準の版、教材の版と問題・全肢・全3ヒントのハッシュ。ハッシュだけを読了の証拠にしない。
- 問題本文・全選択肢・全3ヒントを省略せず保持したパケットへの参照。必要な図表の内容・参照、ヒントの表示文字列・順序・`revealsAnswer`も保持する。ヒントの断片だけでは確定しない。
- `assessment`、3軸の点数と軸別の理由、合計・優先度、critical上書きの有無と理由。0点の軸も十分と判断した足場を説明する。`uncertain`の軸は点数の代わりに判断できない理由を残す。
- 具体的なつまずき：何を知らず、どの段のどの指示で止まるか。該当箇所のH番号・原文引用と、設問・選択肢との関係を示す。「専門的」「難しい」だけでは足りない。
- 累積の読み筋：H1→H2→H3で新しく学べること、残る不足、実行可能になった判断。後段で補われた情報を不足のまま扱わない。
- 修正を検討する方向：必要な意味・仕組み・例・対応等をどう補うかを一文で示す。完成した改稿本文は今回作らない。未解決点がなければ、その旨を記録する。

別担当の一致・不一致は、同じ対象版を参照する追加記録として扱う。異なる点数を平均して確定せず、根拠の差を確認する。教材版が変わった場合、旧判定を自動継承しない。正答・原問の誤りが疑われる場合は別件として記録し、この点検で黙って修正しない。

## 基準の使い方と限界

分担点検を始める際は、少数の同じパケットを別担当が読み、境界と証拠の取り方を校正する。実施していない校正を完了扱いにしない。点数は編集上の優先順位であり、学習者による理解度や学習効果を実測した値ではない。

特に、同じ未知語を3軸へ二重加点すること、遅いが十分な説明を不足と決めること、答えの断定を理解の足場と数えること、具体例で学べる説明へ定義不足を付けることを避ける。点数だけで改稿指示を出さず、根拠と累積の読み筋を確認する。

この点検は、正確性・法令時点・原本画像との一致・開示フラグ・アプリ動作の既存確認を置き換えない。実際の改稿・独立確認・統合は[科目Aの改訂手順](ap-a-content-upgrade.md)に従う。
