## 画面と原稿の基準

| 要素 | 学習者がここで確かめること | 掲載ルール |
| --- | --- | --- |
| 正答・公式解答例 | 何を答えればよかったか | 選択なら内容を先に置き、原問の記号は後ろに添える。順不同の組は一つの正答としてまとめる。語句・記述・数値は答えそのものを示す。数字は必要な単位も表示する |
| 小問の解説 | どの条件を使い、なぜこの答えになるか | 本文や図表にある決め手から、判断・計算・答案へのつながりを説明する。初出の用語はこの設問を解くのに必要な範囲で補う。誤りやすい候補は、結論が分かれる条件を説明する |
| 自己評価の基準 | 自分の答案に必要な要素が入っているか | 自己評価に進んだとき、解答例と評価操作のそばに出す。主語・対象・条件・因果関係など、答案と照らし合わせて判断できる観点を書く。同じ意味の別表現も判定できる言い方にする |
| 確認ポイント | 次も自分で使える判断手順は何か | 自動判定の欄では、解説の外に持ち出せる具体的な手順があるときだけ任意で出す。「図の何を先に見るか」「二つの候補を何で見分けるか」が分かる一文を目安にする。追加の価値がなければ、見出しごと省く |
| 大問全体の解説 | 個々の判断が事例全体でどうつながるか | 事例の背景・共通前提・設問間のつながりは既存の全体解説を使う。小問の結果画面は、その場で答えを理解できるだけの情報量にする |

- 正答の内容は表示時に選択肢ID、または照合済みの旧式記号から引く。長い肢は折り返し、図や表の参照が必要なら該当箇所へ進めるようにする。
- 正答を複数行で表示する場合も「正解は」を繰り返さない。順不同の組には、e・fの片方に特定の正答を割り当てる表示を付けない。
- 短答の登録外表記など、実際の判定が自己評価に進んだ場合は、その欄の基準を出す。自動判定後に自己評価の基準を再掲しない。
- 原問の字数や指定語句は、必要な場所で一度示す。公式採点に関する共通説明が必要な場合は、出典・教材の詳細に置く。
- 引用元や正答の記号は根拠の補助として使う。作問・レビューで見る数値や管理上の注意は、学習画面の文章へ混ぜない。

### 画像の設問での改稿例

**正答**

出荷指図データ（カ）、出荷実績データ（キ）

**解説**

表1の項番4①では、売上を作る日次バッチが正しく実行されたかを確認します。日次バッチは倉庫に出した指示を使って売上を作ります。例えば、10個の出荷を指示して倉庫が8個だけ出荷した場合、バッチが正常に動いても、指示どおり10個分の売上ができます。実際の出荷に基づく売上だと確かめるためには、指示の内容と倉庫が実際に出荷した内容が一致している必要があります。

この組は解説だけで判断をたどれるので、確認ポイントは省きます。自己評価のある同じ大問の設問2では、例えば「営業担当者に売上訂正処理の権限がある、と担当者と権限の関係まで書いたか」を基準にします。自分の答案を読んで判断できる観点です。いずれも計画用の文案で、教材へ反映する前に原問・図表・公式解答・採点講評と照合します。

## 実施順序

1. **共通表示を直す。** 選択肢の内容を正答の主表示にし、正誤 → 正答 → 根拠 → 必要な評価操作の順で出す。自動判定では既存の `rubric` をそのまま確認ポイントとして表示する処理を外し、自己評価時に使用する。開示条件は現行のまま。図だけの選択肢は手で照合した対応を用意する。
2. **2題で試す。** 画像の2022年春期・問11と、図中の記号を扱う2023年春期・問1の全欄で改稿する。選択、順不同の組、短答、記述の自己評価、図の参照を一度に比較できる。正解・誤答・未回答・試験形式の開示前後と、320／390／1440pxでの読みやすさをローカルで確かめる。
3. **レビューと配布の単位を決める。** 小問の解説・自己評価基準・任意の確認ポイント・図の表示用対応を、`caseId`・教材版・`itemId`・`fieldId` と元データのハッシュにひも付けた表示用の改訂として管理する。改訂では自己評価に進み得る欄に評価基準を求める。確実に自動判定する欄では任意の確認ポイントだけを扱う。既存の教材・採点キー・大問全体解説・学習記録の保存時の版を保持する。過去の記録にも、当時の教材と照合できた改訂だけを適用する。表示データは既存の教材生成・オフライン保存に載せ、同じ解決結果をAI質問でも使う。
4. **試行で基準が合ったら定期運用へ進む。** 最初は1時間ごとに最大2大問を目安にする。画像と同じ定型文がある2022年春期を優先し、その後は重複率の高い試験回から進める。各回の中では問番号順。重複が機械検出されなかった欄も、根拠と評価基準を一度確認して「改稿済み」または「現行で可」を記録する。

## 定期作業の完了条件

- 着手時に先行作業、進捗、予約、編集状態、元教材のハッシュを確認する。前回が未完了なら、その回の修正・再レビュー・表示確認を終える。
- 作者は各大問の原問・全図表・公式解答・採点講評を参照し、全回答単位を点検する。別担当が原本から解き直し、正答と表示する語句、解説の根拠、自己評価の観点を照合する。修正後は最終版の内容とハッシュを再確認する。
- 機械検査は、選択肢ID・表示内容の対応、解説の複製、確認ポイントの定型文、自己評価基準の欠落、全欄の対応とハッシュを確認する。言い換えの重複、初学者が判断をたどれるか、評価基準が自分で使えるかは文章レビューで判断する。
- 承認済みの改訂をローカルで確認する。採点・回答の再開・大問全体解説へのリンク・試験中の開示・オフライン、共通画面を使うFP2級実技の表示も確認する。
- 1回ごとに対象・判定・最終ハッシュ・検証・残件を記録する。全88大問の点検と対象改稿の承認・ローカル反映で定期タスクを終了する。本番反映は別工程とする。
