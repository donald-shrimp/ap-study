# 自力正答率の推移と計画履歴

2026-10-11実装。[画面案](growth-history-mock.html)に合わせ、学習ホームには表示を増やさず、記録と計画の詳細に置きます。

## 自力正答率の推移

記録 → 普段の学習 → 全体の自力正答率 → 推移 → 分野別の記録、の順です。分野別の「推移を見る」でもグラフへ移動できます。

グラフは今日・7日前・14日前・21日前・28日前・35日前の6点です。それぞれ、その暦日の直近28日（当日を含む）に完了した通常学習を集計します。同じ問題は各時点での最後の結果だけを数え、後の解き直しを過去に反映しません。過去の点はその日の終了まで、今日の点は現在まで。日付は計画のタイムゾーン、計画なしならAsia/Tokyoです。

- 分子：ヒント・解答を事前に見ずに正解した問題数。
- 分母：自力正解・ヒント付き正解・不正解・解答閲覧になった問題数。
- 診断・模試・未完了・未来日時・別資格の記録は除外。
- 記録なしは空白。10問未満は点線のマーカー。点を押すとその時点の分子・分母を表示。
- 分野・パートを絞った場合も同じ数え方。保存済み問題の分野を使い、現行の教材分類で過去を変更しない。

最新点は記録の全体集計と一致します。試行全件を数えるAI Exportや計画実績とは分母が異なります。率だけで習熟や合格を断定せず、問題や分野の構成変化による増減もあり得ることを折りたたみ説明に記載します。

## 計画履歴

計画画面は現在の概要、終了期間の実績、計画の変更、折りたたみの編集・AI入出力の順です。

計画を変更する操作すべてで、完全なStudyPlanの不変スナップショットを保存します。受験日・フェーズ・週別目標・予定の完了・前提・JSON登録・競合解決を含みます。内容が変わらない保存では履歴を増やしません。変更一覧は日付・受験日や目標等の変更内容・保存時の前提を表示し、変更前後の計画を閲覧するダイアログへ進みます。履歴から現在の計画へ自動復元はしません。任意で過去のStudyPlan JSONを書き出せます。

終了期間の実績は、現在の計画と内容が一致する最新履歴から`previousId`をたどり、終了時点の保存済み目標を参照します。同じ内容の計画が複数系列にある場合は、最新の保存を基準とします。終了後の目標引き下げ・期間延長・削除で、当時の目標は塗り替えません。終了前に削除・延期した期間を終了扱いにしません。不採用の競合案も変更一覧に残しますが、選択中の系列の終了目標には混ぜません。

計画実績は従来どおり完了試行回数です。解き直し・解答閲覧・既存問題の完了診断を含み、模試・派生診断は除外します。現在ある学習記録から再計算するので、後でバックアップを取り込むと実績数が変わることがあります。保存時点の実績を凍結した値ではありません。

履歴開始前の変更は復元できません。履歴のない既存計画の初回変更では変更前を`baseline`として保存し、過去期間は保存開始時の基準である旨を明記します。削除済みの学習記録や以前の計画内容を捏造しません。未受信の比較元は「まだありません」と表示し、同期後に比較します。

## 保存と同期

資格定義や教材は変更しません。グラフは回答履歴から算出し、集計専用のクラウド文書を作りません。表示中の分野・点は一時的なUI状態です。

履歴はユーザー×資格のresources内、`kind:planRevision`、`id:plan--<UUID>`。内容は次の形式です。

```json
{
  "format": "hitomon-plan-revision",
  "version": 1,
  "id": "plan--UUID",
  "qualificationId": "ap",
  "savedAt": "2026-10-11T10:00:00.000Z",
  "origin": "edited",
  "previousId": "plan--PREVIOUS",
  "plan": { "format": "hitomon-study-plan", "version": 1 }
}
```

`plan`には完全な検証済みStudyPlanを保存します（上は省略例）。`origin`はregistered／edited／imported／baseline／resolved／restored。ID・資格・UTC日時・出自・前回参照・全計画を検証します。前回参照は遅延同期や部分バックアップで欠けることを許容し、閲覧時に明示します。

現在の計画と新しい履歴・送信待ちを同じIndexedDBトランザクションで保存します。失敗時はまとめて中止。クラウドの同じ履歴IDに異なる内容を上書きできず、削除も許可しません。計画本体のCAS競合解決は維持し、両端末の履歴を保持します。

学習記録全体の`workspaceBackup.planRevisions`に含めます。既存計画を維持して履歴を追加でき、同じIDの異なる内容は原子的に拒否します。ゲスト取り込みも同じ検証・原子的取り込みを使います。公開StudyPlan JSON v1は変更しません。

履歴用の本番Rulesは別途公開が必要です。[更新手順](firebase-setup.md#plan-history-rules)。未公開のときは履歴だけ送信待ちに残し、既存の計画・診断の同期を継続します。本番Rulesの配備・本人の実機同期を、この環境で実施したとは報告しません。
