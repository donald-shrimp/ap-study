# 固定80問の模試

学習タブの「模試」カードから回を選ぶ。現在は模試A・Bの各80問。通常の3入口・1操作開始を維持し、模試への誘導はメイン入口の下に置く。

- 各回は固定問題・固定順・固定4択。同じ回を受け直してもランダム抽出しない。
- 選択した回答を端末へ保存し、「回答して次へ」で確定する。未回答で次へ進むこともできる。確定回答へ戻る操作・制限時間は初期版に設けない。
- 受験中はヒント・正誤・解答解説を表示しない。80問を進めるか「ここまでで模試終了」で一括採点する。中断は終了と区別し、再開できる。
- 正答率は正解数÷80。未回答は正解に含めない。途中終了には「部分結果」「途中終了」を付ける。
- 選択画面は各回の最後に終了した受験の正答率を表示。中断中なら「続きから」を出す。別の新しい回を始めるときは、中断した記録も保持する。
- 記録タブの「模試結果」→模試A／B→受験履歴→結果・全4択理由。受け直しは別の受験IDで保存する。
- 模試結果は通常の自力正答率・復習候補・学習回数・計画実績と、30問診断の結果から分離する。終了後の「元の過去問を学習」は別の通常試行になる。

## 教材を増やす

`content/ap/mock-sets.json` が固定問題の作成元。資格定義の `mockSetSource` から、公開用 `mockSets.<hash>.json` と一覧用メタデータを生成する。`status:ready` のセットだけを公開し、80枠・問題IDの一意性・元問題／分野・確認済みの診断専用教材を検証する。

C以降も別のセットID・表示名・版・固定80枠を追加し、診断専用の完成教材と確認記録を登録する。画面はセット定義から作るため、A／Bの名前をコードへ固定していない。教材本文を変更した場合、教材版と確認記録を更新し、セット内容を変更した場合はセット版も上げる。現在の教材は通常800問・単語帳681枚・公開派生180問／確認待ち0を保持。

## 保存と同期

受験はユーザー×資格のworkspaceへ `kind:mock` で保存。`mode:mock`、セットID・名前・版・固定問題ID、開始時の全問題／解説スナップショット、未確定の選択、確定回答・現在位置・終了時刻を保持する。教材の更新で保存済みの受験・採点を変えない。

Googleログイン時は `users/{uid}/qualifications/{qualificationId}/resources/{runId}` へ、計画・診断と同じCAS同期で送受信。問題・順序・確定回答・終了済み記録は変更できない。別端末で同じ受験を進めた競合は、クラウドの内容を採用するか、この端末の内容を別の回として保存する。自動で確定回答を上書きしない。

全体の学習記録バックアップに模試も含め、取り込みでは既存IDを保持し、異なる内容の同IDは拒否する。ゲストの模試はログイン時の明示取り込み対象。学習状況Exportでは `mockExams` 配列に分離して渡す。

新しい受験はオンラインで80問と画像を準備。中断した受験は保存済みの教材と画像でオフライン再開できる。端末保存と通常回答の同期は従来どおり使える。模試用のRulesがまだ公開されていない場合は模試を端末に残し、計画・診断の送信は継続する。

[Firestore Rulesの追加公開手順](firebase-setup.md#mock-rules)。本番のルール公開・本人アカウントの実機同期は、Emulatorによる検証と区別する。
