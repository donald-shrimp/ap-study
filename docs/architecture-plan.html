今の1・3・5問の開始、中断／ホーム、段階ヒント、回答の下の正解表示を共通部品にします。資格によって変わるのは、名前・分野・教材・出題回の表示です。

応用情報しか公開していない間は、資格選択を毎回挟まず、すぐ学習を始められる入口にします。

URLとPWAの扱い

公開先は今のGitHub Pages。資格ページは /ap-study/ap/、追加資格は /ap-study/資格ID/ を想定します。ページを実ファイルとして置くので、直接開いて再読み込みできます。

PWAは「ひと問」1つ。IDとスコープ /ap-study/ を維持し、使った資格・教材・画像だけを追加保存します。

今のコードから変える場所

app.jsにまとまっている画面・採点・復習・保存を分けます。1つの応用情報JSONから、資格別の教材一覧と教材パックへ分けます。春秋・4択・80問という固定条件は、応用情報の設定と取込処理に寄せます。

フレームワーク導入を前提にせず、既存のJavaScriptモジュールとPythonツールを使います。

2 / 増やし方

資格と問題を、データで追加する。

資格を増やす

資格ID・名前・分野を登録し、最初の教材パックを用意します。同じ選択式なら共通画面を使えます。

問題を増やす

その資格へ教材パックを追加します。件数・年度・分野の一覧はデータから生成します。

  1. 原本と正答を確認し、問題・図・選択肢を用意する。
  2. 解答解説、各選択肢の理由、問題固有のヒントをセットで作る。
  3. 別の確認担当が原本から解き直し、修正後の教材まで確認する。
  4. 出典・ID・正答・画像・確認記録を検証し、公開用データを生成する。
  5. スマホ表示・中断再開・オフライン・同期を確認して公開する。

共通部分は「1回80問」「春と秋」「4択」に固定しません。最初は単一選択に対応し、別の問題形式は実際に必要になったときに追加します。

問題や分野が混ざらない仕組み

問題は「資格ID＋問題ID」、分野は「資格ID＋分野ID」で区別します。応用情報の既存IDは活用できます。他資格に同じ問題番号や分野名があっても、履歴とメモが混ざりません。

問題の内容を訂正しても、過去の回答を新しい正答で採点し直しません。記録時点の教材と採点情報を残します。

教材が増えたときの読み込み

資格ごとに軽い教材一覧を取得し、選んだ問題の教材パックを読みます。他資格の全問題や全画像を初回にまとめてダウンロードしません。

出典・問題画像・教材はGitHub Pagesに置き、Firebaseには学習記録を保存します。

3 / 同期

別端末で続きから。

Googleログイン・同期コードを追加しました。Firebaseのルールを公開した後、実機で確認します。

  1. ログインなしでも、端末内に保存して勉強できます。
  2. Googleログインすると、同じアカウントの記録へ接続します。
  3. 最初は回答履歴・ヒント閲覧・中断状態を同期します。
  4. オフラインの記録は送信待ちに残し、つながったら再送します。

表示は「この端末に保存済み」「同期中」「同期済み」「同期を保留」を区別します。同期が失敗しても端末内の学習を続けられます。

スマホとPCで同じ問題を解いても、片方の回答を消しません。解いた記録ごとに保存します。

同時利用と再開のルール

別端末で中断状態を再開するときは、ヒントや回答候補を引き継いだ継続記録を作ります。元の記録とつなげ、未回答の元記録を完了件数へ二重に数えません。

同時に2端末で続けたら、両方の回答を残します。再送は同じIDを使い、記録を重複させません。更新が届いても、現在解いている画面を勝手に切り替えません。

無料枠と費用

FirebaseのSparkプランから始めます。支払い情報は不要。2026-10-06の公式情報では、Firestore Standardは保存1GiB、読取5万件／日、書込2万件／日が無料枠です。

スクロールのたびに通信せず、変更をまとめて送ります。全履歴の常時購読も避け、実際の利用量を確認します。読書メモ・自作教材・設定の同期は後の工程です。

アカウントと保存の安全性

記録は利用者と資格ごとに分けます。Googleアカウントを切り替えても前の人の記録を表示・送信せず、サーバー側でも本人だけが読み書きできるよう制限します。

初回ログイン時、ログイン前の記録をそのアカウントへ追加するか選べます。PC・Android Chrome・インストール済みPWAでログインの往復を確認します。
