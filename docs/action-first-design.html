01 / 現状

集計はある。行動への入口が足りない。

「分野の状況はAI用の出力でしか見られない」は、普段の学習については、ほぼそのとおりです。診断結果には「5問回答中2問正解」と分野別の学習ボタンがあります。普段の学習には分野別グラフがありません。

現在あるもの足りないこと
分野別演習解いた問題の件数は分かるが、どの分野を次に確認するか比較しにくい。
学習記録試行ごとの結果は見られるが、分野の傾向をまとめて見られない。
診断結果分野別の正解数はある。通常学習の入口でその結果を思い出しにくい。
目標・計画残日数・現在のフェーズ・実績・週目標は表示済み。重点分野はホームに出ず、開始ボタンの出題にもつながっていない。
ホーム開始、達成、復習、目標が別々のカード。上部の5つのナビゲーションや中断した診断も、通常学習の開始と注意を取り合う。

グラフを足すだけでは、迷いは残ります。

まず「次はデータベースを1問」を決めて示し、理由や数値を確かめたい人がグラフへ進める形を推奨します。

02 / ホーム

見たら、そのまま始められる。

最上段の大きなボタンはひとつ。計画の詳細を開かなくても、次にすることと試験までの日数が見えます。

見本は架空の学習記録です。状態を切り替え、開始・ヒント・回答・終了まで試せます。アプリの学習記録には保存しません。

この見本で変えること

  1. 行動を具体化。「データベースを1問」「前回の問題を続ける」を先に示す。
  2. 大きなボタンを統合。中断時の主ボタンは「続きから」。新規開始は控えめな別ボタンにする。
  3. 計画を近くに。主操作のすぐ下に「選択式まで28日」「基礎確認」「重点：DB」を短く表示。
  4. 成績は下へ。確認候補の分野を最大2つだけ出し、全分野のグラフは別画面にする。
  5. ナビを3つに。「学習」「分野」「記録」。問題検索は分野画面、計画と診断は記録画面からも入れる。

診断の中断は通常学習の開始カードの上に置かず、下に専用の再開ボタンを置きます。開始が診断に勝手に切り替わることを防ぎます。

残日数を目立つ赤い締切カウントにせず、行動を選ぶ文脈にします。常時の点滅・音・連続日数の圧力は加えません。

ホームに残す詳しく見る画面へ
次の1問／中断の続き・短い理由出題順位の詳細・全復習一覧

詳細の「計画を見る」「分野を見る」は、枠のある小さなボタンにします。読めるだけの文字リンクにせず、主ボタンより控えめな見た目にそろえます。

03 / 分野の見える化

割合・件数・次の行動をセットに。

レーダーチャートより、横棒グラフを推奨します。分野名と件数が読みやすく、低い数値から「この分野を1問」へ進めます。未回答は0%にせず、未確認と表示します。

架空の記録 · グラフの見本

普段の学習

「自力正解 48%・12 / 25問」のように表示。ヒント付き正解・不正解・解答閲覧も棒と数値で区別します。

ヒント付き正解を失敗扱いするのではなく、自力で再確認する入口にします。

支援なし診断

「2 / 5問正解」のように、診断ごとの件数を中心に表示。未回答は別記し、回答した問題だけを分母にします。

普段の学習と別タブにし、低い率だけで「苦手」「合格できない」と断定しません。

グラフの数え方を決めておく
  • 初期表示は通常学習の直近28日。同じ問題を10回解いても10問とは数えず、期間内の完了記録のうち、問題ごとの最後の1件を使います。「25問の最後の記録」という意味を表示します。
  • 自力正解の割合：correct ÷（correct＋assisted＋incorrect＋revealed）。解き途中・中断は分母に入れません。答えを含むヒントによるrevealedや、解答閲覧も独立した区分です。
  • 診断と通常学習を分離。新しい通常グラフではdiagnosticRunIdのある試行を除外。診断専用の派生問題も除外。診断タブは固定された1回を表示し、違う回や構成を足し合わせません。
  • 少数の記録は目印を添える。例として10問未満を「記録少なめ」と表示し、率だけの自動順位から外します。10は医学・統計上の確定基準ではなく、製品上の暫定基準です。診断は分野あたり少数になりやすいため、件数の事実を中心にします。
  • 期間外・未確認は0%ではない。「直近28日に記録なし」。過去の履歴は消さず、詳細で表示できます。最近の率だけで過去の苦手が解消したとも判断しません。
  • 繰り返しを減らしても理解度とは言い切れない。同じ問題の答えを覚えている場合、アプリ外の学習、問題ごとの難易度差は残ります。名称は「学習の記録」、表示は「次に確認する候補」にします。
  • 色だけで区別しない。数値・区分名・件数のテキストを添え、棒のアニメーションや合格ラインは置きません。

現在のAI Exportは解き直しの全試行を数えます。このグラフの率と、従来ExportのselfCorrectRateは分母が違います。既存フィールドを黙って読み替えず、新しいUI用集計として実装し、後でExportする際も方式を明示します。

どの分野を上に並べる？

最初は「現在の計画の重点分野」→「記録のある分野」→「未確認」。計画がなければ、記録のある分野は自力正解の割合が低い順、同率は資格定義の順にそろえます。記録少なめは別にまとめ、40%の5問を48%の25問より必ず優先するとはしません。

未確認の分野には「初めて確認する」ボタンを置きます。色を赤く塗って最弱分野にしません。ホームは全17分野を並べず、具体的な復習候補・計画の重点から最大2件に絞ります。

04 / 次の1問

AIを待たず、説明できるルールで選ぶ。

「まずはこれ」を示すために、合格予測や複雑な苦手スコアは不要です。途中の問題・復習の目安・登録済みの計画から選べます。提案は1問の入口であり、計画を書き換えるものではありません。

① 通常学習の中断があれば、続き。

「DB・ヒント2まで・回答未確定」を示す。「別の1問」も選べる。中断した診断は別の入口。

② 現在の計画の重点分野に、復習日が来た問題があれば、その1問。

「前回ヒント付き正解。今日は自力で確認」。優先の理由は「苦手認定」ではなく、具体的な記録。

③ 重点分野に復習対象がなければ、重点分野の未着手の1問。

重点が複数なら、最近触れた問題の種類数が少ない分野から。新規がなくなったら、その分野の最も前に完了した問題を再確認。率だけで同じ分野に固定しない。

④ 計画なし・重点なしなら、復習日→未着手の1問。

開始までの操作は増やさない。グラフの低い率から自動で計画を作る段階は後回しにする。

見えているおすすめと、押した後の問題を一致させる。

「DBを1問」と表示したボタンが、別分野を開くことを防ぎます。同期で記録が増えても、操作中の候補や学習セッションは勝手に差し替えません。

計画優先だけでは困る場合
  • 重点以外の復習：「ほかの分野の復習が3問」を控えめに示し、1操作でその復習も始められるようにする。残数をノルマにしない。重点だけで長く偏る場合は記録画面から計画を見直せる。
  • 模試・読書の予定：今日は手元の教材で模試、という予定は計画カードに表示する。教材未対応の記述式を、通常問題の開始ボタンで扱えるかのように見せない。予定の完了は本人が明示する。
  • 自由文の制約：「土日は休む」「DBをやらない」はcontextに書けるが、機械が確実に解釈できる構造ではない。最初は前提の文章として見られるようにし、自動で休み・科目制約を推定しない。
  • 計画の空白期間：「今の期間の計画なし」と短く示し、通常出題を続ける。期限切れの重点をいつまでも使わない。
  • 週目標なし：登録されていない120問などを勝手に生成しない。フェーズの実績だけ表示。未達を翌週へ自動で繰り越さない。
  • 教材なし／オフライン：まず解ける問題を確認。対象に保存済みがなければ、別分野の保存済み1問を明示して提案。1問もなければ「オンラインで問題を開く」と現在できることを示す。
  • 日にち：計画のtimeZoneで日付をそろえ、複数パートは選択中の対象パート名を付ける。過ぎた日は「あと−3日」と出さない。
  • 次の問題：開始した分野・計画の範囲は、1問ごとの途中同期で変えない。「もう1問」で同じ範囲を続け、終了時に次の候補を更新する。セッション内の重複回避は維持。

05 / 全体の流れ

各画面にも「次にすること」を置く。

問題選択後に「回答する」ヒント、中断、画像拡大。診断中は支援なし。

設定・同期必要な設定／同期保存先とアカウントを読めるように。通常学習にログインを強制しない。
ログイン忘れ・端末の違いも、流れで防ぐ

今回、PCのログイン忘れが計画が見えなかった理由と本人が報告しています。「同期済み」が、どのアカウントの何を同期したのか分かることも必要です。

  • 設定に「この端末だけ」／「Googleアカウントで同期」を明示。アカウント名は設定内で確認できる。
  • 計画をゲストで保存した後に「この端末に保存しました。他の端末でも見るにはログイン」を短く表示。ログインを強制しない。
  • ログイン後、ゲスト計画が残っていれば「ログイン前の計画を取り込む」の入口を見つけやすくする。
  • クラウドに既存の計画がある場合は自動で置き換えない。両方の概要を比較し、取り込む方を選ぶ。今のJSON経由の手順は改善余地がある。
  • 「同期済み」は送信待ちや競合がないこと。PCのゲスト領域にある計画がアカウントへ届いた証明にはならない。対象の計画あり／なしも設定内で確認できるようにする。
ADHDへの配慮を、具体的な仕様にする
  • 選択肢の数を増やす前に、既存ボタンが何をするか分かる名前にする。
  • 重要情報は行動の近くに置く。前のページの計画や分野名を覚えていなくても進める。
  • 支援や終了を失敗扱いしない。1問で終えても取り組みを保存する。
  • 大きな主ボタンはひとつでも、終了・中断ボタンを小さく隠さない。枠・背景・アイコン、44px以上の操作領域を保つ。
  • 長いグラフ一覧や全期間の表はホームに置かない。通知・点滅・音・達成演出を追加の主役にしない。
  • 折りたたみは詳細に使う。「今すぐ始める」や「あと何日」は隠さない。
  • 失敗時は「何が保存できたか」「次にできること」を示す。何度も同じ保存操作を要求しない。
  • 390px・文字200%・キーボード操作・色に頼らない読み方で確認する。

06 / 実装順

見える化から始め、出題へつなぐ。

P0：実装済み · 現在地と計画を、読める形にする。

通常／診断を分けた分野集計と横棒グラフ。計画を読む画面と編集を分け、現在の重点・残日数をホームの開始直下へ。ナビと中断カードの優先順位を整理。主操作の数は増やさない。

P1：実装済み · ホームの1操作で、計画に沿った1問を開く。

理由付きの候補を共通関数で決め、カードと開始に同じ候補を使う。重点分野の復習／未着手、途中の再開、オフライン・計画空白・教材未対応を扱う。回答後の次と終了を統一。

P2：未実装 · 使いながら調整する。

履歴の推移、初見と再挑戦の比較、ゲスト計画の比較取り込み、必要なら選び方を調整。AIとの計画相談は既存のExport／Importを使い、自動書換や「苦手スコア」は必須にしない。

実装するレイヤーと、変更しない保存データ
場所変更案
domain/analytics.js（新規）資格・パート・期間・通常／診断を指定した集計。最新の1試行／問題、状態別件数、母数、記録少なめを返す。状態を保存する別スコアは作らない。
domain/next-action.js（新規）候補と理由の共通関数。既存の復習判定・計画・教材の利用可能性を入力。画面と開始処理で別々に選ばない。
features/planning.js資格・利用者別に計画と診断を渡す。読み取り用の計画表示を追加し、編集フォームと保存／競合保護は維持。

資格定義・StudyPlan・IndexedDB既存のtopics、examParts、focusTopicIds、weeklyTargetsを利用。画面のための新しい必須設定は増やさない。
Firebase・Export率は既存記録から計算。P0／P1のために新しいクラウド文書やRulesを必須にしない。Exportの既存集計の意味を変えない。

実装後の受入確認
  • 登録・診断・ログインなしでも1操作で通常学習が始まる。
  • 通常学習の中断と診断の中断が両方あっても、主ボタンは通常学習の続き。
  • 「DBを1問」と示した主ボタンが実際にDBを開く。
  • 複数資格・パート、重点複数、空白期間、週目標なし、対象教材なしでも表示と実際の動作が一致。
  • 同じ問題を繰り返してもグラフの母数を水増ししない。0問は未確認。途中は分母外。答えを含むヒントは閲覧扱い。
  • 率の低い少数データだけで最優先や苦手認定をしない。通常と診断の率・分母は区別。
  • 保存・再開・解き直し・選択肢の表示・ヒント・PWA・Firebaseの競合保護を維持。
  • 通常開始では診断専用教材を取得しない。派生問題を通常学習・復習・グラフに混ぜない。
