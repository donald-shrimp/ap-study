# ヒントの共通ルール

**目的は、知らない問題でもヒントから知識や手順を学び、自分で回答へ進めるようにすること。** 答えを隠すこと自体を目的にしない。ヒントで解けたことも学習の前進として扱い、自力正解とは記録を分ける。

全資格・科目・問題形式の、新規作成と既存教材の追加・改稿・レビューに適用する。ヒントの品質と答えの開示判定はこの文書を正本とし、資格別手順では重複して定義しない。形式・保存先・公開条件は [問題の追加手順](content-authoring.md)、解説と強調は [解説記述ルール](explanation-authoring-rules.md)に従う。

## 作るときの基準

1. **つまずきから始める。** 用語を知らない、公式を選べない、条件を取り違える、図表の読み方が分からないなど、その問題で止まる理由を特定する。
2. **各段階で新しい情報を渡す。** 入口で見る場所・比較軸・前提を示し、次に必要な定義・仕組み・公式・基準・具体例・途中式を教える。「思い出そう」「比べよう」の言い換えだけで段階を埋めない。
3. **初学者が使える内容にする。** 「○○の定義を使う」なら必要な定義を、「公式に代入する」なら公式と変数の対応を教える。知らない人が次に何をすればよいかを判断できることを確かめる。
4. **残る判断を意識する。** 計算・条件の適用・概念の比較などを本人に残せるなら残す。定義や名称そのものを教えないと進めない問題では、学習価値のある説明とともに答えを教えてよい。開示した事実は正しく記録する。
5. **問題の根拠を守る。** 原本・公式解答・確認できる一次資料と照合し、単位・例外・適用時点を落とさない。過去問は出題時点を基準にし、現行法令や製品仕様を混ぜない。
6. **必要な分だけ書く。** 段数・文字数・太字の数を埋めるための説明、全問共通の前置き、解説全文のコピーは加えない。同じ概念でも、与件・問い方・選択肢に合うかを一問ずつ確認する。

通常は「入口→具体的な知識・手段」の2段構成を基本にするが、段数は教材契約に合わせる。APの既存3段構成なら、知識と具体的な当てはめを分けられる。新ルールを理由に全問を2段へ変換しない。ヒントが任意の形式では未設置も許容し、空疎なヒントを追加しない。

## 答えを含むかの判定

**「ヒントを読めば正解できる」だけでは不適切としない。** 内容に学習価値があるかと、答えを開示したかを分けて判断する。問題文・全選択肢・それまでに開くヒントも一緒に読む。

| 実際に渡す情報 | `revealsAnswer` |
| --- | --- |
| 公式・変数の意味・途中式・比較軸を教え、与件の適用や計算・比較を本人が行う | `false` |
| 正答の番号・名称・最終数値、正答肢そのものと実質同じ説明を渡す | `true` |
| 正答以外をすべて除外し、残る選択肢を直接確定させる。複数選択で正答の組合せを渡す | `true` |

定義問題で正答肢を言い換えた説明を渡す場合も `true`。正答の語を避けただけで `false` にしない。一方、公式を教えて本人が計算する支援まで一律に解答開示としない。迷う場合は該当する文と残る判断をメモし、レビューで確定する。未判定を `false` で埋めて公開しない。

答えの番号や全文を告げるだけでは、よいヒントにならない。開示が必要な場合も、意味・仕組み・根拠を教える。太字・タイトル・図・前段との組合せも判定に含める。

### 現行の表示・記録との対応

- `true` の段階は開く前に「答えを含む」と表示する。
- 回答前に開けば、正しく選んだ場合も **「解答を確認」（`revealed`）**。解答確認扱いを避けるために内容を曖昧にしたり、フラグを偽ったりしない。
- 答えを含まないヒントを使って正しく回答すれば **「ヒントで正解」（`assisted`）**。使わず正しく回答すれば **「自力で正解」（`correct`）**。
- 回答確定後にヒントを開いても、確定した結果や解答前の支援履歴を遡って変更しない。復習は [共通の出題仕様](practice-scheduling.md)に従う。
- 診断・模試の受験中にヒントを出さない既存の条件を維持する。未開示のヒントや解答を本文へ混ぜない。

これは [既存の採点処理](../src/domain/study.js)の扱いであり、新しい点数や合否判定を設けるものではない。

## 問題タイプ別の例

以下は説明用の架空設問で、公開教材ではない。H1／H2は段階の例。採用する教材の段数に合わせて調整する。

### 計算・数値

問い：12 Mバイトを8 Mビット/秒、実効利用率75％で転送する時間。Mは10の6乗、ほかの負荷はない。

- 悪い例：「転送時間の公式を思い出そう」だけで公式や単位を教えない。
- H1：データ量はバイト、速度はビット。1バイト＝8ビットにそろえる。`false`
- H2：時間＝データ量÷実効速度。データ量は12×8、実効速度は8×0.75なので、96÷6を計算する。`false`。最後の計算を本人に残す。
- 「答えは16秒」と最終値まで示すなら `true`。

### 用語から説明を選ぶ

問い：デルファイ法の説明を、専門家への反復質問／一度だけの集団討議／過去データの数式分析／購入者アンケートから選ぶ。

- 悪い例：「デルファイ法の特徴を思い出し、合う説明を選ぼう」。未知の用語を知らないままにする。
- H1：予測には、数値データを分析する方法と、人の見解を集める方法がある。その違いで選択肢を整理する。`false`
- H2：デルファイ法は専門家から個別に見解を集め、集計結果を返して再回答してもらい、繰り返して意見を収束させる方法。`true`。この問いでは正答肢の説明そのものを教えている。

### 説明から用語を選ぶ

問い：最後に入れたデータを最初に取り出す構造を、キュー／スタック／木／ハッシュ表から選ぶ。

- 悪い例：「LIFOの構造を選ぼう」。未知の略語に置き換えただけ。
- H1：積み重ねた皿は最後に置いた皿から取り、レジの待ち行列は先に並んだ人から進む。設問はどちらの動きかを考える。`false`
- H2：スタックは後入れ先出し。皿を重ね、上に置いた皿から取るイメージ。キューは先入れ先出しで、待ち行列に対応する。`true`。名称を含むが、意味と対比を教える支援として許容する。

### 制度・法令の条件

原本が「20歳以上・所得200万円以下・学生は対象外」と定める**架空の給付制度**。問い：22歳・所得220万円の非学生は対象か。

- 悪い例：「制度の条件に当てはめよう」だけで条件を教えない。
- H1：年齢・所得・学生かどうかを分け、すべての条件を満たすかを見る。`false`
- H2：対象は20歳以上、所得200万円以下で、学生ではない人。与件の年齢と所得をそれぞれ基準と比べる。`false`。条件の照合を本人が行う。
- 「この人は所得が上限を超えるので対象外」と判断まで渡すなら `true`。実際の制度問題では、基準日と例外も原本から照合する。

### 似た概念の比較

問い：検索結果のうち正しいものが60件、誤りが20件、検索から漏れた正しいものが40件のときの適合率と再現率。

- 悪い例：「適合率と再現率を混同しない」。違いを知らない人に判断材料がない。
- H1：適合率は検索結果の正確さ、再現率は正しいものをどれだけ拾えたか。分母が異なる。`false`
- H2：適合率＝正しく検索した件数÷検索結果の全件数。再現率＝正しく検索した件数÷本来検索すべき正しい全件数。分母をそれぞれ60＋20、60＋40として計算する。`false`
- 「適合率75％・再現率60％」まで教えるなら `true`。

### 図表・複数小問・ケース

共通の在庫表に、商品Aの期首在庫10個・入庫5個・出庫8個がある。対象欄は期末在庫。

- 悪い例：「表をよく見よう」。見る行や列も分からないまま。
- H1：商品Aの行と、同じ期間の期首・入庫・出庫の列を見る。ほかの商品の数値を混ぜない。`false`
- H2：期末在庫＝期首＋入庫－出庫。10＋5－8を計算する。`false`。他の回答欄の正答は出さない。
- 「期末在庫は7個」と教えるなら `true`。

この設計基準は各回答欄にも適用する。ただし現行のAP科目B・FP実技のcase形式にはヒント専用フィールド・開示履歴がない。設計メモと未対応点を草稿の別ファイルへ残し、土台担当へ引き渡す。未定義のフィールドを追加したり、解説を回答前に表示して代用したりしない。

## 一問ごとの作成と受入チェック

作者は問題ID（caseなら小問・欄IDも）と版にひもづけ、次の短い設計メモを草稿・作業記録へ残す。新しい必須JSON項目や文量のノルマは作らない。

| 対象ID・版 | つまずき | 各段階で増える知識・手段 | 本人に残る判断 | 開示フラグと理由 |
| --- | --- | --- | --- | --- |
| 例：term-q01 v2 | 定義が未知 | H1は分類軸、H2は定義と具体例 | H2後は説明と肢の対応のみ | H1 false／H2 true：正答肢と実質同一 |

作者の自己点検後、別担当が**修正後の最終版**について以下を確認する。合否・指摘・根拠は対象IDと版／ハッシュにひもづける。

- [ ] 初学者がどこで止まるかを想定し、各段階で新しい情報を得られる。
- [ ] 定義・公式・比較軸・具体例など、次の判断に必要な足場がある。全問共通文や同義反復で埋めていない。
- [ ] 問題文・全選択肢・各欄・それまでのヒントと照合し、残る判断を実際に辿れる。
- [ ] 開示判定が内容に一致する。正答と実質同じ定義、全誤答の消去、名称・最終値、強調も確認した。
- [ ] 公式解答・一次資料と式・数値・単位・時点・例外が一致する。原本のない独自問題は設定した根拠から検算した。
- [ ] 表示・採点・履歴が開示フラグと整合する。未開示情報や他欄の正答が意図せず出ていない。

レビューは作者と別担当による読み直し・問題の解き直しで行える。実際に初学者へ試していない場合、「初学者で効果を確認済み」と記録しない。形式チェックやフラグの有無だけでは内容承認にしない。

## 既存教材への適用

新規・改稿はこの基準で受け入れる。**既存の公開済み・レビュー済み教材も対象**だが、従来の承認を新基準での確認済みに読み替えない。

1. 資格・科目・問題ID／版・作成元・旧レビュー・担当と未確認草稿を棚卸しする。未着手／作者改稿済み／別担当確認待ち／確認済みを分ける。
2. 各問を本基準で点検し、十分なヒントは維持する。不足だけを直し、段数や定型文の一括置換はしない。ヒント未設置は、それだけで不合格にはしない。
3. 修正したら同じIDの版を増やし、修正後の内容を別担当が確認する。旧版・旧レビュー・原本を保持し、所定の台帳・ハッシュ・生成物を更新する。
4. 公開は確認済みの範囲に限る。途中の学習記録には保存された旧教材を残し、本人の過去の回答・支援履歴を新しい判定へ書き換えない。
