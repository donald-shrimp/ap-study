# 学習体験と学習効率を両立する設計案

調査日：2026-10-05。対象：開発中の応用情報学習アプリ。

利用目的は2026年中の受験に向けた過去問学習。過去問の収集とヒント・解説の追加、演習と解き直しを中心にする。制度変更やシラバス比較は対象に含めない。

## 設計の中心

**始める・操作する・再開する負担を減らし、思い出す・比較する・説明する練習を支える。**

使いやすさは、開けばすぐ次の行動が分かり、中断しても戻れること。学習効率は、使った時間に対して後日自力で使える知識が増えること。この2つを別々に観察する。

その場の正答率、滞在時間、連続利用日数だけで良いアプリと判断しない。ヒントで理解できた経験を肯定し、その知識を後から助けなしで確かめられるようにする。

研究の対象・確認範囲・出典は [調査メモ](research-notes.md) に記載。以下の画面・出題ルールは研究を参考にした製品設計であり、ADHDの成人に対するこのアプリの効果が実証されたものではない。

## 1. 主要な設計判断

| 判断 | 採用する案 | 根拠と限界 |
|---|---|---|
| 始めるまでの操作 | ホームに「まず1問」。年度・分野・問数の設定は任意 | W3Cは主要な操作までの経路を短くし、任意の手順を必須にしないことを推奨 [R10] |
| 学習単位 | 1問で完了。3・5問にも変更可能。長文問題は後に設問単位の区切りを検討 | NICEの短い集中区間と休憩 [R1]。1・3・5という数は設計仮説 |
| ヒント | 必要なときすぐ開ける。1段ずつ提示。強制的な待ち時間や回数制限を設けない | 支援量の最適なバランスは未解決 [R7]。本人に選択権を持たせ、後日確認する |
| 初学者の支援 | 知らない概念には短い解法例・基礎説明を用意し、次に自分で解く機会を置く | IESの解法例と問題演習の組合せ [R6]。例を読むだけで終わらない |
| 復習 | 日をあけて、ヒントと解答を閉じて開始する | 想起練習と分散学習 [R3–R5]。具体的な間隔は調整が必要 |
| 解説 | 結論→今回の判断手順→選択した誤答の理由→詳細 | フィードバックは伝える情報の内容で効果が変わる [R8]。この表示順は設計案 |
| 教材の並び | 新規は概念ごとのまとまり。理解後に似た概念を混ぜ、使い分けを練習 | 学習法レビュー [R11]。初回から全分野を無秩序に混ぜることは推奨しない |
| 進捗 | 「別の日に自力正解」「使ったヒント」「関連する別問題の結果」を分けて示す | 学習直後の流暢さと後日の保持は異なる [R5][R6][R11] |
| 中断 | 操作ごとに保存し、再開時に現在地と直前の操作を短く表示する | W3Cの保存・現在地・注意の回復に関するパターン [R10] |
| 報酬 | 学習上の具体的な前進を短く伝える。音・動き・連続記録は任意 | ゲーム化には効果の報告があるが、設計・対象による差がある [R9] |

## 2. 画面ごとの体験

### ホーム：次にすることを決めやすい

- 主ボタンは「まず1問」。中断中なら「続きから」を提案する。
- 中断した問題が負担なら「別の1問」へ進める。途中の問題は残し、誤答にしない。
- 今日の復習がある場合は「今日はこの問題を確認します」と短く理由を表示する。
- 復習の総残数は必要なときに確認できる。開いた瞬間に未処理件数を大きな警告として見せない。
- 詳細な成績と設定は別の入口へ置く。初回の長い設定ウィザードは用意しない。

### 問題：読む・考えることに集中できる

- 問題文、図表、選択肢、ヒント、回答ボタンの位置をそろえる。
- 選択肢を選んだだけでは採点せず、「回答する」で確定する。
- 図表は関連する文章の近くに置く。小さい画面では拡大して戻れる。
- 自信は回答前の任意の1操作にする。毎問の入力を必須にしない。
- ヒントを開いても選択中の回答や問題内の位置を保つ。
- すぐ分からない場合の入口を「ヒント」「解法を読む」「あとで」にする。
- ヒントの利用や解答閲覧を理由に点を減らす仕組みは設けない。

### 解説：次の問題に使える手順を持ち帰る

短い要点だけでも、その問題の理由を理解できる内容にする。詳細は展開できる。

1. 結論：正答と要点。
2. 判断手順：何を見て、何を比較・計算したか。
3. 今回の誤答：選んだ選択肢が当てはまらない条件。
4. 次回の手がかり：「まず単位をそろえる」など、次にも使える具体的な行動。
5. 任意の詳細：他の選択肢、前提知識、図解、関連する解法例。

理解を確かめる短い「なぜ？」や途中計算は教材に応じて任意で付ける。自由記述を毎問要求しない。追加の選択式確認だけで深い理解が測れるとも扱わない。

### 終了・再開：学習を区切り、戻りやすくする

- 「今日はここまで」と「次の1問」を同じ画面に置く。自動で次の問題へ進めない。
- 終了時は「1問取り組みました」「次はこの概念を確認します」と短く示す。
- 再開時は「転送時間の問題／ヒント2まで確認／選択肢は未確定」のように現在地を表示する。
- 保存済みの回答候補、ヒント、メモ、位置を復元する。保存に失敗した場合は明示する。
- タイマーを使う場合も、終了時に強制採点しない。時間の目安と休憩は本人が選べる。

## 3. ヒントの具体例

以下は教材の構造を示す自作例。IPAの過去問ではない。

> 12 Mバイトのデータを、通信速度8 Mビット/秒、実効利用率75%の回線で転送する。転送時間は何秒か。Mは10の6乗とし、その他のオーバーヘッドは考えない。
>
> 選択肢：8秒／12秒／16秒／24秒

| 段階 | 提示する内容 | 学習者が行うこと |
|---|---|---|
| H1：注目点 | データ量はバイト、速度はビット。実効利用率も条件にあります | 単位と条件に気づく |
| H2：手順 | データ量をビットに直し、通信速度に利用率をかけます。時間＝データ量÷実際の速度です | 式を選び、単位を合わせる |
| H3：適用 | 12×8＝96 Mビット。8×0.75＝6 Mビット/秒。96÷6を計算しましょう | 最後の計算を行う |
| 解説 | 96÷6＝16秒。12秒という答えは実効利用率を反映していません | 誤りの原因と次の手順を理解する |

後日の復習はヒントを閉じて始める。別問題ではデータ量・速度・利用率・表現を変え、同じ手順を適用できるか確かめる。選択肢の位置や数値だけを記憶した正解と区別する。

語句問題では無理に計算用の3段階へ合わせず、「定義の観点→似た概念との違い→条件への適用」にする。H3で事実上正答を明かす教材は解答閲覧として扱う。ヒントの段数は教材に合わせて変更する。

## 4. 復習と習熟の扱い

### 問題の記録と概念の記録を分ける

同じ問題の繰り返しだけでは、その答えを覚えて解ける場合がある。問題IDに加え、学習する概念と関連問題のグループを教材に付ける。問題ごとの正誤を概念全体の習熟にそのまま変換しない。

記録は少なくとも次を区別する。

- その試行の自力正解、ヒント付き正解、不正解、解答閲覧、途中、あとで。
- 解答前に見たヒント、解答後に読んだ解説。
- 同じ日の再挑戦、別の日の確認、関連する別問題。
- 実際に正答を見せる内容が出た時点。段階番号だけで支援の強さを同一視しない。

「別の日に自力正解：2回」のように観察した事実を表示する。回数だけで「完全習得」「試験合格レベル」と断定しない。

### 出題する順序

出題候補は、直近の不正解、ヒント付き正解、任意の低い自信、復習日、最近の出題回数を使って選ぶ。特定の問題が毎回出続けないよう、同日の重複を抑える。

初期の間隔は翌日・3日・7日・14日などを仮置きし、結果に応じて調整する。ヒントの数が多いほど必ず短くする、といった細かな数式を科学的な最適値として導入しない。苦戦が続く概念には、再出題だけでなく基礎説明や解法例を提案する。

復習がたまった日は小さな単位で再開する。選んだ単位内で復習を優先しつつ、新しい概念への入口も残す。期限切れを個人の失敗として扱わない。

### 出題方法の段階

1. 初めての概念：短い説明・解法例→自分で1問。
2. 理解の確認：後日に同じ問題を助けなしで試す。
3. 応用の確認：収集した過去問の中で、同じ概念の別問題、似た概念との使い分け。
4. 任意のまとめ演習：希望する場合は複数の過去問を続けて解く。

初期版では選択式の過去問を使って体験を検証する。長文・記述式への拡張は必要に応じて判断し、試験全体の模試は初期版の必須機能にしない。

## 5. 採用を急がない設計

| 設計 | 判断する理由 | 当面の案 |
|---|---|---|
| 25分集中を全員に必須 | 個人に合う時間を固定できない | 1問で終了可能、時間は任意 |
| ヒント前に30秒待たせる | 最適な待ち時間の根拠がなく、分からない人の負担が増え得る | すぐ支援へ進める |
| 不正解だけを復習 | ヒント付き正解や偶然の正解も再確認が必要 | 支援利用と任意の自信も記録 |
| 正答率から合格確率を表示 | 出題範囲・難度・支援の有無が違い、妥当な推定モデルがない | 確認できた事実を表示 |
| 全分野を最初からランダム出題 | 新しい概念を理解するまとまりを失いやすい | 新規は概念ごと、理解後は使い分け |
| 連続記録を失うと大きく警告 | 再開への影響はこのアプリで未検証 | 累積の取り組みと具体的な前進を表示 |
| 解説を毎回長文で表示 | 情報の選別に負担がかかる | 要点から詳細へ展開 |
| 派手な演出や音を常時使用 | 注意を妨げる可能性があり、好みも異なる | 小さな視覚的反応、動きと音は任意 |
| AIが毎回ヒントを生成 | 不正確さや支援量の変動で学習を損なう可能性 | レビュー済みの教材を配信 |

ゲーム化の研究は平均的に好ましい効果を報告している [R9]。そのため一律に否定せず、このアプリでは必要性と本人への負担を確かめて追加する。特定の報酬方式がADHDに最適とは主張しない。

## 6. 何を測れば改善が分かるか

| 観点 | 観察・指標 | 読み違えを避ける方法 |
|---|---|---|
| 始めやすさ | ホームから最初の問題までの操作数、入口が分かるか | 速さだけで評価せず、本人の負担も聞く |
| 再開しやすさ | 中断後に現在地を説明できるか、保存内容が戻るか | 中断自体を失敗と集計しない |
| 操作の負担 | ヒント・終了・回答が迷わず使えるか、必須入力の数 | 操作を減らして誤操作が増えていないか確認 |
| 保持 | 決めた期間をあけた初回試行の自力正解率 | 支援付き、解答閲覧、同日再挑戦を分ける |
| 応用 | 同じ概念の未見の別問題での結果 | 同じ問題の答えの記憶と混ぜない |
| 支援の有効性 | 支援利用の推移と、後日の自力正解 | ヒントの少なさだけを成功と判定しない |
| 学習効率 | 学習への実際の負担に対し、保持・応用が増えたか | 滞在時間は放置を含むため、そのまま学習時間にしない |

正解率の分母は対象の確認問題への回答数とし、対象総数・未実施数も別に示す。簡単な問題だけを解いた結果が全体の習熟に見えないようにする。

最初の1〜2週間は操作・着手・再開を中心に観察する。数週間にわたる利用では、一定期間後の確認問題を用意し、問題の難度、出題範囲、学習に使った時間をそろえられる範囲で比較する。個人の小規模な利用だけで、一般的な効果や因果関係を結論づけない。

## 7. 初期版への反映順

1. 1問開始、手動で終了、中断保存と現在地の復元。
2. レビュー済みのヒント・解説と、支援の有無を分けた履歴。
3. 後日の解き直し、少量の復習候補、事実に基づく進捗表示。
4. 少数の重要概念に関連問題を用意し、別問題での確認を試す。
5. 利用で負担を確かめた後に、通知・報酬・出題の細かな調整を追加。

開発中のため、これらの判断・画面・データ構造は変更できる。後方互換性や旧データの移行対応を必須にしない。
