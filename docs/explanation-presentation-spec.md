# 解答解説の表示・強調 — 全資格共通仕様（提案）

> **状態：設計提案。実装・教材改稿・独立レビューはこのPRの対象外。**
> 対象：応用情報（科目A／B）、AB-730、FP2級など、ひと問に登録されたすべての資格・試験回・科目と、今後追加する資格。
> 記述の詳細は [解答解説の共通記述ルール](explanation-authoring-rules.md) を参照。

## 1. 目的と判断

解答後に、**何を問うか・なぜその答えになるか・類題で使える知識**が分かるようにする。**正誤を分ける条件・数値・例外を限定的に太字**で示す。説明を増やすことや、三つの欄を埋めることを目的にしない。

書式は **Markdown のインライン太字 `**重要部分**`** とする。教材データに `<b>`、`<strong>`、`<br>` などの生HTMLを書かせない。

| 方式 | 評価 |
| --- | --- |
| `**重要部分**` | **採用。** 著者が書きやすく、JSONでは単なる文字列。既存の `src/ui/question-text.js` に太字の限定表示処理があるため実装方針をそろえられる |
| `<strong>重要部分</strong>`／`<b>` | **不採用。** HTMLを教材に混ぜるとタグの許可・サニタイズ・注入対策が難しくなり、記述と表示が密結合する |
| `<br>` | 太字ではなく改行用のHTMLタグ。強調表記として不適切。改行が必要なら通常の改行文字を使う |

新しく共通化する書式は、**`**…**` による安全なインライン強調**とする。フル機能のMarkdownパーサの導入は求めない。科目B・実技で利用中の数式・表・コード・段落の表示機能は維持する。

## 2. 既存コードとの関係

- `src/ui/views.js` の `resultHTML(q,a)` は、選択式問題の `summary`、`explanation`、`choiceReasons[]`、`takeaway` をすでに別領域に表示している。ただし本文は `esc(...)` でエスケープした文字列として表示し、現状の解説データの `**…**` は強調されない。
- `src/ui/planning.js` の診断／模試の結果は、保存済みの `materialSnapshot` から `summary`・`explanation`・`choiceReasons[]` を `esc(...)` で表示する。`takeaway` は現在未表示なので、保存されている場合は結果の解説にも追加する。回答中には表示しない。
- `src/ui/question-text.js` の `questionTextHTML()` は問題文・選択肢に加え、`src/features/written.js` の `fields[].explanation` にも使用している。太字・数式・表・コード・段落を扱う既存のブロック表示を、太字だけの関数に置き換えない。
- **インライン強調の処理を共通化**し、通常学習・診断／模試の解説と既存のブロック表示で同じ太字記法を使う。ブロック表示全体を解説の `<p>` 内へ埋め込まず、段落タグの入れ子を避ける。生の教材文字列をHTMLとして信頼しない。
- 資格IDで分岐せず、各形式の画面構成・採点・正答開示タイミングを維持する。共通化のためにケースの回答欄へ新しいフィールドを増設しない。

## 3. 解答後の表示構造

| 保存フィールド | 役割 | 表示上の要件 |
| --- | --- | --- |
| `summary` | **何を問われているか**。確認したい概念・判断軸を先に示す | 存在する場合に正答表示後に簡潔に表示する。専用の見出しやカードを増やす必要はない |
| `explanation` | **なぜそう判断するか**。用語の定義、解法の順序、根拠、例外、必要な計算 | 既存の「解説」領域を維持。不正解時等の展開状態を破壊しない |
| `choiceReasons[]` | **各選択肢の適切／不適切の理由**。一肢ごとの相違点 | 既存の選択肢別表示を維持し、本文中の太字だけを追加で解釈する |
| `takeaway` | **次回に覚えておくべき規則・見分け方** | 存在する場合に「要点」として表示し、summary/explanationの単なる繰り返しを避ける。本文の太字を見出し扱いしない |
| `hints[].text` | 解答前の段階的な補助 | **答え漏えい防止が最優先**。この仕様を理由に正答番号・正答文を新たに強調／露出しない。任意の太字対応も同じ安全なパーサを使う |
| ケース・実技の `fields[].explanation` など既存の解説文字列 | 各回答欄の根拠と計算の説明 | 既存フィールドを保ち、同じ太字記法で表示できるようにする。回答欄単位の採点・開示条件を変えない |

`summary`・`takeaway` は任意のままとし、ない場合はその領域だけ省略する。短い問題は `explanation` と各肢の理由だけで十分な場合もある。既存の「復習メモ」などフォールバック挙動を維持し、必須項目を新設しない。同じ説明を別の枠に重複コピーしない（不正解肢の理由を先行表示するときの重複にも留意）。

共通にするのは**説明の役割と強調の書式**。三つの見出し・カードや一律の文章量を要求しない。解説は各モードの既存の開示条件を満たした後に表示し、診断・模試では終了後の結果公開まで表示しない。

### 「要点」のラベルと本文の強調

現行の `.takeaway strong` と `.result .takeaway strong` は、`strong` 全体にラベル用の改行・文字サイズ等を適用する。実装では「要点」のラベルを専用クラス（例：`.takeaway-label`）等で区別し、ラベル用のスタイルを本文の `strong` に適用しない。本文の強調は**インラインのまま、周囲の文字サイズを保つ**。太字を付けた語の前後に意図しない改行や余白を作らない。

## 4. 許可する記法とレンダリング契約

1. 太字は**同じ行で閉じる、非空の `**文字列**`** のみをサポートする。通常の文章と複数の強調箇所を混在させられる。
2. 無装飾の既存テキストは**表示・改行ともに従来どおり**。未対応Markdown、閉じていない `**`、空の `****` は破壊せず文字として表示する。深いネストや複雑なマークダウン記法を要求しない。
3. 文字列を必ずHTMLエスケープし、**整合した強調トークンにだけ実装側が `<strong>` を生成**する。安全性は「置換の前にエスケープ」または「文字列をトークン化してテキスト部分ごとエスケープ」で担保し、`innerHTML` へ生の教材文字列を流さない。
4. 教材内の `<script>`、`<img onerror=...>`、`<strong>`、`<br>` は実行・解釈しない。**生HTML、任意リンク、画像、イベント属性、任意CSSは認めない**。
5. 太字は意味上の強調として `<strong>` を使い、配色だけに依存しない。文字サイズ・テーマ・大きな文字設定でも本文が読めるようにする。
6. 問題文・選択肢と、科目B／実技の解説で使う数式（KaTeX）・表・コード・段落の表示を維持する。コード中の `**` を強調に変えたり、数式内の記号を強調の区切りとして解釈したりしない。既存機能の回帰確認を行い、新しい数式構文は追加しない。
7. 強調の有無で正誤判定、検索、学習記録、ヒント消費数、選択肢ID、法令基準日、読み込み済み問題の復元を変えない。必要な箇所では**装飾を除いた本文**をテキストとして利用する。
8. `referenceAnswers`・正答ID・数値の採点用文字列には強調マーカーを入れない。`rubric[]`・ラベル・出典等は今回の強調対象に追加せず、既存の表示・採点契約を維持する。

## 5. 遡及適用・互換性の方針

**草稿の作成と、強調付き教材の公開を分ける。** 新規・既存の草稿にはこの役割分担と太字記法を使える。強調付き教材の公開は次の順で進める。

1. 通常学習・診断／模試の結果・科目B／実技を対象に、共通の強調処理とCSSを実装する。解説の開示条件、保存済み教材の再開、既存のブロック表示を確認する。
2. 表示対応を先に公開し、公開ファイルとの一致と、PWAの初回起動・既存キャッシュからの更新・取得済み教材のオフライン表示を確認する。
3. 強調付き教材を独立レビュー・既存の版／ハッシュ更新・再生成を経て公開する。新規教材にも同じ順序を適用する。

古いクライアントやキャッシュの混在時も、少なくとも記号を含む本文が読め、採点・入力・学習記録を壊さないことを確認する。全端末の更新完了を待つことや、記録を消して更新させることは求めない。強調のない既存教材はそのまま表示する。

実装・レビュー担当の移行対象（このPRでは**編集しない**）：

- FP2級・2025年1月の学科 **60問**、2024年9月の学科 **20問**：別Draft PR #38 の作問済み80問。まず `summary`／`explanation`／`takeaway`、必要な `choiceReasons[]` に最小限の `**…**` を追加する。
- 既存のAP・AB-730・その他公開教材：**資格によらず同じ表示仕様**を使う。公開済み教材の一括文字列置換は避け、作者・レビュワーの確認フローに従い順次強調を加える。
- 原文・正答・理由・出典・法令時点を**太字化のついでに変更しない**。装飾変更でも作成元データのハッシュや保存スナップショットが変わり得るため、既存の版管理・独立レビュー・再生成規約を守る。
- 未レビュー教材を `reviewed` に昇格させない。既存の独立レビュー記録や署名・ハッシュを捏造／再利用しない。

既存の解説に太字がないこと自体はエラーにしない。安全なレンダリング提供と、著者による段階的な内容強調を独立して進められるようにする。
