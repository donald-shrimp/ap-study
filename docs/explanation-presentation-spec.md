# 解答解説の表示・強調 — 全資格共通仕様（提案）

> **状態：設計提案。実装・教材改稿・独立レビューはこのPRの対象外。**
> 対象：応用情報（科目A／B）、AB-730、FP2級など、ひと問に登録されたすべての資格・試験回・科目と、今後追加する資格。
> 記述の詳細は [解答解説の共通記述ルール](explanation-authoring-rules.md) を参照。

## 1. 目的と判断

解答後の解説を「**この問題では何を問うか** → **どう考えて判断するか** → **何を覚えるか**」の順で読み進められるようにする。**正誤を分ける条件・数値・例外を限定的に太字**で示し、原文の説明を削らずに視線誘導する。

書式は **Markdown のインライン太字 `**重要部分**`** とする。教材データに `<b>`、`<strong>`、`<br>` などの生HTMLを書かせない。

| 方式 | 評価 |
| --- | --- |
| `**重要部分**` | **採用。** 著者が書きやすく、JSONでは単なる文字列。既存の `src/ui/question-text.js` に太字の限定表示処理があるため実装方針をそろえられる |
| `<strong>重要部分</strong>`／`<b>` | **不採用。** HTMLを教材に混ぜるとタグの許可・サニタイズ・注入対策が難しくなり、記述と表示が密結合する |
| `<br>` | 太字ではなく改行用のHTMLタグ。強調表記として不適切。改行が必要なら通常の改行文字を使う |

フル機能のMarkdownパーサを導入する要求ではない。**解説向けに `**…**` だけを解釈する限定的で安全なインライン整形**を標準とする。

## 2. 既存コードとの関係

- `src/ui/views.js` の `resultHTML(q,a)` は、選択式問題の `summary`、`explanation`、`choiceReasons[]`、`takeaway` をすでに別領域に表示している。ただし本文は `esc(...)` でエスケープした文字列として表示し、現状の解説データの `**…**` は強調されない。
- `src/ui/question-text.js` の `questionTextHTML()` は問題文・選択肢に限り `**…**` を `<strong>` に変換する限定書式を実装済み。ただしこの関数は数式・表・コードブロックも扱うため、**そのまま解説の `<p>` 内へ埋め込んで二重の段落タグを作らない**こと。
- 実装担当は**安全なインライン強調処理を共通化・再利用するか、新規の小さな共通関数に切り出すか**を選べる。ユーザー入力からHTMLを信頼して挿入してはいけない。
- 選択式以外の科目B等の解説、ケース／実技の各回答欄にも、**同じ表記と安全性の契約**を適用する。画面構成と採点方式は各形式の現状を保持し、資格IDで分岐しない。

## 3. 解答後の表示構造

| 保存フィールド | 役割 | 表示上の要件 |
| --- | --- | --- |
| `summary` | **何を問われているか**。確認したい概念・判断軸を先に示す | 正答表示後に簡潔に常時表示する。可能なら「この問題で問われること」と分かる見出しを付ける |
| `explanation` | **なぜそう判断するか**。用語の定義、解法の順序、根拠、例外、必要な計算 | 既存の「解説」領域を維持。不正解時等の展開状態を破壊しない |
| `choiceReasons[]` | **各選択肢の適切／不適切の理由**。一肢ごとの相違点 | 既存の選択肢別表示を維持し、本文中の太字だけを追加で解釈する |
| `takeaway` | **次回に覚えておくべき規則・見分け方** | 既存の「要点」領域を維持。summary/explanationの単なる繰り返しを避ける |
| `hints[].text` | 解答前の段階的な補助 | **答え漏えい防止が最優先**。この仕様を理由に正答番号・正答文を新たに強調／露出しない。任意の太字対応も同じ安全なパーサを使う |
| ケース・実技の `fields[].explanation` など既存の解説文字列 | 各回答欄の根拠と計算の説明 | 既存フィールドを保ち、同じ太字記法で表示できるようにする。回答欄単位の採点・開示条件を変えない |

フィールドがない場合は**その領域だけ省略**し、既存の「復習メモ」などフォールバック挙動を維持する。必須項目を新設する仕様ではない。表示では、同じ説明を別の枠に重複コピーしない（不正解肢の理由を先行表示するときの重複にも留意）。

この3段階の構造と強調は**資格を問わない共通の学習体験**とし、資格ごとの独自レイアウトや別パーサを増やさない。解説は**解答確定後**に表示する。診断・模試など結果公開まで正答を出さないモードでも、従来の開示タイミングを厳守する。

## 4. 許可する記法とレンダリング契約

1. 太字は**同じ行で閉じる、非空の `**文字列**`** のみをサポートする。通常の文章と複数の強調箇所を混在させられる。
2. 無装飾の既存テキストは**表示・改行ともに従来どおり**。未対応Markdown、閉じていない `**`、空の `****` は破壊せず文字として表示する。深いネストや複雑なマークダウン記法を要求しない。
3. 文字列を必ずHTMLエスケープし、**整合した強調トークンにだけ実装側が `<strong>` を生成**する。安全性は「置換の前にエスケープ」または「文字列をトークン化してテキスト部分ごとエスケープ」で担保し、`innerHTML` へ生の教材文字列を流さない。
4. 教材内の `<script>`、`<img onerror=...>`、`<strong>`、`<br>` は実行・解釈しない。**生HTML、任意リンク、画像、イベント属性、任意CSSは認めない**。
5. 太字は意味上の強調として `<strong>` を使い、配色だけに依存しない。文字サイズ・テーマ・大きな文字設定でも本文が読めるようにする。
6. 既存の問題文向け数式（KaTeX）・表・コードのパーサは壊さない。解説で数式・表が必要な場合は既存機能と干渉しない形を設計／別途審査し、このPRでは追加の数式構文を要求しない。
7. 強調の有無で正誤判定、検索、学習記録、ヒント消費数、選択肢ID、法令基準日、読み込み済み問題の復元を変えない。必要な箇所では**装飾を除いた本文**をテキストとして利用する。

## 5. 遡及適用・互換性の方針

**新規教材はこのルールを直ちに作問仕様として採用**する。既存教材は、表示処理が対応するまでは通常のプレーンテキストとして扱う。

実装・レビュー担当の移行対象（このPRでは**編集しない**）：

- FP2級・2025年1月の学科 **60問**、2024年9月の学科 **20問**：別Draft PR #38 の作問済み80問。まず `summary`／`explanation`／`takeaway`、必要な `choiceReasons[]` に最小限の `**…**` を追加する。
- 既存のAP・AB-730・その他公開教材：**資格によらず同じ表示仕様**を使う。公開済み教材の一括文字列置換は避け、作者・レビュワーの確認フローに従い順次強調を加える。
- 原文・正答・理由・出典・法令時点を**太字化のついでに変更しない**。装飾変更でも作成元データのハッシュや保存スナップショットが変わり得るため、既存の版管理・独立レビュー・再生成規約を守る。
- 未レビュー教材を `reviewed` に昇格させない。既存の独立レビュー記録や署名・ハッシュを捏造／再利用しない。

既存の解説に太字がないこと自体はエラーにしない。安全なレンダリング提供と、著者による段階的な内容強調を独立して進められるようにする。
