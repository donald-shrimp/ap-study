# 次の工程：Firebaseを用意する

2026-10-06時点ではプロジェクト未作成。公開アプリは端末内保存で動き、Googleログイン・同期はまだ提供していない。共通化・資格別教材・IndexedDB保存は実装済み。

## 作るもの

1つのFirebaseプロジェクトに、Webアプリ、Googleログイン、Firestoreを用意する。教材・画像の配信は引き続きGitHub Pages。最初はSpark無料プランを使い、Cloud Functions・SMS認証は追加しない。

## 作成手順

1. [Firebase Console](https://console.firebase.google.com/)をGoogleアカウントで開き、「プロジェクトを作成」。表示名は「ひと問」などでよい。Google Analyticsはこの機能には不要。
2. プロジェクトの設定からWebアプリ（`</>`）を登録する。Firebase Hostingは使わない。表示された `firebaseConfig` とプロジェクトIDを控える。
3. Authentication → ログイン方法 → Googleを有効にする。サポートメールを設定し、承認済みドメインに `donald-shrimp.github.io` を追加する。パス `/ap-study/` はドメイン欄へ入れない。
4. Firestore Databaseを作成する。最初は本番モードで作成し、まだ記録を公開・書込許可しない。場所は後から変更できないため、利用地域に合わせて選ぶ（主に日本で使う場合は東京など）。
5. プロジェクトIDと `firebaseConfig` を開発担当へ渡す。Web設定はクライアント配布用で、管理者鍵・サービスアカウント鍵は不要。

Spark無料枠は同じプロジェクト内で共有される。2026-10-06の[公式料金](https://firebase.google.com/pricing)を基準に利用量を確認する。無料枠を超えた場合も端末内で学習を続けられる同期を実装する。

## 設定を受け取ってから実装すること

- Googleログインと、ゲスト記録をアカウントへ追加する選択。
- UID・資格別の送受信。未送信を別のアカウントへ送らない。
- 本人だけが読み書きできるFirestore Rulesと、改ざん・他人の領域・確定回答上書きの拒否。
- ページ分割とサーバー時刻による差分取得、安定IDによる再送。
- 別端末の中断からの継続と、同時回答を両方残す処理。
- 2ブラウザ・通信断・再送・アカウント切替・権限拒否の検証。
- PC・Android Chrome・インストールしたPWAで実際のGoogleログインを確認。

Firestoreへ公開教材や画像を複製しない。読書メモ・個人教材・設定の同期は後の工程とし、端末内で使い続ける。アプリの学習画面とオフライン動作は、ログインSDKの初回通信に依存させない。
