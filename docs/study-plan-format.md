# StudyPlan JSON と学習状況Export

2026-10-15から、アプリの公開形式は **version 2のみ**です。旧形式は実行時に読み込みません。保存済みのファイルは[一回変換の手順](learning-record-v2.md)で変換します。

- [計画のJSON Schema](../schemas/study-plan.v2.json)
- [科目A・B共通計画のサンプル](../schemas/study-plan.example.json)（日付は説明用）

## 計画を登録する

「受験日・学習計画」で手動編集、またはAI用プロンプトをコピーして相談します。返されたJSONを「検証してプレビュー」→「この内容で登録」で取り込みます。計画の変更は学習記録を変更しません。未知の版・項目・別資格・不正な日付・逆転や重複した期間は登録前に拒否します。256KB、24フェーズまでです。

## `hitomon-study-plan` / version 2

| 項目 | 意味 |
| --- | --- |
| `qualificationId` | `ap`、`ab730`など、現在の資格 |
| `timeZone` | IANAタイムゾーン。標準は`Asia/Tokyo` |
| `examDates` | `{examPartId, date}`。科目ごとに1件。日付は`YYYY-MM-DD` |
| `phases` | 最大24件。同じ資格の共通計画 |
| フェーズの`id`・`name` | 重複しないIDと表示名 |
| `start`・`end` | 両端を含む、重複しない期間 |
| `examPartIds` | この期間の対象科目 |
| `goals` | `{examPartId, unit, target}`の配列。1科目1件、目標は1〜100000 |
| `focusTopicIds` | 重点分野。対象科目の重点外の学習も実績に数える |
| `weeklyTargets` | 任意の`{id,start,end,goals}`配列。週ごとにも科目・単位を保持 |
| `milestones` | 任意の`{id,name,date,examPartId,completed}`配列。本人が完了操作 |
| `context` | 任意の学習済み範囲・教材・週の分数・制約・理由・更新日 |

応用情報の科目Aは`objective` / `questionAttempts`（問）、科目Bは`written` / `cases`（大問の題数）です。AB-730は`objective` / `questionAttempts`。AとBの件数を足しません。同じ期間にA100問、B3題を登録できます。

A・AB-730は取り組みを確定した回数を数え、解き直し・自力正解・ヒント付き正解・不正解・解答閲覧を含みます。診断の通常問題は含みますが、診断の派生・模試・未回答は含みません。Bは全欄の回答確定（「分からない」を含む）と自動判定／自己評価まで終えた大問だけを数えます。部分終了・評価待ちは完了題数に含めません。予定のチェックを学習実績には加算しません。

週別目標は1フェーズ104件まで、フェーズ内の重複しない1〜7日です。科目ごとの週目標の合計はそのフェーズ目標以下。目標の自動按分・未達の次週への繰り越しはしません。未来の日時の学習記録は、その時点まで実績へ加算しません。

`context`の文章は各2000文字以内、`weeklyMinutes`は0〜10080、`updatedOn`は実在する日付です。AIからの計画で`context`を省略すると現在の前提を維持し、`context:{}`なら明示的に削除します。未入力の前提は推測しません。

## `hitomon-study-summary` / version 2

`learningByPart`に科目・単位別の実績を収録します。A・AB-730は累計／今日／直近7日／28日、完了回数・問題種類数・自力正答率・分野ごとの母数を含みます。Bは完了題数を別に持ち、自己評価を公式点数・合格可能性へ読み替えません。診断・固定模試、受験日と残日数、前提、現在計画、科目別の期間・週の実績も含みます。

通常問題本文・アカウントのUID／メールは含めません。前提に本人が入力した文章は含むため、コピー前にプレビューできます。AIとの自動通信やAPI課金は行いません。

## 計画の履歴と保存

変更時には`hitomon-plan-revision` / version 2で計画全体・日時・理由・変更元を保存します。終了した期間は、終了時に保存されていた計画を基準に表示し、後日の目標引き下げで過去目標を塗り替えません。既存計画があるバックアップ取り込みでは、その計画を保持し履歴を追加します。

新しい端末保存領域と`resourcesV2`を使用します。旧保存先・旧クラウド文書は自動移行も削除もしません。新版Firestore Rulesの本番公開は別工程です。端末間の競合では使う内容を選び、確定済みの診断・模試・大問を上書きしません。[同期設定](firebase-setup.md)。
