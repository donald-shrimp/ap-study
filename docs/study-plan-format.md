公開形式の版1です。AI APIは使わず、コピーとJSONの取り込みで利用できます。

- [JSON Schema](../schemas/study-plan.v1.json)
- [登録できるサンプル](../schemas/study-plan.example.json)（受験日は説明用の仮値）
- [人間向けの設計・実装範囲](study-planning-review.html)

## 計画の往復

「受験日・学習計画」で「AI用プロンプトをコピー」。学習状況、有効な資格・パート・分野ID、対応フォーマットが入ります。使っているAIに貼り付け、計画を相談してください。返されたJSONを貼り、「検証してプレビュー」→「この内容で登録」と進みます。手動登録・編集もできます。

計画の取り込みで変更するのは、その利用者・資格の受験日と有効な計画です。回答・ヒント・診断の履歴は変更しません。不正なJSON、別資格、未知の項目・版、参照できないID、実在しない日付、逆転・重複した期間は登録しません。256KB、24フェーズまでです。取り組み回数の目標には、教材のあるパートを1つ以上指定してください。

## `hitomon-study-plan` / version 1

| 項目 | 意味 |
| --- | --- |
| `format` / `version` | `hitomon-study-plan` / `1` |
| `qualificationId` | 開いている資格のID。応用情報は `ap` |
| `timeZone` | 有効なIANAタイムゾーン。既定は `Asia/Tokyo` |
| `examDates` | `examPartId` と `YYYY-MM-DD` の `date`。未登録なら空配列 |
| `phases` | 最大24件。計画なしなら空配列 |
| フェーズの `id` / `name` | 重複しない英数字IDと表示名 |
| `start` / `end` | 両端を含む期間。フェーズ同士を重複させない |
| `examPartIds` | 取り組み回数を数えるパート |
| `targets.completedAttempts` | 解き直しを含む取り組み回数。1〜100000の整数 |
| `focusTopicIds` | 重点分野。対象パート内なら他分野も実績に数える |

パート・分野IDは資格定義に従います。現在の応用情報は `objective`（選択式・午前過去問）と `written`（記述式・教材未対応）。受験日はどちらも登録できます。演習の実績は提供している教材のみから計算します。

取り組み完了回数は、自力正解・ヒント付き正解・不正解・解答閲覧の合計です。異なる問題数とは別です。診断は終了時に、回答を確定した問題の正解・不正解を加えます。診断の未回答は加えません。日々の未達の繰越や週目標の自動生成はしません。

版1では週別目標・手動マイルストーン・AIによる自動変更を扱いません。未対応項目を黙って削除せず、検証で知らせます。公開版の意味を読み替えず、将来の拡張はSchemaの対応版を明示します。内部の同期用 `revision`、UID・端末ID、実績値は計画JSONに入れません。

## `hitomon-study-summary` / version 1

AIへの相談用です。集計日時・資格・タイムゾーン・受験日と残日数、累計／今日／直近7日／28日の取り組み回数、異なる問題数、4種類の結果内訳、分野別の母数と自力正解数、復習候補数、終了した診断、現在の計画・フェーズ実績を出します。

自力正答率は、学習履歴（終了した診断の回答を含む）では「自力正解数÷取り組み完了回数」。解き直しを含み、習熟や合格可能性ではありません。診断の正答率は「正解数÷回答確定数」で、未回答を別に表示します。全学習の集計と、診断ごとの結果を別に出します。診断回答を全学習の集計で二重には数えません。率の分母が0なら `null` です。

診断は支援なしの30問です。途中の答え・ヒント・正誤を表示しません。中断は未採点で保存し、終了すると正解・不正解・未回答、分野別件数、解説を見られます。途中終了は部分結果です。結果を見た診断は続行せず、復習は新しい通常演習の試行に記録します。

相談用Exportにメール・UID・問題本文・個人メモを含めません。アプリからAIへ自動送信もしません。

## 保存・バックアップ・同期

利用者×資格単位でIndexedDBへ保存します。通常演習の試行と、受験日・計画・診断の文書は別の保存／同期処理です。診断の問題一覧・版・教材は固定し、確定回答は追記、終了後は変更しません。採点結果を診断から導出するため、試行と診断を二重送信・二重計上しません。

「表示・データ」の学習記録書き出しには通常演習と `workspaceBackup`（受験日・計画・診断）が入ります。読み込み時は通常演習を置き換え、計画・診断は追加します。既存の計画・診断は保持し、同じIDで異なる診断は拒否します。元データが壊れている場合の書き出しは、その元データを保ちます。診断だけの書き出し・取り込みも診断一覧から行えます。

Googleログイン時の新機能の同期には、追加のFirestore Rulesが必要です。[設定手順](firebase-setup.md#planning-rules)。通常演習の同期は従来のままです。計画の競合は双方をプレビューして選びます。診断の確定回答は上書きせず、この端末の診断を別の回として保存するか、クラウドの診断を使います。
