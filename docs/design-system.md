# ひと問の共通デザインルール

基準：2026-10-25の科目A公開版（`570d09d`）。ユーザーが調整してきた実画面・CSSと確定済みの設計を共通の基準にする。過去のモックは経緯の資料であり、現在の画面や最新の指示と異なる部分を復活させない。

## コンセプト

**読み、考え、次の一歩へ進むための静かな画面。** 開いたら始められ、中断しても戻れ、操作の説明を読まずに役割が分かることを優先する。

- 問題文・図・入力を主役にする。カード、色、見出し、補足を増やすことを改善とみなさない。
- 通常学習の開始／再開を最上段に置く。設定、計画、記録、出典は主操作に割り込ませない。
- 確定済みの入力と採点、自己評価、解説の開示条件をデザイン変更で変えない。
- 誤答、ヒント、中断を罰や失敗の演出にしない。自己評価を公式得点や合格判定に置き換えない。

## 色の意味

色は既存のCSS変数と状態クラスを使う。資格や問題形式のための別パレットは作らない。

| 用途 | 現行値／部品 | ルール |
| --- | --- | --- |
| 画面の地 | `--bg: #f4f6fa` | 薄い無彩色寄りの背景。装飾やグラデーションを足さない |
| 読む面・入力面 | `--white: #fff`、`.panel` | 白い面と細い境界。装飾目的の枠を入れ子に増やさない。淡色の解答結果枠は科目Aの部品を使う |
| 見出し・本文 | `--navy: #142d4e`／`--text: #233750` | 本文に十分な濃さを保つ |
| 補助情報 | `--muted: #586b81` | 時期、分野、件数など。薄色で必須の条件を隠さない |
| 境界 | `--line: #dae2ec` | 区切りに使い、文字・ボタンに重ねない |
| 回答・次へ | `--accent: #087d79`、`.button.primary` | 白い画面上で進行・確定する操作。各独立した回答欄／操作群の主操作を1つに絞る |
| 開始カード | `.hero-start` | 紺の面。**主ボタンは白＋紺文字**。補助は `#203d61` の面＋白文字、`#657c95` の枠。緑の主ボタンをこの中へ直接置かない |
| 中断・ホーム | `.study-back-button` | 面 `#e8eef7`・枠 `#a8b9cd`・紺文字と停止／ホームのアイコン。学習画面の左上に置く |
| 選択中 | `.choice.selected` | 面 `#f1faf8` と緑の枠。文字やネイティブ入力のチェック状態も残す |
| 支援 | `--pale: #e9f5f3` | ヒント等の淡い緑。解答の正誤を示す色と文言を混同しない |
| 解答結果の面 | `.result` | 面 `#f7fbfa`・枠 `#c4ddd9`。科目Aの結果表示と同じ余白・角丸を使う |
| 正解の肢 | `.correct-choice` | 面 `#edf8f4` と緑の枠。開示可能になった後だけ表示 |
| 誤答の肢 | `.wrong-choice` | 面 `#fff3f4`・枠 `#c5737d`。誤答の文言も表示 |
| 注意 | `--amber: #835313`／`--amber-bg: #fff4df` | 判断に必要な注意だけに使い、通常の補助説明を警告色にしない |

`.primary` は常に同じ塗り色ではない。**白い内容面では緑、紺の開始カードでは白**という科目Aの文脈を守る。開始は `studyEntryButton`、中断は `studyBackButton`、AI質問は `aiQuestionButton` を使用する。共有実装は `src/ui/study-controls.js`。

## 操作と配置

- ヘッダの資格・科目選択と、学習／分野／記録のナビは共通。画面内に別の資格切替を足さない。
- ホームは `.home-core`、`.hero-start`、`.entry-list`。主操作と補助操作は同じ行型の形・余白・右矢印で揃える。
- 設定がなくても開始できる。実技の解答確認タイミングなどは「学習の設定」に畳み、毎回の開始条件にしない。
- 分野・試験回の選択は白い行／カードと右矢印。各行を緑の主ボタンで埋め尽くさない。
- 問題画面は上に中断と現在地、その下に分野・試験回などの短いメタ情報、本文・図・回答を置く。出版社・加工説明は出典の詳細へ。
- 終了・中断は左、次へ進む主操作は右。小画面で折り返す場合もDOMの順序を逆にしない。自動で次問へ進まない。
- 「今日N回」や記録タブと重複するボタンをホーム下へ足さない。オフライン保存は控えめな単独操作にする。

## 形・余白・文字

- `.panel`、`.button`、`.study-toolbar`、`.question-meta`、`.choice`、`.answer-actions`、`.finish-actions` を再利用する。既存の角丸・枠・レスポンシブ余白に従い、形式別に似た部品を作り直さない。
- 新しい固定幅でPCを細くしたり、スマホで左右にはみ出させたりしない。親は `minmax(0,1fr)`、子は必要に応じ `min-width:0`。
- 文字の役割は、ページ見出し→設問／回答欄の見出し→学習本文→メタ情報。大きな題名を重複して置かない。
- 学習本文・選択肢・解説は科目Aと同じ `--study-text-scale` と `--study-device-scale` を使う。操作ラベルやナビまで問題文と一緒に拡大しない。
- 記述・数値の編集欄は共通フォームに合わせる。スマホの入力文字は最低16pxとし、読み物の縮小率を入力操作に強制しない。これは科目Aの非入力型問題を複数欄へ拡張する際の補完ルール。
- 問題文・図・数式・表の強調を保持する。装飾目的の太字は増やさず、解説の太字は [既存ルール](explanation-presentation-spec.md)に従う。

## 回答と解説

- 選択肢はコードと本文を別要素にし、行全体で選択する。ラジオ／チェックの丸は視覚的に隠しても、ネイティブ入力とキーボード操作を残す。
- 選択しただけでは確定しない。「回答する」で確定する。入力が空なら確定を無効にし、「分からない」は別の操作として扱う。
- 選択・正解・誤答・フォーカスの状態を共通クラスで表す。色だけで伝えず、ラベル・正誤の文言・支援技術向け表示を付ける。
- 正答→解説→必要なら確認ポイント・各肢理由→AI質問。正解時の長い詳細は畳み、誤答や自己評価に必要な内容は開く。
- 自動判定と自己評価は明記する。複数欄の結果を、根拠のない点数・正答率にまとめない。
- 最後に解答を確認する設定では、開示可能になるまで正答・解説・正誤の色も出さない。

## 共通本文と複数小問

- PCは本文と設問の2列を使い、本文の参照位置を保つ。スマホは「問題文／設問・回答」の明確な切替とする。
- 小問ナビは現在の小問を淡い青と `aria-current` で示す。1小問しかない場合はナビを出さない。
- 本文の参照先はテキストノードや図の要素へ付ける。生成済みHTML全体の文字列置換で、画像の `alt`・リンク先などの属性を書き換えない。
- 複数回答欄は細い区切りでまとめる。欄ごとにカードを重ねたり、出典と注意を繰り返したりしない。
- 回答・採点・解説の開示は既存の欄単位を維持する。小問・大問の移動でも入力とスクロールを保持する。
- 大問全体の回答・評価が終わったら、終了を左、次の問題／大問を右に置く。分野・試験回・順序は引き継ぐ。

## 文言とアクセシビリティ

- 日常画面は結果と操作名で伝える。同期、内部形式、制作進捗、利用場面の説明を繰り返さない。エラー・競合・答えを含むヒントなど、判断に必要な情報は残す。
- 触れる領域は44px以上、フォーカスは枠で視認可能にする。`label`、`legend`、`aria-pressed`、`aria-current` を失わない。
- 320／390／1440px、文字設定の変更、キーボードで検証する。長い表は内容領域でスクロールし、画面全体を横スクロールさせない。

## 根拠と確認

- 科目Aの現行ホーム／問題／解説：[実装](../src/ui/views.js)、[CSS](../styles.css)。開始カードの色と行型、左上の中断、選択行、確定、終了・次問を実画面で確認。
- 学習の中心と保存：[learning-design.md](learning-design.md)。古い将来案は現行仕様より優先しない。
- 補足表示の削減：[ui-copy-implementation.md](ui-copy-implementation.md)。利用者が削除した説明を別形式で戻さない。
- 学習対象の境界：[learning-target-navigation-plan.md](learning-target-navigation-plan.md)。科目の記録と件数を混ぜない。
- 開始の配置：[study-entry-design.html](study-entry-design.html)。現行画面と一致する紺・白・行型の意図を参照する。

新しい画面では、科目Aの既存部品を選ぶ→状態と役割を確認する→必要な差分だけ足す→科目Aと新画面を比較する。仕様書と見た目だけで完了にせず、保存・再開・開示・オフラインも確認する。
