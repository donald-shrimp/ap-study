# 応用情報学習アプリ：要件定義 v0.10

更新日：2026-10-06／状態：2021〜2025年の午前800問で演習できる開発版。

読みやすい説明版： [HTML定義書](requirements.html)（要点・1章ずつの表示・試せるヒント例）。

## 今回のモックで試せる範囲

1・3・5問の直接開始、手元の教科書から分野別に演習、任意の読書範囲メモ、取り組みと前回からの進歩の表示、段階ヒント、解説、正誤とヒント履歴、中断再開、解き直し、復習目安、学習記録の書き出し・読み込み、自作教材の編集を実装した。教材はIPA公式の2021〜2025年春・秋の午前800問。個別ヒントは全800問に3段階。2022〜2025年の春秋640問の解説・4選択肢の理由を追加済み。全体の詳しい個別解説は642問で、残り158問は個別解説未追加と明示し、解答後に分野の復習メモを表示する。年度・期・分野・キーワード・個別解説の有無で検索し、20問ずつ表示する。新規問題は原本画像と拡大表示を使い、読み取りテキストは検索に限定する。端末内保存で、サーバーとログインは使わない。PWAとしてホーム画面へ追加でき、一度開いた問題をオフラインで再開・解き直しできる。中断は枠・背景・一時停止アイコンのあるボタンとして表示する。

以下は目標仕様を含む。大量収集の取り込み画面、復習日の手動変更、端末間同期は今回のモックには含まない。問題の追加はJSONファイルで行う。教材の出典と改変箇所は [SOURCES.md](SOURCES.md) に記載する。

### PWAと中断の操作

- インストール可能なブラウザでは「表示・データ」に追加操作を用意し、iOSではSafariの共有メニューを案内する。開始画面へインストール案内を常設しない。
- アプリ・問題データ・開いた画像を保存し、オフラインの新規出題は読める問題を選ぶ。未保存画像の問題を直接開く場合は理由を伝え、既存の回答・ヒント記録を保つ。
- オンラインでは最新の公開教材を取得する。アプリ更新による再読み込みは学習者が操作し、学習中に強制しない。教材のキャッシュと学習記録の保存は分ける。
- 中断ボタンは44px以上の押せる領域と枠・淡い背景・一時停止アイコンを持ち、文字だけのリンクに見せない。キーボードと拡大表示でも操作できる。

### 追加した学習の流れ

教科書は利用者が別に持っているものを使う。アプリに教科書本文を作らず、「手元の教科書を読む → 読んだ分野だけの過去問を解く」を支える。章やページのメモは任意。演習中、次の問題・中断再開・一巡後の解き直しでも分野を維持する。

ホームの1・3・5問は、押したらすぐ開始する独立したボタンとし、問数の選択と開始を1操作にする。分野別演習は収録数に合わせたボタンを表示し、問題が足りない分を別分野で埋めない。

モチベーションのため、今日1問の達成、直近7日間の取り組み、小さな達成、前回の不正解から自力正解になった変化・ヒントが減った変化を表示する。実際の記録から計算し、取り組みと正誤は区別する。学習が空いた日のペナルティは設けない。

### 画面の表示方針

ブランド名「ひと問」と、ホームの「今日は、どれくらいやろう？」の開始カードには個性を残す。その他の画面は、機能名・操作・学習記録を中心にし、キャッチコピーや英語の装飾ラベルを省く。モチベーションの表示は「今日の解答数」「ヒント数の変化」などの事実で伝え、学習日や達成の詳細は折りたたむ。問題画面では問題文と選択肢を優先する。

## 1. 目的

2026年中の受験に向け、応用情報の過去問を収集・整理し、段階的なヒントと解説を加えて効率的に学習するためのツールを作る。制度変更への対応や年度別シラバスの比較は対象に含めない。

集中が続かない日にも1問から学習を始められ、中断から戻れ、助けを使って理解した内容を後日自力で解けるようにする。

中核となる記録は「正誤」と「どこまでヒントを見たか」。正解でもヒントを見た問題は復習候補に残す。ヒントを使うことを失敗扱いせず、学習支援と自力で解ける度合いを区別する。

根拠と不確実性は [調査メモ](research-notes.md)、画面と教材への対応は [学習体験の設計案](learning-design.md) に記載。具体的なヒント数・時間・復習間隔は実証済みの最適値ではなく初期案。

### 開発中の変更方針

このアプリは開発中であり、仕様・画面・データ構造は大幅に変更できる。後方互換性は要件に含めず、旧仕様への対応、互換レイヤー、旧データの移行処理を必須にしない。学習体験の改善と実装の簡潔さを優先する。

以下の履歴保持・中断再開・エクスポート／インポートは、同じ仕様内での通常利用についての要件。仕様変更をまたぐデータ互換性は保証しない。問題の版管理も学習履歴を解釈するためのもので、旧アプリ仕様の維持を目的としない。

## 2. 利用者と初期版の範囲

- 対象：応用情報技術者試験の学習者。着手、長文の読解、中断からの再開、復習管理に負担を感じる人。
- 暫定前提：まず1人が使う学習アプリ。スマホとPCの両方で操作できる。主な端末と複数人への提供範囲は未確認。
- 開発版：選択式の午前800問を収録。解説・4選択肢の理由・ヒントを1問のセットで作り、10問ずつ原本・内容を照合して教材を増やす。
- 教材は収集した過去問を中心にする。年度・問題番号は出典と検索のための情報として保持する。
- 最優先は過去問の収集、ヒント・解説の追加、演習、履歴保存、解き直し。試験制度への追従や合格予測のための仕組みは設けない。

## 3. 基本の学習フロー

ホーム → 「まず1問」または「続きから」 → 問題 → 必要ならヒント → 回答 → 解説 → 「終える／次の1問」

1. ホームでは主要ボタンを1つに絞る。未完了があれば「続きから」、なければ「まず1問」を優先する。
2. 問題画面は1問ずつ表示。問題文、必要な図表、選択肢、ヒント入口を置く。
3. 選択肢の選択だけでは回答を確定しない。「回答する」で採点する。
4. ヒントは必要なときだけ1段ずつ表示する。答えを試す前にヒントを読むことも許可する。
5. 回答後は正誤と、理解に必要な短い解説を最初に表示する。詳細解説は展開できる。
6. 1問完了を学習単位にする。終了ボタンを常に用意し、次へ進むことを強制しない。
7. 終了時は取り組んだ件数と次回の入口を示す。長い振り返り入力は求めない。

困った場合は「解法を読む」「あとで」を選べる。知らない概念には短い基礎説明や解法例を用意する。中断した問題があっても別の問題から開始でき、自動で次の問題へ進まない。

## 4. 必須機能

| ID | 要件 | 期待する動作 |
|---|---|---|
| F01 | 問題と選択肢 | 問題文、図表、選択肢、出典、分野を保持。図表を欠落させず表示 |
| F02 | 段階的なヒント | 3段階を基本形とし、教材に合わせて数を変更可能。1段ずつ開き、前のヒントを読み返せる |
| F03 | 回答と解説 | 回答後に正誤、正答、解く手順、各選択肢が正しい／誤りである理由を表示 |
| F04 | 解答履歴 | 試行ごとに回答、正誤、ヒント到達段階、解答前の解答閲覧、日時を保存 |
| F05 | 中断・再開 | 選択中の回答、開いたヒント、問題内の位置を保存。再開時に内容を復元 |
| F06 | 解き直し | 不正解、ヒント付き正解、自信の低い正解を復習候補にする。手動で問題を選んで復習も可能 |
| F07 | 復習予定 | 学習状況から次の候補日を提案。ユーザーが延期・変更できる |
| F08 | 学習状況 | 「自力正解」「ヒント付き正解」「要復習」「未回答」を区別して見られる |
| F09 | 短い学習単位 | 1問を標準にし、希望すれば3問・5問の単位も選べる |
| F10 | データ管理 | 記録のエクスポート、インポート、削除を用意。保存先と消失し得る条件を説明 |
| F11 | 概念と関連問題 | 問題に学習する概念と関連問題を対応づける。少数の重要概念では別問題での確認も試す |
| F12 | 基礎説明・解法例 | 苦戦している概念の短い説明や例へ進める。閲覧は自力解答と区別して記録 |
| F13 | 過去問の収集・教材化 | 過去問と公式解答を取り込み、年度・問題番号で対応づける。図表を保持し、ヒント・解説を追加・編集できる |

### ヒントの作り方

- H1「何に注目するか」：問われている概念、重要な条件、図表の見る場所。
- H2「どう進めるか」：使う式、比較の手順、選択肢を検討する観点。
- H3「この問題に当てはめる」：途中計算や条件への具体的な適用。正答をそのまま示す内容は解答として扱う。

例：転送時間の計算なら、H1でデータ量と転送速度の単位、H2で単位をそろえて量÷速度、H3で数値を代入するところまで示す。

ヒントは短い段落に分け、必要な式・図を含める。「次に何をすればよいか」が分かる文にする。順序を固定するのは初期案で、最適性は利用で確かめる。

実装では全800問に3段階の個別ヒントを用意する。問題IDごとに内容を割り当て、計算式・表の行・図の位置などを具体的に示す。同じ概念と解法の反復問題では内容を共有できる。詳しい個別解説の有無は別の状態として表示する。

教材化は1問ずつ「解説 → 4選択肢の理由 → 3段階ヒント → 内容確認」の順で行う。原本画像の条件・図を確認し、式を使う理由、具体的な代入や最初の操作、4択それぞれの理由を記す。2022〜2025年春秋640問は `data/lessons/` の各回JSONで解説とヒントを一緒に管理し、再生成では既存のヒント割当てより優先する。2025年秋・2024年春秋の240問と、2023年春秋の160問、2022年春秋の160問は、作成担当と別の確認担当が原本から解き直して修正・再確認した。2023年・2022年の追加はgpt-6.1-solの同時稼働を最大2担当とし、作成2担当の終了後に別の確認2担当を動かした。`data/lesson-reviews/` に問題ごとの独立解答・指摘履歴・確認済み教材のSHA-256を保存する。

ヒント前の強制待ち時間や利用回数制限を設けない。教材には、どの支援で正答が実質的に明かされるかを設定する。段階番号だけから異なる問題の支援の強さを同一視しない。

### 回答・解説の扱い

- 「解答を見る」を常に選べる。回答せずに見た場合は「解答閲覧」と記録し、正解数に含めない。
- 回答前に正答を見た試行は、その後正しい選択肢を選んでも自力正解にしない。
- 通常の回答後に解説を読んでも、その試行の正誤や回答時点のヒント記録は変えない。
- 回答後のヒント閲覧は、回答前のヒント利用とは別に記録する。
- 「自信がある／迷った」の入力は回答前の任意の操作。入力しなくても次に進める。
- 解説は結論、判断手順、選んだ誤答の理由、次に使える手がかりを要点として示す。他の選択肢や詳細な説明は展開できる。
- ミスの理由は任意で「知識」「読み取り」「計算」「その他」を選べる。操作を増やすため、初期版では優先度を下げる。

## 5. 学習記録と状態の定義

### 保存するデータ

| 対象 | 主な項目 |
|---|---|
| 問題 | ID、版、出典、出題区分、年度・問題番号、分野、概念ID・関連問題、問題文、図表、選択肢、正答、ヒントと正答開示の設定、解説、教材の確認状態 |
| 試行 | 試行ID、問題ID・版、開始・更新・確定日時、回答、正誤、状態、回答前に見たヒントの段階と履歴、解答閲覧の時点、任意の自信 |
| 中断位置 | 試行ID、選択中の回答、表示中のヒント、スクロール位置、最後の更新日時 |
| 問題ごとの集約 | 最後の結果、後日の自力正解履歴、復習候補日、手動延期、任意のお気に入り |
| 設定 | 学習単位、タイマー表示、文字サイズ、復習間隔など |

問題の改訂後も過去の試行が何を解いたものか分かるように版を保存する。回答履歴を最新結果で上書きしない。診断名・服薬などの医療情報は機能に必要ないため収集しない。

### 状態の意味

| 状態 | 判定 | 復習への扱い |
|---|---|---|
| 未着手 | 試行がない | 新規問題の候補 |
| 途中 | 問題を開始し、回答を確定していない | 再開を優先。誤答として扱わない |
| あとで | 回答を確定せずに本人が保留した | 内容を保存し、任意に再開。誤答や解答閲覧にしない |
| 不正解 | 確定した回答が誤り | 復習候補 |
| ヒント付き正解 | 正答だが回答前にヒントを見た | 復習候補。使用した段階を表示 |
| 自力正解 | 回答前にヒントも正答も見ずに正答 | 間隔をあけた確認へ。1回で習熟と断定しない |
| 解答閲覧 | 回答前に正答を見た | 理解の学習として記録し、復習候補 |

「自力」はこのアプリ内の操作についての意味。外部の資料利用までは検知できない。任意の「迷った」は自力正解でも短めの復習候補にできる。

進捗は「別の日に自力正解：2回」のように観察した事実を表示する。同じ日の連続正解はこの回数に含めない。回数だけで習熟・合格を断定しない。同じ問題と関連する別問題の結果も分ける。

## 6. 復習の初期ルール

複雑な推定モデルを最初から導入せず、説明できるルールで開始する。

1. 不正解・解答閲覧・ヒント付き正解は、原則翌日以降に再出題する。
2. 後日自力正解できた問題は、次の間隔を3日、7日、14日のように伸ばす案とする。
3. 再び間違えたら短い間隔に戻す。自信の低い正解も早めの確認候補にする。
4. 当日の解き直しは任意でできるが、長期の定着を確認した回数には含めない。
5. 優先順は「中断した問題→予定日を過ぎた復習→今日の復習→新規問題」。同順位では古い候補を優先する。
6. 復習が多くたまっていても、今日表示する単位は1・3・5問に収める。全件を今日のノルマとして押しつけない。
7. 復習では前回の正答や解説を初めから表示しない。ヒントも閉じて開始し、必要になったときに開く。
8. 苦戦が続く概念には再出題に加えて基礎説明・解法例を提案する。同日の同じ問題の出題が続かないようにする。
9. 中断した問題は再開を提案するが、別の問題から始める選択肢も残す。

日数は科学的な最適値として扱わない。本人の負荷と後日の自力正解を見て調整する。分野の新規学習へ進む入口も設け、復習だけが続く状態を回避する。

同一問題の正答記憶と理解を分けるため、初期版でも少数の重要概念で別の過去問への適用を試す。新規学習は概念ごとのまとまりを持たせ、理解後に似た概念との使い分けを練習する。

## 7. 集中が切れやすい人への画面要件

- 1画面の主要な操作を絞り、ホームに大量の設定や成績を並べない。
- 問題画面の「中断」「ホーム」は、枠・背景・アイコンを持つ押しやすいボタンにする。
- 回答後の「あなたの回答」「正解」は選択肢の下へまとめる。4択の狭い枠へ長い状態ラベルを入れず、スマホと文字拡大でも配置を保つ。
- カウントダウンは標準で非表示。希望者には5分・10分・自由設定の目安を用意する案。
- 時間切れで回答を強制したり、問題を閉じたりしない。いつでも休憩・終了できる。
- 説明は短い段落と見出しで区切る。問題文の条件や必要な図表は隠して欠落させない。
- ヒントを開いても問題文と選択中の回答を見失わない。スマホでは必要に応じて元の位置へ戻れる。
- 再開時は問題の主題、ヒントの利用、回答の確定状態を短く示す。
- 連続日数を失うペナルティ、ランキング、派手な演出は初期版の必須機能にしない。
- フィードバックは「ヒントを使って解けた」「前回より少ない助けで解けた」など、行動を具体的に示す。
- 色だけで正誤を伝えない。キーボード、読み上げ、文字拡大に対応し、図表にも代替説明を付ける。

## 8. 初期版の保存方式

自分用を前提とする暫定案では、アカウントなし・端末内保存から始める。履歴の更新はトランザクション単位で行い、確定ボタンの連打で試行を重複作成しない。保存失敗を画面に表示し、失敗したまま「保存済み」と見せない。

端末内保存はブラウザのデータ削除、プライベートモード、端末紛失で失われ得る。書き出し・読み込みを用意し、書き出しの日時を表示する。複数端末で使いたい場合は、実装前にログインと同期の優先度を上げる。

技術スタックや公開先は、この要件段階では決定しない。

## 9. 初期版に含めないもの

- 記述式の自動採点、試験全体の模試モード。
- 実行時のAIによる未確認ヒント・解説の自動配信。
- SNS、ランキング、複雑な報酬制度。
- 診断・症状評価、医療情報の収集。
- 複数端末同期と通知は、自分用という前提で優先度を保留。利用者の希望で見直す。

## 10. 過去問の収集と教材化

- IPAの問題・公式解答を基準に、対象年度、問題番号、分野を記録する。
- 収集→問題文・選択肢・図表の抽出→公式解答との照合→ヒント・解説の追加→内容確認→演習用セットへの登録、の順で教材化する。
- 重複は年度・出題区分・問題番号で判別する。抽出が難しい図表は原資料の画像を保持し、本文の欠落や誤変換を確認する。
- 第三者サイトの解説をそのまま移さず、独自のヒント・解説を追加する。外部に公開する場合は転載・加工・図表の利用条件を確認する。
- 独自のヒント・解説も、正答との一致、計算、単位、用語、各選択肢の理由をレビューする。
- 教材の確認状態を持ち、未確認の内容を通常の学習セットに混ぜない。
- AIを下書きに使う場合も、確認工程と出典を必要とする。

## 11. 受け入れ条件

1. 正答を選んでヒント2まで使った試行は「ヒント付き正解・段階2」として保存され、復習候補になる。
2. 回答前に正答を見た試行は、後から正答を選んでも自力正解として集計されない。
3. 回答後に解説を読んでも、回答時のヒント利用段階は変更されない。
4. 途中で画面を閉じて再開すると、同じ試行の選択中の回答と開いたヒントを復元できる。
5. 不正解後の再挑戦は新しい試行として保存され、前の回答履歴が残る。
6. 別の日の自力正解回数に、同じ日の連続正解を含めず、回数だけで習熟を断定しない。
7. 復習画面は正答を伏せ、ヒントを閉じた状態で開始する。
8. 1問で終了でき、タイマーを使わず全ての基本機能を操作できる。
9. 保存失敗が表示され、エクスポートした記録を読み戻して履歴を復元できる。
10. スマホ、キーボード、文字拡大で問題・ヒント・回答・再開が操作できる。
11. 「あとで」は誤答として扱われず、別の問題へ進める。保存した内容は再開できる。
12. ヒントを開くために待つ必要がなく、正答を実質的に明かす支援は自力正解に含まれない。
13. 関連する別問題の結果が、同じ問題への再回答と区別して記録される。
14. 取り込んだ過去問に公式解答、図表、出典が対応づき、ヒント・解説を追加・編集できる。

## 12. 初期検証と判断点

最初は小さな教材セットで1〜2週間使い、次を確かめる。ADHDへの治療効果の評価ではなく、学習体験の改善を目的とする。

- 着手：ホームから問題に入るまでの操作が分かるか。1問だけでも始められるか。
- 再開：中断後、状況を把握して無理なく続けられるか。
- 学習：別の日に助けなしで解ける問題が増えるか。問題ごとに見て難度の変化を混ぜない。
- 負担：ヒントや保存が便利か、入力・通知・復習量が負担になっていないか。

1〜2週間の初期検証は操作・着手・再開を中心とする。保持と応用は数週間の利用で一定期間後の初回試行と関連する未見問題を確認する。正解率には対象総数・回答数・未実施数を併記し、支援付き正解や同日の反復を分ける。小規模な個人利用から一般的な効果や因果関係を断定しない。

確認済みの前提：2026年中に受験する。過去問を収集して学習するためのツールを作り、制度変更は扱わない。

未確認の点：主な端末、端末間同期の必要性、最も困る学習場面、現在の理解度、利用者の範囲。現時点では自分用・選択式問題から開始する案とする。外部資料の確認範囲は調査メモに記載した。今後は教材の収集・品質と実際の学習体験を中心に検証する。
