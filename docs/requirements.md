# 応用情報学習アプリ：要件定義 v0.14

更新日：2026-10-08／状態：2021〜2025年の午前800問で演習できる開発版。

読みやすい説明版： [HTML定義書](requirements.html)（要点・1章ずつの表示・試せるヒント例）。

## 今回のモックで試せる範囲

1操作で通常学習を開始、手元の教科書から分野別に演習、任意の読書範囲メモ、取り組みと前回からの進歩の表示、段階ヒント、解説、正誤とヒント履歴、中断再開、解き直し、復習目安、学習記録の書き出し・読み込み、自作教材の編集を実装した。教材はIPA公式の2021〜2025年春・秋の午前800問。個別ヒントは全800問に3段階。2021〜2025年春秋の全800問に、原本を確認した独自の解答解説・4選択肢の理由・具体的な3段階ヒントを追加済み。2021年秋の残る78問を完成し、既存722問の教材本文を保持した。2021年秋問3・4は第2段の正答開示設定だけを訂正した。年度・期・分野・キーワード・個別解説の有無で検索し、20問ずつ表示する。新規問題は原本画像と拡大表示を使い、読み取りテキストは検索に限定する。資格別教材と共通画面を分離し、利用者・資格別のIndexedDBへ端末内保存する。Googleログインと資格別のFirebase同期コードを実装。本番アクセスルールの配備と実機認証は未確認。PWAとしてホーム画面へ追加でき、一度開いた問題をオフラインで再開・解き直しできる。中断は枠・背景・一時停止アイコンのあるボタンとして表示する。

以下は目標仕様を含む。大量収集の取り込み画面、復習日の手動変更は今回の実装には含まない。問題の追加はJSONファイルで行う。教材の出典と改変箇所は [SOURCES.md](SOURCES.md) に記載する。

### PWAと中断の操作

- インストール可能なブラウザでは「表示・データ」に追加操作を用意し、iOSではSafariの共有メニューを案内する。開始画面へインストール案内を常設しない。
- アプリ・問題データ・開いた画像を保存し、オフラインの新規出題は読める問題を選ぶ。未保存画像の問題を直接開く場合は理由を伝え、既存の回答・ヒント記録を保つ。
- オンラインでは最新の公開教材を取得する。アプリ更新による再読み込みは学習者が操作し、学習中に強制しない。教材のキャッシュと学習記録の保存は分ける。
- 中断ボタンは44px以上の押せる領域と枠・淡い背景・一時停止アイコンを持ち、文字だけのリンクに見せない。キーボードと拡大表示でも操作できる。

### 追加した学習の流れ

教科書は利用者が別に持っているものを使う。アプリに教科書本文を作らず、「手元の教科書を読む → 読んだ分野だけの過去問を解く」を支える。章やページのメモは任意。演習中、次の問題・中断再開・一巡後の解き直しでも分野を維持する。

ホームは「身軽に1問」「書いて考える1問」「おまかせで1問」から直接開始する。問数の指定と事前のモード切替は不要。分野別演習は収録数に合わせたボタンを表示し、問題が足りない分を別分野で埋めない。

モチベーションのため、今日1問の達成、直近7日間の取り組み、小さな達成、前回の不正解から自力正解になった変化・ヒントが減った変化を表示する。実際の記録から計算し、取り組みと正誤は区別する。学習が空いた日のペナルティは設けない。

### 画面の表示方針

ブランド名「ひと問」と、ホームの3つの入口には個性を残す。その他の画面は、機能名・操作・学習記録を中心にし、キャッチコピーや英語の装飾ラベルを省く。モチベーションの表示は「今日の解答数」「ヒント数の変化」などの事実で伝え、学習日や達成の詳細は折りたたむ。問題画面では問題文と選択肢を優先する。

## 1. 目的

2026年中の受験に向け、応用情報の過去問を収集・整理し、段階的なヒントと解説を加えて効率的に学習するためのツールを作る。制度変更への対応や年度別シラバスの比較は対象に含めない。

集中が続かない日にも1問から学習を始められ、中断から戻れ、助けを使って理解した内容を後日自力で解けるようにする。

中核となる記録は「正誤」と「どこまでヒントを見たか」。正解でもヒントを見た問題は復習候補に残す。ヒントを使うことを失敗扱いせず、学習支援と自力で解ける度合いを区別する。

根拠と不確実性は [調査メモ](research-notes.md)、画面と教材への対応は [学習体験の設計案](learning-design.md) に記載。具体的なヒント数・時間・復習間隔は実証済みの最適値ではなく初期案。

### 開発中の変更方針

このアプリは開発中であり、仕様・画面・データ構造は大幅に変更できる。後方互換性は要件に含めず、旧仕様への対応、互換レイヤー、旧データの移行処理を必須にしない。学習体験の改善と実装の簡潔さを優先する。

以下の履歴保持・中断再開・エクスポート／インポートは、同じ仕様内での通常利用についての要件。仕様変更をまたぐデータ互換性は保証しない。問題の版管理も学習履歴を解釈するためのもので、旧アプリ仕様の維持を目的としない。

## 2. 利用者と初期版の範囲

- 対象：応用情報技術者試験の学習者。着手、長文の読解、中断からの再開、復習管理に負担を感じる人。
- 暫定前提：まず1人が使う学習アプリ。スマホとPCの両方で操作できる。主な端末と複数人への提供範囲は未確認。
- 開発版：選択式の午前800問を収録。解説・4選択肢の理由・ヒントを1問のセットで作り、10問ずつ原本・内容を照合して教材を増やす。
- 教材は収集した過去問を中心にする。年度・問題番号は出典と検索のための情報として保持する。
- 最優先は過去問の収集、ヒント・解説の追加、演習、履歴保存、解き直し。試験制度への追従や合格予測のための仕組みは設けない。

## 3. 基本の学習フロー

ホーム → 3つの入口のいずれか（中断中は「続きから」） → 問題 → 必要ならヒント → 回答 → 解説 → 「終える／次の1問」

1. ホーム最上段に3つの開始入口を置き、前回の入口だけを強調する。それぞれの入口に未完了があれば、その同じボタンで「続きから」。細かな事前設定は置かない。
2. 問題画面は1問ずつ表示。問題文、必要な図表、選択肢、ヒント入口を置く。
3. 選択肢の選択だけでは回答を確定しない。「回答する」で採点する。
4. ヒントは必要なときだけ1段ずつ表示する。答えを試す前にヒントを読むことも許可する。
5. 回答後は正誤と、理解に必要な短い解説を最初に表示する。詳細解説は展開できる。
6. 1問完了を学習単位にする。終了ボタンを常に用意し、次へ進むことを強制しない。
7. 終了時は取り組んだ件数と次回の入口を示す。長い振り返り入力は求めない。

困った場合は「解法を読む」「あとで」を選べる。知らない概念には短い基礎説明や解法例を用意する。中断した問題があっても別の問題から開始でき、自動で次の問題へ進まない。

## 4. 必須機能

| ID | 要件 | 期待する動作 |
|---|---|---|
| F01 | 問題と選択肢 | 問題文、図表、選択肢、出典、分野を保持。図表を欠落させず表示 |
| F02 | 段階的なヒント | 3段階を基本形とし、教材に合わせて数を変更可能。1段ずつ開き、前のヒントを読み返せる |
| F03 | 回答と解説 | 回答後に正誤、正答、解く手順、各選択肢が正しい／誤りである理由を表示 |
| F04 | 解答履歴 | 試行ごとに回答、正誤、ヒント到達段階、解答前の解答閲覧、日時を保存 |
| F05 | 中断・再開 | 選択中の回答、開いたヒント、問題内の位置を保存。再開時に内容を復元 |
| F06 | 解き直し | 不正解、ヒント付き正解、自信の低い正解を復習候補にする。手動で問題を選んで復習も可能 |
| F07 | 復習予定 | 学習状況から次の候補日を提案。ユーザーが延期・変更できる |
| F08 | 学習状況 | 「自力正解」「ヒント付き正解」「要復習」「未回答」を区別して見られる |
| F09 | 短い学習単位 | 1操作で開始し、1問ずつ自由に続行・終了できる |
| F10 | データ管理 | 記録のエクスポート、インポート、削除を用意。保存先と消失し得る条件を説明 |
| F11 | 概念と関連問題 | 問題に学習する概念と関連問題を対応づける。少数の重要概念では別問題での確認も試す |
| F12 | 基礎説明・解法例 | 苦戦している概念の短い説明や例へ進める。閲覧は自力解答と区別して記録 |
| F13 | 過去問の収集・教材化 | 過去問と公式解答を取り込み、年度・問題番号で対応づける。図表を保持し、ヒント・解説を追加・編集できる |

### ヒントの作り方

- H1「何に注目するか」：問われている概念、重要な条件、図表の見る場所。
- H2「どう進めるか」：使う式、比較の手順、選択肢を検討する観点。
- H3「この問題に当てはめる」：途中計算や条件への具体的な適用。正答をそのまま示す内容は解答として扱う。

例：転送時間の計算なら、H1でデータ量と転送速度の単位、H2で単位をそろえて量÷速度、H3で数値を代入するところまで示す。

ヒントは短い段落に分け、必要な式・図を含める。「次に何をすればよいか」が分かる文にする。順序を固定するのは初期案で、最適性は利用で確かめる。

実装では全800問に3段階の個別ヒントを用意する。問題IDごとに内容を割り当て、計算式・表の行・図の位置などを具体的に示す。同じ概念と解法の反復問題では内容を共有できる。詳しい個別解説の有無は別の状態として表示する。

教材化は1問ずつ「解説 → 4選択肢の理由 → 3段階ヒント → 内容確認」の順で行う。原本画像の条件・図を確認し、式を使う理由、具体的な代入や最初の操作、4択それぞれの理由を記す。2022〜2025年春秋と2021年春の720問は `data/lessons/` の各回JSONで解説とヒントを一緒に管理し、再生成では既存のヒント割当てより優先する。2025年秋・2024年春秋の240問と、2023年春秋の160問、2022年春秋の160問、2021年春の80問は、作成担当と別の確認担当が原本から解き直して修正・再確認した。2023年・2022年・2021年春の追加はgpt-6.1-solの同時稼働を最大2担当とし、作成2担当の終了後に別の確認2担当を動かした。`data/lesson-reviews/` に問題ごとの独立解答・指摘履歴・確認済み教材のSHA-256を保存する。

ヒント前の強制待ち時間や利用回数制限を設けない。教材には、どの支援で正答が実質的に明かされるかを設定する。段階番号だけから異なる問題の支援の強さを同一視しない。

### 回答・解説の扱い

- 「解答を見る」を常に選べる。回答せずに見た場合は「解答閲覧」と記録し、正解数に含めない。
- 回答前に正答を見た試行は、その後正しい選択肢を選んでも自力正解にしない。
- 通常の回答後に解説を読んでも、その試行の正誤や回答時点のヒント記録は変えない。
- 回答後のヒント閲覧は、回答前のヒント利用とは別に記録する。
- 「自信がある／迷った」の入力は回答前の任意の操作。入力しなくても次に進める。
- 解説は結論、判断手順、選んだ誤答の理由、次に使える手がかりを要点として示す。他の選択肢や詳細な説明は展開できる。
- ミスの理由は任意で「知識」「読み取り」「計算」「その他」を選べる。操作を増やすため、初期版では優先度を下げる。

## 5. 学習記録と状態の定義

### 保存するデータ

| 対象 | 主な項目 |
|---|---|
| 問題 | ID、版、出典、出題区分、年度・問題番号、分野、概念ID・関連問題、問題文、図表、選択肢、正答、ヒントと正答開示の設定、解説、教材の確認状態 |
| 試行 | 試行ID、問題ID・版、開始・更新・確定日時、回答、正誤、状態、回答前に見たヒントの段階と履歴、解答閲覧の時点、任意の自信 |
| 中断位置 | 試行ID、選択中の回答、表示中のヒント、スクロール位置、最後の更新日時 |
| 問題ごとの集約 | 最後の結果、後日の自力正解履歴、復習候補日、手動延期、任意のお気に入り |
| 設定 | タイマー表示、文字サイズ、復習間隔など |

問題の改訂後も過去の試行が何を解いたものか分かるように版を保存する。回答履歴を最新結果で上書きしない。診断名・服薬などの医療情報は機能に必要ないため収集しない。

### 状態の意味

| 状態 | 判定 | 復習への扱い |
|---|---|---|
| 未着手 | 試行がない | 新規問題の候補 |
| 途中 | 問題を開始し、回答を確定していない | 再開を優先。誤答として扱わない |
| あとで | 回答を確定せずに本人が保留した | 内容を保存し、任意に再開。誤答や解答閲覧にしない |
| 不正解 | 確定した回答が誤り | 復習候補 |
| ヒント付き正解 | 正答だが回答前にヒントを見た | 復習候補。使用した段階を表示 |
| 自力正解 | 回答前にヒントも正答も見ずに正答 | 間隔をあけた確認へ。1回で習熟と断定しない |
| 解答閲覧 | 回答前に正答を見た | 理解の学習として記録し、復習候補 |

「自力」はこのアプリ内の操作についての意味。外部の資料利用までは検知できない。任意の「迷った」は自力正解でも短めの復習候補にできる。

進捗は「別の日に自力正解：2回」のように観察した事実を表示する。同じ日の連続正解はこの回数に含めない。回数だけで習熟・合格を断定しない。同じ問題と関連する別問題の結果も分ける。

## 6. 復習の初期ルール

複雑な推定モデルを最初から導入せず、説明できるルールで開始する。

1. 不正解・解答閲覧・ヒント付き正解は、原則翌日以降に再出題する。
2. 後日自力正解できた問題は、次の間隔を3日、7日、14日のように伸ばす案とする。
3. 再び間違えたら短い間隔に戻す。自信の低い正解も早めの確認候補にする。
4. 当日の解き直しは任意でできるが、長期の定着を確認した回数には含めない。
5. 優先順は「中断した問題→予定日を過ぎた復習→今日の復習→新規問題」。同順位では古い候補を優先する。
6. 復習が多くたまっていても、1問ずつ進み、いつでも終了できる。全件を今日のノルマとして押しつけない。
7. 復習では前回の正答や解説を初めから表示しない。ヒントも閉じて開始し、必要になったときに開く。
8. 苦戦が続く概念には再出題に加えて基礎説明・解法例を提案する。同日の同じ問題の出題が続かないようにする。
9. 中断した問題は再開を提案するが、別の問題から始める選択肢も残す。

日数は科学的な最適値として扱わない。本人の負荷と後日の自力正解を見て調整する。分野の新規学習へ進む入口も設け、復習だけが続く状態を回避する。

同一問題の正答記憶と理解を分けるため、初期版でも少数の重要概念で別の過去問への適用を試す。新規学習は概念ごとのまとまりを持たせ、理解後に似た概念との使い分けを練習する。

## 7. 集中が切れやすい人への画面要件

- 1画面の主要な操作を絞り、ホームに大量の設定や成績を並べない。
- 問題画面の「中断」「ホーム」は、枠・背景・アイコンを持つ押しやすいボタンにする。
- 回答後の「あなたの回答」「正解」は選択肢の下へまとめる。4択の狭い枠へ長い状態ラベルを入れず、スマホと文字拡大でも配置を保つ。
- カウントダウンは標準で非表示。希望者には5分・10分・自由設定の目安を用意する案。
- 時間切れで回答を強制したり、問題を閉じたりしない。いつでも休憩・終了できる。
- 説明は短い段落と見出しで区切る。問題文の条件や必要な図表は隠して欠落させない。
- ヒントを開いても問題文と選択中の回答を見失わない。スマホでは必要に応じて元の位置へ戻れる。
- 再開時は問題の主題、ヒントの利用、回答の確定状態を短く示す。
- 連続日数を失うペナルティ、ランキング、派手な演出は初期版の必須機能にしない。
- フィードバックは「ヒントを使って解けた」「前回より少ない助けで解けた」など、行動を具体的に示す。
- 色だけで正誤を伝えない。キーボード、読み上げ、文字拡大に対応し、図表にも代替説明を付ける。

## 8. 初期版の保存方式

自分用を前提とする暫定案では、アカウントなし・端末内保存から始める。履歴の更新はトランザクション単位で行い、確定ボタンの連打で試行を重複作成しない。保存失敗を画面に表示し、失敗したまま「保存済み」と見せない。

端末内保存はブラウザのデータ削除、プライベートモード、端末紛失で失われ得る。書き出し・読み込みを用意し、書き出しの日時を表示する。Googleログイン時は試行・ヒント・中断状態をFirebaseと同期する。認証なしの端末内保存とJSON書き出しも提供する。

現行実装はES modules、Pythonによる教材・入口生成、IndexedDBとCache Storage、GitHub Pagesを使用する。

## 9. 初期版に含めないもの

- 記述式の自動採点、試験全体の模試モード。
- 実行時のAIによる未確認ヒント・解説の自動配信。
- SNS、ランキング、複雑な報酬制度。
- 診断・症状評価、医療情報の収集。
- Googleログインと複数端末同期のコードを実装。本番ルール・実機確認は残る。通知は保留。

## 10. 過去問の収集と教材化

- IPAの問題・公式解答を基準に、対象年度、問題番号、分野を記録する。
- 収集→問題文・選択肢・図表の抽出→公式解答との照合→ヒント・解説の追加→内容確認→演習用セットへの登録、の順で教材化する。
- 重複は年度・出題区分・問題番号で判別する。抽出が難しい図表は原資料の画像を保持し、本文の欠落や誤変換を確認する。
- 第三者サイトの解説をそのまま移さず、独自のヒント・解説を追加する。外部に公開する場合は転載・加工・図表の利用条件を確認する。
- 独自のヒント・解説も、正答との一致、計算、単位、用語、各選択肢の理由をレビューする。
- 教材の確認状態を持ち、未確認の内容を通常の学習セットに混ぜない。
- AIを下書きに使う場合も、確認工程と出典を必要とする。

## 11. 受け入れ条件

1. 正答を選んでヒント2まで使った試行は「ヒント付き正解・段階2」として保存され、復習候補になる。
2. 回答前に正答を見た試行は、後から正答を選んでも自力正解として集計されない。
3. 回答後に解説を読んでも、回答時のヒント利用段階は変更されない。
4. 途中で画面を閉じて再開すると、同じ試行の選択中の回答と開いたヒントを復元できる。
5. 不正解後の再挑戦は新しい試行として保存され、前の回答履歴が残る。
6. 別の日の自力正解回数に、同じ日の連続正解を含めず、回数だけで習熟を断定しない。
7. 復習画面は正答を伏せ、ヒントを閉じた状態で開始する。
8. 1問で終了でき、タイマーを使わず全ての基本機能を操作できる。
9. 保存失敗が表示され、エクスポートした記録を読み戻して履歴を復元できる。
10. スマホ、キーボード、文字拡大で問題・ヒント・回答・再開が操作できる。
11. 「あとで」は誤答として扱われず、別の問題へ進める。保存した内容は再開できる。
12. ヒントを開くために待つ必要がなく、正答を実質的に明かす支援は自力正解に含まれない。
13. 関連する別問題の結果が、同じ問題への再回答と区別して記録される。
14. 取り込んだ過去問に公式解答、図表、出典が対応づき、ヒント・解説を追加・編集できる。

## 12. 初期検証と判断点

最初は小さな教材セットで1〜2週間使い、次を確かめる。ADHDへの治療効果の評価ではなく、学習体験の改善を目的とする。

- 着手：ホームから問題に入るまでの操作が分かるか。1問だけでも始められるか。
- 再開：中断後、状況を把握して無理なく続けられるか。
- 学習：別の日に助けなしで解ける問題が増えるか。問題ごとに見て難度の変化を混ぜない。
- 負担：ヒントや保存が便利か、入力・通知・復習量が負担になっていないか。

1〜2週間の初期検証は操作・着手・再開を中心とする。保持と応用は数週間の利用で一定期間後の初回試行と関連する未見問題を確認する。正解率には対象総数・回答数・未実施数を併記し、支援付き正解や同日の反復を分ける。小規模な個人利用から一般的な効果や因果関係を断定しない。

確認済みの前提：2026年中に受験する。過去問を収集して学習するためのツールを作り、制度変更は扱わない。

未確認の点：本番アクセスルールの配備と実機Google認証、次の資格とその教材出典、現在の理解度、利用者の範囲。Android Chrome・複数端末同期の希望は確認済み。現時点では自分用・選択式問題から開始する案とする。外部資料の確認範囲は調査メモに記載した。今後は教材の収集・品質と実際の学習体験を中心に検証する。

## 800問収録の実装範囲

## 複数資格へ向けた構造の実装範囲（2026-10-06）

共通の学習・復習・画面・教材取得・保存を分離。応用情報は `/ap-study/ap/` からも利用でき、共通ルートと同じ記録を使う。資格一覧に登録した設定から入口と教材パックを生成し、他資格の全教材を初回に取得しない。2択／5択・可変ヒント数・少数パック・同じ問題ID／分野名の資格を一時教材で検証した。第二資格の本番教材は未登録。

現在と同じversion 1形式の記録は検証後、内容を変えず初回だけコピーして元のlocalStorage値を残す。異なる旧形式の変換・互換機構はない。読めない元の値は上書きせず書き出し可能。保存失敗時も学習と書き出しを継続する。JSON読み込みは64MB以下。

Firebase認証・送受信・Rulesを実装し、Emulatorで検証する。本番Rulesの配備と実機Googleログインは未確認。[実装順と同期設計](architecture-plan.html)、[教材追加手順](content-authoring.md)を参照。

## Googleログインと同期（2026-10-06）

設定画面でGoogleログイン、ログアウト、任意の同期、ゲスト記録の明示的な取り込みを提供する。元のゲスト記録を残し、取り込みの再実行で重複させない。別UIDの表示・送信待ちは混在させない。クラウド削除とアカウント削除のUIは未実装で、ログイン中は端末記録の削除・置換インポートを表示しない。書き出しは可能。

試行の選択・ヒント・答え閲覧・結果・中断と記録時点の問題／教材を同期。読書メモ・個人教材編集・表示設定・スクロールは端末内に保持する（個人教材で解いた際のスナップショットは試行の一部として送信）。同期は通常最短15秒、表示中の差分確認は60秒間隔。100件単位でサーバー時刻＋文書IDのカーソルを使い、取込とカーソルを原子的に保存する。通信失敗・無料枠超過・権限不足では未送信を残す。900KB超の試行は送信せず表示する。

他端末の途中記録は継続UUIDに分けて再開し、同時回答を保持。確定結果と教材は不変、回答後のヒント追加だけを許可。アプリ起動は認証の初回通信を待たず、固定版SDKをPWAの静的資産として保存する。Googleログインはpopup方式で、実機Chrome/PWAの確認は必要。

### 診断専用派生問題と計画の前提（2026-10-07、追加基盤を実装）

- 初期版は既存過去問のみ。確認済みの派生問題を少しずつ追加し、分野ごとの出題枠内で優先する。不足は既存過去問で補い、分野ごとの供給量が充実したら派生割合を増やす。合計件数だけで切り替えず、初期上限は各分野1問。分野別上限は資格定義のvariantLimitsで0〜30を指定でき、配分変更時は出題方針の版を上げる。件数による自動切り替えはしない。
- 派生問題は診断専用の別問題集。通常学習・検索・通常復習の候補には混ぜない。診断結果から振り返り、通常学習へは元問題や分野で戻れるようにする。現行の「診断の誤答を通常復習へ」は既存過去問の扱い。
- 独立ID・版・元問題ID・分野・試験パート・確認記録を持つ。既存の教材を上書きしない。同一診断内で同じ元問題に属する問題を重ねて出さない。出題候補不足時の補完・開始可否を明示し、開始後の問題・版は固定する。
- 数値変更は計算・条件・丸め・図・正解の一意性・誤答理由まで独立に検証する。用語問題は問い方や場面も検討する。選択肢順の変更だけで理解の検証済みとは扱わない。未確認の問題を診断時に自動生成しない。
- 診断結果とExportに開始時の方針・上限を保存し、既存／派生の出題数・回答数・正解数、各問題の既出状況、元問題の既出状況、出題方針の版を含める。異なる構成の結果を同一難易度と見なさず、アプリ外の既視経験や合格可能性は推定しない。
- 計画の前提として学習済み範囲・教材・使える時間・休む予定・計画の理由を任意で編集・保存し、外部AIへ渡す内容を確認できるようにする。受験日・残日数・診断・学習実績・現在計画と一緒に出力し、新しい計画にも前提を引き継ぐ。公開v1の任意contextとして実装。各文章2000文字、週の時間0〜10080分、更新日を保存。importで省略した前提は引き継ぎ、{}は明示クリア。内容確認・Schema・プレビュー・バックアップ・利用者×資格の保存と同期対象へ反映。今回のcontext対応Rulesは、2026-10-07に利用者が公開を報告済み。新しい項目の本番同期表示と別端末復元は未確認。
- アプリ内の自動調整提案は保留。診断と事実・前提のExportを先に充実させ、外部AIへの相談、検証・プレビュー、本人の採用という往復を使う。通常の1操作開始を維持する。

公開の派生問題は0問。通常800問・教材と学習記録を保持し、現行診断は既存過去問だけで動作する。追加基盤は別のハッシュ付き教材ファイルを診断開始時だけ読込。通常の開始では読み込まない。未確認・確認ハッシュ不一致・元問題や分野不一致の教材は生成時に拒否し、取得失敗も黙って既存問題へ置き換えない。未着手の派生→未着手の既存→既出の派生→既出の既存の順。同じ元問題を重ねて出さず、派生問題の誤答は通常復習へ混ぜない。開始した診断は教材追加・配分変更後も固定。派生問題の回答は診断結果だけに数え、通常履歴と計画実績には含めない。[追加・確認手順](diagnostic-authoring.md)。

### 計画の受信と画面への反映（2026-10-07）

### 次の行動を示す画面（2026-10-07、P0・P1実装）

- 主な移動先は「学習」「分野」「記録」。ホームの主操作は通常の1問開始、または最新の通常学習の「続きから」。診断の中断は下に別表示し、通常開始を妨げない。「別の1問」も選べる。
- ホームは表示時に具体的な問題IDと範囲を保持し、そのボタンから同じ問題を開く。現在の計画の重点分野で、復習日が来た問題→未着手→古い完了記録の再確認を選ぶ。未着手は直近28日の通常学習で確認した問題種類の少ない分野を優先し、同数なら資格定義の順序。重点なし・計画空白は通常出題。対応教材がなければ理由を表示して通常問題を選び、オフラインでは保存済みの問題だけが候補となる。
- 計画から開始した分野とパートはそのセッション内で保持し、「もう1問」も同じ範囲。途中の同期で計画が変わっても切り替えない。明示的な分野選択・検索からの開始を優先する。終了後のホームで候補を再評価。
- 開始直下に受験パート名・残日数、現在のフェーズ・重点分野、任意の週別目標の実績／目標／残り、次の未完了予定を表示。過ぎた受験日は経過日数で示す。ゲストの計画は端末内であることを表示。
- 分野画面は「普段の学習・直近28日」と「最新の30問診断」を切替。通常は資格・パートごとに、計画のタイムゾーンで今日を含む28暦日の問題ごとの最後の完了記録を集計。未完了・診断・派生問題・未来の記録は除外。自力正解／ヒント付き正解／不正解／解答閲覧の割合と件数を表示。再挑戦の回数では分母を増やさず、解答後のヒントで解答前の分類を変更しない。
- 診断グラフは最新の終了した1回の回答確定数を分母にし、未回答を不正解に含めない。通常と混ぜない。記録なしは「未確認」、10問未満は「記録少なめ」。少数の低い率を通常の並びの上に置かず、計画の重点→10問以上→少数→未確認の順。率から苦手・習熟・合格可能性を断定しない。
- 各分野からすぐその分野の演習を開始できる。検索は分野画面、計画・診断・復習と達成の詳細は記録画面からも開ける。
- 計画画面は概要を先に表示。編集とAI用JSONは別の折りたたみ。同期受信時は読取専用の概要を更新し、未保存の入力を保護する。診断結果のAI相談ボタンは計画のAI入口を直接開く。既存のAI Exportと計画実績の全試行数の定義は保持する。

新しい必須設定・クラウド文書・Rulesは追加しない。教材800問と既存記録、学習・同期・PWAは保持。P2の推移グラフ、ゲスト計画の比較取り込み、計画の自動調整は未実装。[読みやすい画面設計](action-first-design.html)。

## 電車向け試用（2026-10-07）

- 主開始ボタンは維持し、その下で「すべて／紙・ペンなし」を選択。全800原本を分類済み。紙なし651問、机向け149問、未分類0問。難易度の判定ではない。
- 計画・復習・分野・パート・オフラインの範囲と交差させる。対象不足を説明し、紙なしから筆算や未分類へ無言で切り替えない。セッション中の取り組み方は固定する。診断・グラフ・既存の正答率集計は変更しない。
- 問題パネルの外・下側にある「この問題のオプション」から「紙なしの候補から外して中断」を実行すると、回答候補とヒントを保存して中断。ホームに保持件数と指定解除を表示する。未完了記録は削除しない。
- 単語帳681枚は任意の別入口。用語→裏面→思い出せた／もう一度。自己評価は四択・計画実績に混ぜず、カード版ごとに扱う。一周中の既出・直前カードを避け、再確認を優先する。

- 分類・カードを任意の資格別サイドカーとして追加。原問の教材本文は変更せず、分類の元問題ハッシュ・カード参照をビルドで検証。通常開始ではカードJSONを取得しない。初回取得後はPWAの教材キャッシュでオフライン利用。

### 学習開始の3つの入口（2026-10-08）

- 「身軽に1問」「書いて考える1問」「おまかせで1問」。補足の小さな説明を付けず、押すとすぐ問題を開く。分類は公式教材の651／149問を利用し、おまかせは全800問。個人の机指定は紙なしから除き、書いて考える側へ加える。
- 前回の入口を強調し、途中の問題は開始した入口で再開。選択した回答・ヒント・スクロール位置を保持。個人の机指定で中断した問題は、書いて考える入口へ移す。新しい入口を使っても他の入口の途中記録は失わない。
- 入口の直下に単語帳・分野別、計画の重点または学習記録から最大2分野の近道。近道は前回の入口の問題範囲を引き継ぐ。該当する問題がない分野は勝手に別範囲で埋めない。
- その下に試験までの日数、今週の目標または期間の実績・残り、今日の分野。長いフェーズ名・全重点分野・予定一覧は計画詳細へ。初期設定・計画登録・ログインは必須にしない。
- 320／390px幅・844px高・通常文字で、開始・近道・計画を初期画面内に表示。文字200%では横にはみ出さず縦に読めることを優先。
- 選んだ入口・試行の入口・個人の机指定は端末内の利用者×資格の設定。四択の回答・ヒント・中断、計画・診断の既存同期とデータは維持。Firestore Rulesの再公開は不要。
