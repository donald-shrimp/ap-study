# 端末をまたぐ学習の同期 — 設計レビューと実装範囲

2026-10-10。まず主担当が保存・選出・再開・Firebase・バックアップを調査し、別担当が読み取りレビューを実施。その指摘を反映してからP0aを実装し、再度レビューしています。教材の変更はありません。

## 実装済みの範囲（P0a・P0b）

スマホで「この問題は紙ペンが必要」と指定し、PCで「書いて考える1問」から回答候補・ヒント・分野指定を保って再開するための基盤です。

| 情報 | 保存・同期単位 | 今回 |
| --- | --- | --- |
| 個人の紙ペン指定と解除 | ユーザー × 資格 × 問題 | 実装 |
| 先送りと解除 | ユーザー × 資格 × 問題 | 実装 |
| 通常演習の入口・分野・パート・復習範囲 | ユーザー × 資格 × 試行 | 実装 |
| 単語帳の思い出せた／もう一度 | ユーザー × 資格 × 評価イベント | P0b実装 |
| 単語帳の中断位置 | 端末別チェックポイント | P1 |
| 前回使った入口 | 端末ごとの入口をクラウド保存 | P1 |
| 教科書メモ | ユーザー × 資格 × 分野 | P1候補 |
| 文字サイズ・スクロール・教材編集 | 端末内 | 維持 |

前回の入口を全端末共通にすると、スマホの「身軽」がPCの「書いて考える」を毎回上書きします。各端末の入口を保ちつつ、別端末の中断問題を再開できる形を優先します。同期するのは試行の再開条件で、現在の画面や開いている問題は切り替えません。

## レビューで見つかった競合と対応

- **回答の不変性：** 確定した回答を紙ペン設定や先送りの変更で上書きしない。既存attemptsの送信形式と採点ルールを維持し、可変情報は新しいlearningコレクションへ分離。
- **既存の計画同期：** resourcesへ新しい種類を追加すると、旧クライアントの計画検証が止まる。新しい同期経路・状態表示を分ける。ルール未配備でも通常学習と既存同期を維持。
- **先送りの二重管理：** 設定を問題単位の正本とし、全試行の表示と現在セッションの除外へ反映。ホーム・分野・連続出題・おすすめへ同じ除外集合を渡す。明示的な再開・回答・解き直しで解除。
- **別アカウントの設定混入：** 新UIDへの設定初期化で紙ペン指定をコピーしない。ゲスト指定の取り込みは明示操作で、回答0件でも取り込める。
- **同期だけで中断の所有端末が変わる：** 再開範囲などだけのローカル投影では、回答リビジョンと作成端末を変更しない。設定だけの古い保存と新しい受信が交差した場合も、新しい回答内容を保持して不要な継続記録を作らない。他端末の再開は新しい継続UUIDにして、双方の回答を残す。
- **通信待ち中の画面移動：** 必要な情報がある端末内の中断は通信を待たず再開。別端末の範囲が未取得なら取得を待つ。再開要求の冒頭で画面遷移と保存先を捕捉。通信完了時に変化していれば再開を中止。
- **資格に存在しない範囲：** 分野・科目を資格定義と照合し、未知の同期contextや、対象問題と一致しない範囲は通常記録へ適用しない。バックアップは資格IDを持ち、別資格と不正範囲を取り込み前に拒否。
- **分類変更後の中断：** 保存された入口が現在の紙ペン分類に合わなくなった場合、その中断は「おまかせ」で再開。分野・パート・ヒント・回答候補は保持し、理由を表示。
- **単語帳の削除で記録が復活：** P0bで観測した評価IDを列挙するresetを保存。バックアップでの復元は観測したreset IDだけを取り消すrestoreを保存。後の削除は過去の復元に打ち消されない。

## 保存モデルと競合

`users/{uid}/qualifications/{qualificationId}/learning/{id}` に、`desk--{questionId}`、`deferred--{questionId}`、`context--{attemptId}` を保存します。解除も`value:false`を保存し、削除しません。異なる問題・設定種別は別文書です。

端末内は既存IndexedDBのmeta領域を利用者・資格で区切り、通常記録と設定の送信待ちを同じトランザクションで保存します。DBバージョンは上げません。操作IDとローカル・クラウドのリビジョンを別に持ちます。すでにクラウドで確定した別端末の変更と競合した場合はクラウド側を使い、短い案内を表示します。端末時計だけで勝者は決めません。同一端末の後続変更と遅れて届いたACKも区別します。

ローカル保存・回答同期・計画診断同期・新しい学習設定同期は別表示です。新ルールが未配備なら新しい設定は端末に保存したまま待機します。再開条件を取得できない他端末の中断は、不正な範囲へ変えず再同期を案内します。

## P0b：単語帳の自己評価（2026-10-10）

`users/{uid}/qualifications/{qualificationId}/cards/{id}` を別経路で同期します。確認・実装は主担当1人で逐次行い、今回の別担当レビューは行っていません。

- `rating--{eventId}`：カードID・カード版・自己評価・日時を変更せず追記。同じカードを2端末で評価しても2件保持。
- `reset--{id}`：削除操作で確認できた評価IDの一覧。最大200件ずつに分割し、時計による全体リセットは使わない。他端末の未同期評価は削除対象に含めない。
- `restore--{id}`：専用バックアップから復元する評価IDと、取り消すreset IDを各最大200件で記録。古い復元で新しい削除を解除しない。

全クラウド文書は作成後変更・削除不可。同ID・同内容の再送は既存文書を読み取って完了扱い、異なる内容は拒否。ゲスト評価はログインだけでは取り込まず、明示取り込みも削除を取り消さない。専用バックアップは従来のv1形式で可視評価だけを書き出す。削除は集計からの論理削除で、クラウドからの完全消去ではない。

端末内の評価・送信待ち・削除/復元・中断位置は同じIndexedDBトランザクションで保存。既存v1の評価は元IDのまま保持する。差分取得位置は全行を保存した後で端末へ記録し、再読み込みのたびに全履歴を取得しない。可視評価の上限は従来どおり2万件。削除済み評価と制御記録は別に保持し、大量の反復削除・復元時は保存量が増える。

受信で進捗枚数と次候補の評価情報を更新するが、表示中のカード・裏表・フォーカス・中断位置は変えない。自己評価を通常四択の正答率・計画実績に含めない。新ルール未配備なら単語帳だけ案内し、通常の回答・学習設定・計画診断は独立して同期する。
