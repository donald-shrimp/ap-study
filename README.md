# ひと問

短い時間で始められる、資格試験の学習アプリです。現在の公開教材は応用情報技術者試験です。1問ずつ解き、段階ヒントを使い、後から解き直せます。教材と画面はGitHub Pagesで無料公開できます。ログインなしなら端末内で動作し、Googleログイン時はFirebaseで学習記録を同期します。

ホームは「次の1問」から1操作で開始。残日数・現在の重点・週の実績をその下に表示します。分野画面で普段の学習と最新診断のグラフを切り替え、同じ場所から演習を始められます。計画は概要を先に表示し、編集とAI用JSONは必要なときに開きます。

[画面と出題の設計・実装状況](docs/action-first-design.html)（P0・P1実装済み）。通常グラフは直近28日の問題ごとの最後の完了記録です。AI Export・計画実績の全試行数とは集計が異なります。

## ホーム画面に追加・オフライン利用

Android・Chrome等では「表示・データ」にインストールボタンが表示される場合があります。ブラウザのインストールメニューも使えます。iPhone・iPadではSafariの共有メニューから「ホーム画面に追加」を選びます。

Android Chromeでインストール項目が無効になった報告は、広告ブロックを除外することでインストール成功を確認しています。アプリ追加を抑制するフィルターは、マニフェストへのリンクを削除する場合があります。該当する場合は `donald-shrimp.github.io` をサイト除外して再読み込みしてください。`?pwa-check=1` を付けて開くと、端末のブラウザ情報・マニフェストとアイコンの取得結果・サービスワーカーの状態・インストール通知の有無をコピーできます。診断には学習記録を含めず、削除や初期化も行いません。JavaScriptからChrome内部の不適格理由を直接取得することはできません。

アプリと問題データを保存し、表示した問題画像を追加で保存します。初回はオンラインで開いてください。通信が切れても、保存した問題を再開・解き直しでき、選択した回答とヒントの段階を保持します。新しく自動出題する場合も、オフラインで読める問題を選びます。画像未保存の問題を直接選んだ場合は、その理由を表示し、途中の記録を変更しません。全800画像の一括ダウンロードは行いません。

通信できるときは公開教材を取得して保存し、オフラインでは保存済みの教材を使います。アプリ本体の更新が準備できた場合は「表示・データ」に「更新して再読み込み」を表示し、学習中には自動再読み込みしません。学習記録は利用者・資格別のIndexedDB、公開教材の一時保存はCache Storageと分けています。Googleログイン時はFirebaseで学習履歴・ヒント・中断状態を同期します。教科書メモ・設定・教材編集は端末内です。ログインなしで別ブラウザへ記録を移す場合は、学習記録の書き出し・読み込みを使ってください。

`manifest.webmanifest` の起動先・スコープ・画像は相対パスなので、GitHub Pagesの `/ap-study/` でも動作します。 アプリIDは `/ap-study/` で固定します。`id` は起動先やマニフェストのディレクトリではなくオリジン基準で解決されるため、`./` を使うと同じホストの別プロジェクトと識別子が衝突します。アプリ本体を変更する際は `sw.js` の `RELEASE` と、`templates/study.html` のJS/CSS・マニフェストと `app.js` の共通モジュールURLのリビジョンをそろえ、`python tools/build-content.py` で入口を再生成してください。アイコンは `python tools/generate-icons.py` で再生成できます（開発時のみPillowが必要）。

```sh
python tests/pwa.py
```

マニフェスト・アイコン・サブフォルダー、実際のオフライン再読み込み、選択・ヒント・画像の復元、未保存問題の拒否、更新後の保存済み教材を検証します。公開版では `AP_STUDY_PWA_URL=https://donald-shrimp.github.io/ap-study/ python tests/pwa.py` を使います。インストールそのもののOS操作は利用端末で行います。

## 教科書から演習する

教科書は利用者が別に持っているものを使います。アプリ内に教科書本文は用意しません。「分野別演習」で読んだ分野を選び、その分野だけの問題を開始できます。章やページのメモは任意で、開始に必須の操作ではありません。

現在は基礎理論、アルゴリズム、データベース、ネットワーク、セキュリティ、マネジメント、法務など17分野、計800問です。詳細分野はアプリ独自の分類です。分野別の開始ボタンは実際の収録数に合わせています。分野内を一巡したら、同じ分野の解き直しになります。問題と分野設定を追加すると、その分野が一覧に現れます。

達成の表示は学習記録の事実から算出します。ヒント利用や解答確認も、取り組みとして数えます。正誤・ヒント数は別に残し、ポイントの減点や連続利用が途切れた際のリセットは設けません。

## 保存のしくみ

記録は利用中のブラウザのIndexedDBに、端末のゲストID・資格ID・試行UUIDで分けて保存します。ログインなしでは端末内、Googleログイン時は資格別のクラウド同期を使います。ブラウザのデータ削除・別端末・別URL・プライベートブラウズには注意し、必要な記録は「表示・データ」から書き出してください。保存できないときは画面に表示します。

教材を編集しても、既存の学習記録にはその時点のヒント・解説を残します。以前のガイドや更新前のヒントで再開した場合は、「最新のヒントで続ける」から最新教材へ移れます。途中の回答候補を引き継ぎ、ヒントは閉じた新しい試行になります。以前のヒント閲覧履歴は前の記録に残します。編集と復習目安の計算は端末のローカル日付を使います。別タブの新しい試行を全履歴で上書きしません。同じ中断問題へ同時に回答した場合は、継続記録として両方を残します。別タブで初期化・読み込みが行われた場合、古いタブの保存を止めて画面に案内し、消した記録を復活させません。


記録の更新と未同期の送信待ちは1つのトランザクションで保存します。スクロールだけの変更は送信待ちを増やしません。Googleログイン時だけ、UID・資格別の送信待ちをFirestoreへ送ります。「この端末に保存済み」と「同期済み」を別に表示し、通信失敗でも学習を続けられます。読書メモ・表示設定・教材編集は端末内に保持します。別端末で中断から再開するときは新しい継続記録を作り、同時に解いた回答を両方残します。

現在と同じ記録形式のlocalStorageデータがある場合、初回のみ内容を検証してIndexedDBへコピーします。元の値は変更せず残します。別バージョンの変換・互換レイヤーはありません。読めない値は上書きせず、画面からそのまま書き出せます。読み込みは64MB以下の同じ仕様のJSONを対象とします。

## 資格別ページと共通部分

- `/ap-study/`：今は応用情報を直接開く。資格が増えると資格選択を表示。
- `/ap-study/ap/`：応用情報の直リンク。ルートと同じ記録を利用。
- `src/app.js`：画面をつなぐ共通処理。`src/ui/views.js`、`src/domain/`、`src/content/`、`src/storage/` に責務を分離。

## 問題を増やす

応用情報は `data/questions.json` を作成元として問題を追加し、`python tools/build-content.py` で公開用パックと入口を生成します。問題・選択肢・正解・年度・期・出典URL・原本画像・段階ヒント・関連問題IDを記述してください。`hintStatus: individual` は個別ヒント付き、`enrichment: reviewed` は詳しい個別解説付きです。`enrichment: topic-guide` は詳しい個別解説が未追加で、解答後に分野の復習メモを表示します。ヒントと解説の状態は別々に扱います。個別解説がない場合の `choiceReasons` は空配列にします。既存問題を雛形にできます。正解は0始まりの選択肢インデックスです。

ブラウザで編集したヒント・解説を公開教材に反映するには、「問題と教材」→「教材を書き出す」のJSONの公開用ID・絶対画像URLをそのまま作成元へ戻さず、必要なヒント・解説を `data/lessons/` の対応問題へ反映し、`python tools/apply-hints.py` で再生成してコミットします。問題文・正解・図は公式資料と照合してから公開してください。画面上の教材編集では正解や問題文は変更しません。

開発中のため仕様・データ形式は変更可能です。後方互換や移行機構は現段階の要件に含めません。

## 解説とヒントの編集

`data/hint-authoring/` の14ファイルに、初期の791問分のヒントを問題IDで明示的に割り当てています。初期の残る9問は既存教材を土台にしています。完成した各回は `data/lessons/` の教材を優先します。同じ概念・解法の問題では、同じ行へ複数IDを指定できます。分野名だけを使った共通テンプレートへの置換は行いません。

`data/lessons/` の `r07h.json`・`r07a.json`・`r06h.json`・`r06a.json`・`r05h.json`・`r05a.json`・`r04h.json`・`r04a.json`・`r03h.json`・`r03a.json` は2021〜2025年春秋の800問の解説・4選択肢の理由・要点・3段階ヒントをまとめた作成元です。個別の問題画像と公式正解を確認して作成します。`tools/apply-hints.py` は既存ヒントを読み込んだ後、この教材で上書きします。教材化済みの問題はこのJSONで編集し、再生成で古いヒントへ戻らないようにします。

既存ヒントの行の形式は `問題ID（空白区切り）|概念|ヒント1|ヒント2|ヒント3|正答開示の設定` です。最後の設定は省略時 `000`、例えば `010` は2段目で答えを含むことを示します。画面では開く前に「答えを含む」と表示し、回答前に見れば解答閲覧として記録します。

```sh
python tools/apply-hints.py
python tests/corpus.py
python tests/lesson-math-r04a.py
python tests/lesson-math-r04h.py
python tests/lesson-integration-r04.py
python tests/lesson-math-r03h-01-40.py
python tests/lesson-math-r03h-41-80.py
python tests/lesson-integration-r03h.py
python tests/lesson-math-r03a-01-40.py
python tests/lesson-math-r03a-41-80.py
python tests/lesson-integration-r03a.py
python tests/lesson-preservation-r03a.py
```

`hintSource` に作成ファイルと行番号を保存しています。作成済みであることと、学習者が次の一手を理解できることは別です。ヒントは「どの条件を使うか」「なぜその式・手順か」「最初に何を計算・比較するか」まで説明し、一般的な助言だけになっている内容は具体化します。検索用OCRをそのままヒントへ転記せず、数式・単位・図表は公式原本画像で照合します。2021〜2025年春秋の800問全てを、解説 → 4選択肢の理由 → 3段階ヒント → 内容確認の順で仕上げています。2025年秋・2024年春秋の240問に続き、2023年春秋の160問、2022年春秋の160問、2021年春の80問、最後に2021年秋の残る78問を追加しました。今回のgpt-6.1-solは同時稼働を最大2担当とし、作成2担当が終了してから別の確認2担当が全原本を解き直し、修正後まで確認しています。10問単位で保存し、主担当だけが共通データを統合します。確認記録は `data/lesson-reviews/` に残し、教材のSHA-256と照合します。2021年秋の既存2問も本文を保持して原本から再確認し、第2段の正答開示設定だけを訂正しました。全800問の教材が完成しています。

## 800問の取り込みと確認

問題・解答の公式URLとSHA-256は `data/sources.json`、80問ずつの正解は `data/answer-keys.json`、一問ずつの切り出し座標は `data/source-crops.json` に保存しています。2022年春・秋と2023年春は、問題がPDFの3ページ目から始まるため、表紙枚数を固定せず問番号を確認しています。800個の問番号を原本画像で照合しました。

新規問題は原本を損失のないWebP画像で保存しています。検索用テキストは自動読み取りであり、数式や文字に読み取り誤りがあります。解答時の正本は画像です。画像のみの問題文はスクリーンリーダーで全文を読み上げられません。最初の5問は従来の文字・図での表示も残しています。

2022年春の解答PDFは画像形式です。80個の正解を表から転記して原本と再照合しました。その他9回は公式解答PDFのテキストから取得しています。全800問に問題別の3段階ヒントを追加しています。全800問に詳しい個別解説と4選択肢の理由を追加済みです。今後追加する教材の完成状況も明示します。

