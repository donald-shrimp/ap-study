宣言型エンジン エージェントとカスタム エンジン エージェントの比較
フィードバック
Microsoft 365 Copilot は、Microsoft Graph のエンタープライズ データを使用して、Copilot Chat、Outlook、Teams、Word などの Microsoft 365 アプリケーション全体のワークフローを強化する AI 搭載の生産性向上ツールです。 Copilot には強力な組み込み機能が備わっていますが、組織は多くの場合、特定のユース ケースに対処するために追加の知識、データ ソース、またはアプリケーションを統合する必要があります。
エージェントは、特定のドメインに合わせた特殊な AI アシスタントとして機能することで、Copilot の機能を拡張します。 これらのエージェントは、組織の知識と自動化を適用して、ビジネス プロセスを合理化し、意思決定を強化し、効率を向上させます。 エージェントは、情報を取得したり、データを要約したり、電子メールの送信や記録の更新などのアクションを実行することもできます。
Copilot のエージェントを構築するには、2 つのアプローチのいずれかを使用できます。Copilot のエージェントを構築するには、指示、知識、アクションを Copilot のオーケストレーターおよびモデルと共に活用する 宣言型 アプローチと、独自のオーケストレーターとモデルを導入して完全にカスタマイズされたエージェントを作成するカスタム エンジン アプローチです。 この記事では、2 つの方法について説明し、それぞれの使用状況に関する情報を提供します。
エージェントを構築する理由
Microsoft 365 Copilot は強力な AI 主導の支援を提供しますが、Copilot だけではorganization独自のワークフロー、データ ソース、または自動化のニーズに完全には対応できない場合があります。 エージェントを構築することで、次のことができます。
サード パーティのシステムとデータ ソースを統合することで、Copilot の知識を拡張します。
Microsoft 365 および外部アプリケーション全体にわたる複雑な複数ステップのワークフローを自動化します。
Teams チャット、Outlook、SharePoint、カスタム アプリなど、ユーザーが作業する場所に表示される、カスタマイズされたユーザー エクスペリエンスを提供します。
エージェントを使用すると、Copilot と他のエンタープライズ システム間の安全なリアルタイムの対話が可能になります。 Microsoft とそのパートナーは、さまざまな構築済みエージェントを提供しています。 特定の要件に合わせて、ローコード ツールとプロコード ツールの両方を使用して独自のツールを構築することもできます。
たとえば、 Sales Agent for Copilot は、Dynamics または Salesforce 内の連絡先をセールス リードに変換し、会議を設定し、顧客に連絡することで、リード管理を自動化できます。その際に、Microsoft 365 およびエンタープライズ データに安全にアクセスして相互作用をパーソナライズし、ビジネス成果を推進します。
Microsoft 365 Copilot のエージェントを開発することで、組織は Teams、Outlook、Copilot、またはその他の Microsoft 365 アプリケーションのフロー内でエンタープライズ データを安全に利用し、アプリケーション間でアクションを実行し、生産性を向上させることができます。
エージェントのコア コンポーネント
エージェントは、次のコア コンポーネントで構成されています。
知識: 専門的な指示とデータ ソースを提供することで、エージェントの応答を調整します。
アクション: ビジネス プロセスを自動化するアクション、トリガー、ワークフローを開発します。
これらのコア コンポーネント以外にも、追加のレイヤーによってエージェントの機能が強化されます。
オーケストレータは、エージェントが知識、スキル、自律性と対話する方法を管理する中心的なエンジンとして機能します。
基盤モデルは、エージェントの推論、言語理解、応答生成を強化し、すべての対話の背後にあるインテリジェンス層を形成します。
ユーザー エクスペリエンス レイヤーは、エージェントを Microsoft 365 アプリケーションまたは外部プラットフォームに統合して直感的で効率的なワークフローを実現することで、ユーザーとエージェント間のシームレスな対話を保証します。
これらの要素を組み合わせることで、エージェントは Copilot を拡張してタスクの自動化、データの統合、インテリジェントでコンテキスト認識型支援の提供を行う強力な方法を提供します。
宣言型エージェント
宣言型エージェントを使用すると、カスタム命令、追加の知識、アクションを追加してビジネス プロセスを自動化することで、特定のシナリオに合わせて Copilot を構成できます。 宣言型エージェントは Copilot の AI インフラストラクチャ、モデル、オーケストレーターを使用するため、Microsoft 365 のセキュリティ、コンプライアンス、責任ある AI (RAI) 要件に準拠しています。 次の図は、宣言型エージェントの基本的な解剖学的構造を示しています。
宣言型エージェントを構成するには、次を指定します。
organization の特定のニーズやワークフローに合わせて Copilot の応答を形作るカスタム指示。
Microsoft 365 データ ソース (Teams メッセージ、Copilot コネクタ、SharePoint、OneDrive など) または外部データを Microsoft 365 Copilot コネクタを介して接続するためのカスタム知識。
API と統合して外部システムとリアルタイムで対話するカスタム アクション。
宣言型エージェントには、次の特性があります。
ホスティング: Copilot のオーケストレーターと基礎モデルを使用します。 追加のホスティングは必要ありません。
ツール:Microsoft 365 Copilot などのローコード ツール、または Visual Studio、Visual Studio Code などのプロコード ツール、Microsoft 365 Agents Toolkit を使用してエージェントを構築します。
チャネル:Microsoft 365 Copilot や、Teams、Word、Excel、Outlook などの Microsoft 365 アプリで実行します。
ヒント
Work IQ Dev Tools (プレビュー) — ターミナルから宣言型エージェントを構築するチーム向けに、 wiqd は、プロジェクトのスキャフォールディングから検証、プロビジョニング、パッケージ化、公開、監視まで、ライフサイクル全体にわたる宣言型エージェント固有のツールを提供します。 詳細については、 Work IQ 開発ツールのドキュメントを参照してください。
カスタム エンジン エージェント
カスタム エンジン エージェントは、完全にカスタマイズされた AI アシスタントです。 これらは、複雑なワークフロー、オーケストレーション、または特定の言語モデルを必要とするシナリオに役立ちます。 カスタム エンジン エージェントを構築するには、モデルとオーケストレーター用に追加のホスティングを提供し、カスタム エージェントが準拠し、セキュリティで保護され、 責任ある AI (RAI) ポリシーに準拠していることを確認する必要があります。 次の図は、カスタム エンジン エージェントの基本的な分析構造を示しています。
カスタム エンジン エージェントを開発するには、以下が必要です。
ワークフローを完全に制御し、追加の知識と外部 API 呼び出しを統合するカスタム オーケストレーション。 機能を強化するために、1 つ以上の言語モデルを組み込むことができます。
カスタム モデルを使用して 、基盤の大規模言語、小型言語、微調整、または業界固有のモデルなど、ユース ケースに最適なモデルを選択します。
ワークフローとアクションをプログラムで開始するための自律性とプロアクティブなエージェント サポートにより、エージェントが独立して操作し、意思決定を行い、必要に応じてタスクをエスカレートできるようにします。
カスタム エンジン エージェントには、次の特性があります。
ホスティング:Microsoft 365 以外のホスト (通常は Azure などのクラウド サービス) に追加料金でホスティングが必要。
ツール:オーケストレーションは、ローコードの Copilot Studio や、Visual Studio、Visual Studio Code、Agents Toolkit などのプロ コード ツールを使用し、.NET、Python、JavaScript などの言語と、セマンティック カーネルや LangChain などのフレームワークを使用して構築できます。
チャネル:Microsoft 365 Copilot や、Teams、Word、Excel、Edge などの Microsoft 365 アプリで実行できます。
コラボレーション:エージェント間のコミュニケーションをサポートし、エージェントがタスクを委任し、ワークフローを調整できるようにし、organization内の複数のエージェントにわたって Copilot の機能を拡張します。
ビルドするエージェントの種類を選択する
このセクションでは、ビルドするエージェントの種類を決定するのに役立つ、宣言型およびカスタム エンジン エージェントの機能とシナリオについて説明します。
次の表は、宣言型エージェントとカスタム エンジン エージェントの主な違いをまとめたもので、ユースケースに適したオプションを選択するのに役立ちます。

次のフロー チャートは、ビルドするエージェントの種類を選択するための決定プロセスをまとめたものです。
宣言型エージェントを構築する場合:
エージェントが Copilot のオーケストレーションと言語モデル内で動作して、セキュリティとコンプライアンスとの一貫性を確保する必要があります。
より迅速な実装が必要な場合、または Copilot Studio などのツールを使用してコードなしまたはローコードを備えたエージェントを開発したい場合、または Visual Studio や Microsoft 365 Agents Toolkit などのプロコード オプションを使用して合理化されたエクスペリエンスを好む開発者の場合。
ユーザーのワークフローは Microsoft 365 アプリ (SharePoint、OneDrive、Teams) 内にあり、これらのアプリケーションのコンテキスト内で ( @mentions または Teams ビジネス チャットを介して) 作業することを望んでいます。 たとえば、Teams の @mentions に応答する IT ヘルプデスク エージェントや、SharePoint で呼び出されたドキュメント要約エージェントなどです。
カスタム エンジン エージェントを構築する場合:
エージェントには、複雑なワークフロー、特定のビジネス ロジック、正確な意思決定ルール、または複数のシステム統合を処理するためのカスタム オーケストレーションが必要です。 たとえば、金融ローン承認エージェントは、候補者の申請を評価するための特定のビジネス ルール、正確なデータ収集要件、複数の信用チェック システムを備えている場合があります。
独自の AI モデルを使用する場合、またはエージェントが専門知識を持つドメイン固有モデルまたはマルチモーダル モデルの恩恵を受ける可能性があります。
複数のユーザーが Teams のチャネルまたは会議で同じエージェントと共同作業したり、同じエージェントの恩恵を受けたりできる、グループの生産性を有効にしたいと考えています。
Copilot の外部に既存の会話アシスタントを構築し、それを Microsoft 365 および Copilot と統合したいと考えています。
Microsoft 365 と Copilot の外部でエージェントを利用できるようにしたいと考えています。
開発者がワークフローを定義し、ユーザーの操作を必要とせずにエージェントの動作をトリガーできるプロアクティブ メッセージングをサポートする必要があります。
