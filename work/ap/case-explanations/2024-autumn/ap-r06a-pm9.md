# 電気機器メーカーの新たなプロジェクト――機器開発の経験を、そのまま新サービスへ当てはめない

## この問題は、何を考える問題だった？

A社はこれまで、製造現場で使われるIoTセンサーなどの産業機械と、その機器の提供に付随するシステムを開発してきた大手電気機器メーカーです。しかし近年は産業機械市場の成長が鈍化してきたため、研究開発していた「生体センサー」を核にして、一般の消費者に向けたヘルスケアサービスを提供する新規事業へ乗り出すことにしました。

この大問で一貫して問われているのは、**「これまでの『仕様どおりに機器と付随システムを作って納品する開発』と、今回の『消費者の行動変容を促す新サービスを立ち上げるプロジェクト』では、目標・体制・開発手法・リスク対応の何がどう変わるのか」**という点です。

単に用語の定義を当てはめるのではなく、**「誰に何を提供するのか（設問1）」「誰の協力を得て、どの開発手法で進めるのか（設問2）」「何を最優先の目標としてリスクやチーム体制に向き合うのか（設問3）」**を一本の流れとして結び付けて読み解きましょう。

## まず、本プロジェクトの全体像と従来との違いを整理しよう

設問に入る前に、本文に書かれている「従来のプロジェクト」と「本プロジェクト」の違い、および登場人物・組織の関係を整理しておきましょう。

| 観点 | A社の従来のプロジェクト | 今回のプロジェクト（本プロジェクト） |
| --- | --- | --- |
| **市場面（誰に・どの分野へ）** | 製造業向けの産業機械市場 | **消費者向けのヘルスケア市場**への進出 |
| **製品・サービス面（何を）** | 産業機械（機器）の提供に付随するシステム開発 | 生体センサーと連携し、バイタルデータを活用して運動を促す**健康増進に関わるサービスの提供** |
| **最優先の目標** | 決められた仕様・納期どおりの機器・システム納入 | **顧客への体験価値の提供**（利用者が実際に使って価値を得られること） |
| **開発アプローチ** | 従来のシステム開発 | **アジャイル開発アプローチ**（先進ユーザー20名と仮説検証プロセスを反復） |
| **チーム編成** | A社内のメンバー中心 | A社システム部＋事業開発部（買収した**旧T社**を含む）＋提携交渉中の**R社からの派遣社員** |

また、「5年後に事業開発部の売上高比率を全社の20%程度まで拡大する」という中期事業計画と、「まず最初のサービスとして先進ユーザー20名に参加してもらい事業可能性を検証する」という本プロジェクトの範囲の違いもおさえておくと、本文の条件を混同せずに済みます。

## 設問1(1)｜市場面は「誰に、どの分野で届けるか」

設問1は、下線①「A社でこれまでに実施してきたプロジェクトとは異なる市場面及び製品・サービス面の特性」について、それぞれの特性を20字以内でまとめる問題です。

まず設問1(1)の**市場面**から考えましょう。「市場（マーケット）」とは、商品やサービスを届ける**顧客層（誰に）と取引の分野（どの領域で）**を指します。

1. **従来の市場**：製造業向けの産業機械市場
2. **今回の市場**：［ヘルスケア事業の概要］の1つ目に「今後，成長が見込まれる**消費者向けのヘルスケア市場に進出**し」と明記されています。

単に「新しい市場に進出」とだけ書くと対象顧客や分野が分からず、反対に「生体センサーを提供」と書くと次の設問1(2)（製品・サービス面）の内容になってしまいます。「誰に向けた」「どの市場か」の2要素を抜き出して20字以内でまとめます。

- **公式解答例**：「消費者向けのヘルスケア市場に進出」（16字）

## 設問1(2)｜製品・サービス面は「何を提供するか」

続いて設問1(2)の**製品・サービス面**（「顧客に何を提供するか」）を確認しましょう。

1. **従来の提供物**：産業機械市場への「機器の提供に付随するシステム」でした。
2. **今回の提供物**：［ヘルスケア事業の概要］に「消費者向けに機器に加えてサービスを提供するため」「高齢化に伴う未病対策といった**健康増進に関わるサービスを提供**することを目的とする」と書かれています。具体的には、脈拍・血圧・体温などの**バイタルデータ**（身体の状態を示すデータ）を活用して運動を促す行動変容サービスです。

したがって、「センサーというハードウェア（機器）を売るだけでなく、利用者の健康増進に関わるサービスそのものを提供する点」を20字以内でまとめます。

- **公式解答例**：「健康増進に関わるサービスの提供」（15字）

設問1(1)の「誰に・どの市場へ（消費者向けのヘルスケア市場）」と、設問1(2)の「何を（健康増進に関わるサービス）」を入れ替えないよう注意しましょう。

## 設問2(1)｜抵抗しているS氏にも、進捗と成果を伝える

設問2(1)は、表1（社外のステークホルダ登録簿）の下線②で「抵抗する」姿勢を示しているR社の事業部長S氏に対し、プロジェクトマネージャのC課長がとるべき最も適切な行動を選ぶ問題です。

**ステークホルダ**とは、プロジェクトに影響を与えたり、プロジェクトの結果から影響を受けたりする利害関係者のことです。表1と本文から、S氏の状況を整理しましょう。
- 医療機器製造業であるR社の事業部長であり、事業提携の交渉相手として本プロジェクトへの**影響力が大きい**。
- 現時点では提携に消極的で、本プロジェクトに対して**「抵抗する」姿勢**をとっている（ただしR社経営層からは当面A社に協力するよう指示されている）。
- 一方で、［本プロジェクトの立ち上げ］の末尾に「**R社のS氏は，本プロジェクトの成否や成果に強い関心をもっており，新事業が順調に立ち上がれば，提携に積極的な態度に変わるものと期待できる**」と明記されている。

つまり、S氏は「どれだけ説明しても絶対に反対し続ける相手」ではなく、「本当に新事業がうまくいくのか、その成果を注視している重要なパートナー候補」です。したがって、S氏の強い関心に応えて前向きな姿勢への変化を促すには、判断材料となる進捗と成果を適切に共有する **イ**（「適宜プロジェクトの進捗と成果を報告する。」）が最も適切です。

各選択肢の判断理由も比較しておきましょう。

| 選択肢 | 判断と理由 |
| --- | --- |
| ア R社との事業提携の交渉を打ち切る。 | 現時点で消極的だからといって交渉を打ち切ってしまうと、成果次第でR社の協力を得られるはずの可能性まで自ら捨ててしまいます |
| **イ 適宜プロジェクトの進捗と成果を報告する。** | **成否や成果への強い関心に応え、順調な推移を示すことで提携に積極的な態度へ変わってもらうための判断材料を届けられます** |
| ウ プロジェクトの進捗と成果の情報を秘匿し，ステークホルダとのコミュニケーションを避ける。 | 情報を隠して対話を避けてしまっては、S氏の関心に応えられず、態度が前向きに変わる機会を失ってしまいます |
| エ プロジェクトの進捗と成果の報告は最低限にとどめる。 | 影響力も関心も大きいS氏に対して報告を最低限に抑えてしまうと、積極的な協力関係を築くための働きかけとして不十分です |

## 設問2(2)｜アジャイルを選ぶ背景は、仮説検証を繰り返す必要

設問2(2)は、下線③「アジャイル開発アプローチを採用することにした」を実施する背景を、本文中の字句を使って30字以内で答える問題です。

初めて参入する消費者向けサービスでは、最初から「こう作れば必ず利用者が運動を続けてくれる」という正解の仕様が確定しているわけではありません。「このような画面や通知にすれば利用者の役に立つはずだ」という仮説を立て、実際に利用者に使ってもらい、反応を見て改善するサイクルを**仮説検証**と呼びます。

本文の［本プロジェクトの立ち上げ］を確認すると、なぜ一括開発（ウォーターフォール）ではなく、短い期間で作成・確認・見直しを重ねる**アジャイル開発アプローチ**が必要なのかについて、直接の根拠となる一文があります。
- **本文の根拠**：「事業可能性を高めるためには，先進ユーザーに参加してもらった上で，体験価値を確実に実現できるまで**仮説検証プロセスを反復してから新サービスを開始する必要がある**。」

この一文から、アジャイル開発を採用する背景を30字以内で組み立てると次のようになります。

- **公式解答例**：「サービス開始までに仮説検証プロセスの反復が必要だから」（26字）

なお、表2にはプロジェクトメンバーの役割として、事業全体の価値や提携を整理する「ビジネスアーキテクト」、利用者の体験や画面の操作性を設計する「UX/UIデザイナー」、バイタルデータの分析・活用を担う「データサイエンティスト」、システム機能や開発・運用環境を構築する「ソフトウェアエンジニア」が登場します。異なる専門性を持つメンバーが先進ユーザーの反応を持ち寄り、素早く次の仮説検証へ反映させるためにアジャイル開発が選ばれています。

## 設問3(1) a・b｜リスクの発生を抑えるか、発生時の影響を引き受けるか

設問3(1)は、表3（リスク登録簿）の項番1（空欄a）と項番2（空欄b）に入る「リスクへの対応戦略」を2字で答える問題です。

**リスク**とは、まだ確定していない事象のうち、発生するとプロジェクトの目標に影響を与える可能性のことです。マイナスのリスク（脅威）に対する代表的な対応戦略（**回避・転嫁・軽減・受容（保有）**）のうち、表3の「対応策」がリスクに対して何をどう変えているかを見て判断します。

1. **項番1（空欄a）の判断**：
   - **リスク**：R社との調整が難航し、R社からの派遣メンバーが活動できず進捗が遅延する。
   - **対応策**：B取締役、R社経営層、S氏が参加する意思決定の場（**ステアリングコミッティー**：重要な関係者が集まり、プロジェクトの方針や課題を迅速に判断する場）を設け、調整の難航や意思決定の遅延を防ぐ。
   - **結論**：リスクが発生する確率や影響度を小さくする対策なので、空欄aには **軽減** が入ります。

2. **項番2（空欄b）の判断**：
   - **リスク**：先進ユーザーの要求が収束せず、予定していたサービス開始日までにシステム開発が完了しない。
   - **対応策**：必要に応じてサービス開始日を延期して開発を継続することとし、そのための追加開発費用を「予備費」として確保しておく。
   - **結論**：開発が予定日に間に合わない可能性をプロジェクトとして引き受けたうえで、実際に発生したときに使う予備費を用意して備える対策（能動的受容）なので、空欄bには **受容**（または **保有**）が入ります。

4つのリスク対応戦略の違いを整理しておきましょう。

| リスク対応戦略 | 意味と本問での当てはめ |
| --- | --- |
| **軽減** | リスクの発生確率や発生時の影響度を小さくする戦略。**項番1（空欄a）**の意思決定の場の設置が該当します |
| **受容（保有）** | リスクを無理にゼロにせず引き受け、発生時に備えて予備費や予備期間を確保する戦略。**項番2（空欄b）**の開始日延期と予備費確保が該当します |
| 回避 | リスクの原因となる活動自体を取りやめたり計画を抜本的に変えたりして、リスクが発生する可能性を完全にゼロにする戦略（今回は事業や仮説検証自体をやめていません） |
| 転嫁 | 保険への加入や外部との契約などによって、リスク発生時の金銭的負担や対応責任を第三者へ移す戦略（今回は遅延の負担を他社へ移していません） |

「受容」というと「何も対策をせず放置すること」と思われがちですが、項番2のように「起きたときの対応方針（延期）と予備費をあらかじめ準備したうえでリスクを引き受けること」も典型的な**受容（保有）**です。

## 設問3(2)｜不安を減らせば、認識している貢献を行動へ移せる

設問3(2)は、表3項番3の下線④「メンバーの活動を阻害する不安要因を排除して，メンバーが活動しやすい環境を作る。」について、C課長がこの対応策によってリスクに対応できると考えた理由を、本文中の字句を使って40字以内で答える問題です。

まず、［プロジェクト計画の作成］の段落から、チームメンバーの現状とC課長の考えを整理しましょう。
1. **すでに持っているもの（強み）**：表2のとおり、各メンバーは自分が担う役割と「**本プロジェクトへの貢献についての認識**」をすでにしっかり持っています。そしてC課長は、「**各メンバーが本プロジェクトへの貢献についての認識に基づいて活動できれば，本プロジェクトの目標は達成できる**」と考えていました。
2. **妨げになっているもの（リスク）**：一方で、A社・旧T社・R社派遣社員という異なる背景のメンバーが初めて協働することや、これまでの作業環境との違いに**不安**を感じており、その不安が実際の活動を阻害する要因になっています。

つまり、メンバーにスキルや目的意識が欠けているのではなく、「不安」というブレーキが掛かっている状態です。したがって、下線④のように「活動を阻害する不安要因を排除して活動しやすい環境を作る」ことができれば、ブレーキが外れ、**各メンバーがすでに持っている「本プロジェクトへの貢献についての認識」に基づいて活動できるようになる**ため、リスクに対応して目標を達成できると考えたのです。

この因果関係を本文中の字句を使って40字以内でまとめます。

- **公式解答例**：「各メンバーが本プロジェクトへの貢献についての認識に基づいて活動できるから」（36字）

単に「メンバーの不安が解消されるから」とだけ書くと下線④の言い換えに留まってしまいます。「不安要因を排除した結果、何に基づいて活動できるようになるのか」まで本文の言葉で抜き出すのがポイントです。

## 設問3(3) c｜守るべき最優先の目標は、顧客の体験価値

設問3(3)は、本文末尾のB取締役の発言「“［c］が本プロジェクトの最優先の目標なので，特に，表3項番2を注視するように”」に入る字句を15字以内で答える問題です。

1. **本文の根拠を探す**：［本プロジェクトの立ち上げ］の3つ目の箇条書きに、「顧客中心の考え方に基づいて，**顧客への体験価値の提供**を，本プロジェクトで最優先に達成する目標に設定した」とそのまま明記されています（**体験価値**とは、利用者が製品やサービスを実際に体験する中で得られる価値のことです）。
2. **表3項番2とのつながりを確かめる**：従来の機器開発であれば「予定された開始日（納期）を守ること」が優先されがちですが、本プロジェクトの最優先目標は「顧客への体験価値の提供」です。だからこそ、もし予定日までに体験価値を十分に実現できていなければ、サービス開始日を延期してでも仮説検証と開発を継続できるよう、項番2のリスク対応（延期と予備費の確保）を特に注視するよう指示しているのです。

したがって、空欄cには次の字句が入ります。

- **公式解答例**：「顧客への体験価値の提供」（11字）

## 次の問題でも使うこと

- 従来事業と新規事業を比較するときは、**市場面（誰に・どの分野へ届けるか）**と**製品・サービス面（何を提供するか）**を切り分けて整理する。
- ステークホルダへの対応は、現在の態度（支持か抵抗か）だけでなく、**影響力の大きさ・関心の強さ・成果に応じた態度変化への期待**を本文から読み取って選ぶ。
- 新サービス開発で**アジャイル開発アプローチ**を採用する背景には、利用者とともに**仮説検証プロセスを反復**して体験価値を高める必要性がある。
- リスク対応戦略は、発生確率や影響度を減らす**軽減**と、予備費や予備期間を用意してリスクを引き受ける**受容（保有）**を区別する。
