# 問3 最長共通部分列の長さを求めるアルゴリズム

## この問題は、何を考える問題だった？

2つの文字の並び（列）から、**同じ順序で取り出せる共通の文字をできるだけ多く選ぶ**問題です。

例えば、A・B・C という並びからは、真ん中の B を飛ばして A・C を取り出すことができます。このように、もとの順序を保ったままいくつか要素を取り出して並べたものを**部分列**といいます。文字が隣り合って連続している必要はありませんが、C・A のように**もとの順序を入れ替えて取り出すことはできません**。

2つの列の両方から共通して取り出せる部分列を「共通部分列」といい、そのうち最も長いものを**最長共通部分列（LCS：Longest Common Subsequence）**と呼びます。この問題で求めるのは、選んだ文字の並びそのものではなく、その**長さ（文字の個数）**です。最長となる文字の選び方が複数通りあったとしても、最大の長さは1つに決まります。

すべての選び方を最初から毎回調べ直すと膨大な手間がかかるため、「先頭から何文字目までを使うか」で問題を小さく分け、計算した結果を表に記録して再利用します。この**動的計画法（DP）**の考え方を、具体例の計算（設問1）→ 表の穴埋め（設問2）→ プログラムの完成（設問3）→ 計算量の評価（設問4）へと順番につないでいく構成になっています。

## まず、表の1マスが何を表すかを整理しよう

本文の **LCSL(n, k)** は、「列Xの先頭 n 文字」と「列Yの先頭 k 文字」を比べたときの最長共通部分列の長さを表します。例えば X が ABCBDAB、Y が BDCABA のとき、LCSL(3, 4) は X の先頭3文字（ABC）と Y の先頭4文字（BDCA）を比べたときの最長共通部分列の長さです。n と k はそれぞれ「先頭から何文字目までを対象にするか」を表しており、X と Y で異なる文字数を取り出して比べることができます。

表の行番号を n（Xから使う文字数）、列番号を k（Yから使う文字数）とすると、各マスの値は次の3つの場合に分けて求められます。

| 場合 | 今のマス（n行k列）に入れる値 | その理由 |
| --- | --- | --- |
| 片方が0文字（n＝0 または k＝0） | 0 | 片方が空（0文字）なら、共通して取り出せる文字は1つもないため |
| 比べている末尾の文字が同じ | **左上のマス＋1** | 両方の末尾の文字を共通部分列の最後として採用し、両方の末尾を除いた結果（n－1行k－1列）に1文字付け加えられるため |
| 比べている末尾の文字が違う | **左のマスと上のマスの大きい方** | 両方の末尾を同時に使うことはできないため、Yの末尾を使わない場合（左：n行k－1列）と、Xの末尾を使わない場合（上：n－1行k列）のうち、長くできる方を選ぶため |

- **左のマス（n行k－1列）**：Y側の対象だけを1文字減らしたときの結果
- **上のマス（n－1行k列）**：X側の対象だけを1文字減らしたときの結果
- **左上のマス（n－1行k－1列）**：X側・Y側の両方を1文字ずつ減らしたときの結果

**いま比べている末尾同士が一致するかどうかを先に確認し、一致すれば「左上＋1」、不一致なら「左と上の大きい方」を参照する**のが基本ルールです。

最初に、空の列に対応する0行目と0列目をすべて 0 で埋め、上の行から順番に、各行を左から右へと埋めていけば、計算に必要な「左上・左・上」のマスは必ず計算済みになります。

## 設問1｜共通する4文字を見つけ、最大であることも確かめる

設問1で比べる列は **ACBCDC** と **CDBDCA** です（本文の説明で使われている例とは別の文字列なので注意しましょう）。

まず、両方から共通して取り出せる並びを探すと、**C・B・D・C** の4文字が見つかります。

- ACBCDC では **2・3・5・6文字目**（A・**C**・**B**・C・**D**・**C**）
- CDBDCA では **1・3・4・5文字目**（**C**・D・**B**・**D**・**C**・A）

どちらも選ぶ位置が左から右へと順番に増えており、同じ1文字を2回使うこともしていないため、正しい共通部分列になっています。

これで長さ4の共通部分列が存在することは分かりますが、長さ5以上のものが作れないことも確かめておきましょう。先ほどの規則に従って、ACBCDC（縦）と CDBDCA（横）について先頭0文字（空）から順番に表を埋めると、次のようになります。

| X側の末尾／Y側の末尾 | 空 | C | D | B | D | C | A |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 空 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| A | 0 | 0 | 0 | 0 | 0 | 0 | 1 |
| C | 0 | 1 | 1 | 1 | 1 | 1 | 1 |
| B | 0 | 1 | 1 | 2 | 2 | 2 | 2 |
| C | 0 | 1 | 1 | 2 | 2 | 3 | 3 |
| D | 0 | 1 | 2 | 2 | 3 | 3 | 3 |
| C | 0 | 1 | 2 | 2 | 3 | 4 | 4 |

例えば、Xの3文字目 B と Yの3文字目 B を比べるマスでは、末尾が B 同士で一致するため、左上の値 1 に 1 を加えて 2 になります。一方、右下のマスでは X の最後の文字 C と Y の最後の文字 A が異なるため、左の 4 と上の 3 のうち大きい方の 4 を選びます。

表の右下のマスが両方の列全体を使ったときの最長共通部分列の長さになるため、答えは **4** です。具体的な共通部分列を見つける作業と、表で最大長を確かめる作業を合わせて行うことで、見落としを防げます。

## 設問2｜図3の行番号と列番号を先に読む

### 設問2 ア｜先頭3文字と先頭4文字を比べる

ここからは本文の例である **X＝ABCBDAB**、**Y＝BDCABA** に戻ります。図3の空欄アは **n＝3、k＝4** のマスなので、Xの先頭3文字（ABC）と Yの先頭4文字（BDCA）を比べます。

両方の末尾を比べると、Xの3文字目は **C**、Yの4文字目は **A** で一致しません。そこで、左のマスと上のマスの値を比べます。

- **左のマス LCSL(3, 3)**：ABC と BDC の比較で、B・C の2文字が共通して取れるため **2**
- **上のマス LCSL(2, 4)**：AB と BDCA の比較で、BDCA の中には A の後ろに B が現れないため、1文字しか取れず **1**

末尾が異なる場合は左と上の大きい方を選ぶため、空欄アには **2** が入ります。

### 設問2 イ｜一致する末尾を、左上の結果へ足す

空欄イは **n＝7、k＝5** のマスなので、Xの先頭7文字（ABCBDAB）と Yの先頭5文字（BDCAB）を比べます。

両方の末尾を比べると、Xの7文字目も Yの5文字目も **B** で一致しています。したがって、両方の末尾を1文字ずつ除いた左上のマス **LCSL(6, 4)**（ABCBDA と BDCA の最長共通部分列の長さ＝**3**）に 1 を加えて、空欄イには **4** が入ります。

実際に文字で確認しても、前半の ABCBDA と BDCA から長さ3の共通部分列（B・D・A）が取れ、その後ろに両方の末尾で一致した B を1文字付け加えて **B・D・A・B**（長さ4）を作ることができます。これが「左上＋1」の意味です。

## 設問3｜文字配列の添字と、長さの表の添字を対応させる

図4のプログラムを読むときは、**文字を入れた配列 S・T の添字**と、**長さを記録する2次元配列 lcsl の添字**のずれに注意が必要です。

- **文字配列 S・T**：要素番号は **0 から**始まります。したがって、先頭1文字目の文字は S[0]、**先頭 n 文字目の末尾の文字は S[n - 1]**（T側なら **T[k - 1]**）で表されます。
- **長さの表 lcsl[n, k]**：Sの先頭 n 文字と Tの先頭 k 文字に対する答えを表します。先頭0文字（空列）を表す0行目・0列目があるため、配列全体の大きさは (s＋1)行×(t＋1)列 です。

つまり、**「n 文字目・k 文字目の文字を取り出すときは n - 1・k - 1 を使い、表のマスを指定するときはそのまま n・k を使う」**と整理しておくと迷いません。

### 設問3 ウ｜末尾が一致したら、両方の対象を1文字減らす

if 文の条件 S[n - 1] と T[k - 1] が等しいときは、比べている末尾の文字同士が一致しています。このとき、一致した末尾を使う前の長さは、両方の列から末尾を1文字ずつ除いた**左上のマス（n - 1 行、k - 1 列）**に入っています。そこへ今回の1文字分を足すため、空欄ウは次の式になります。

```
lcsl[n - 1, k - 1] + 1
```

もし誤って上（n - 1, k）や左（n, k - 1）に 1 を足してしまうと、片方の末尾の文字を二重に使ってしまうことになるため、必ず両方から1文字ずつ減らした左上を参照します。

### 設問3 エ・オ｜不一致なら、左と上を比べる

末尾が一致しない場合は、elseif 文に進みます。条件式は **lcsl[n, k - 1] ＞ lcsl[n - 1, k]**、つまり「左のマスの値が上のマスの値より大きいとき」です。

条件が成り立つときは大きい方である**左のマス**の値を選ぶため、空欄エは次の式になります。

```
lcsl[n, k - 1]
```

条件が成り立たないとき（else 側）は**上のマス**の値を選ぶため、空欄オは次の式になります。

```
lcsl[n - 1, k]
```

なお、左のマスと上のマスの値が同じ場合は else 側へ進んで上のマスの値が選ばれますが、求めたいのは部分列の長さ（数値）なので、同じ値のどちらを選んでも結果は変わりません。

### 設問3 カ｜全体を使った答えの場所を返す

二重の for ループがすべて終わると、Sの全 s 文字と Tの全 t 文字を使ったときの答えが、表の右下（s行 t列）に入っています。したがって、最後に返す空欄カは次の式になります。

```
lcsl[s, t]
```

文字配列 S の最後の文字が S[s - 1] だからといって、返す場所まで lcsl[s - 1, t - 1] にしないよう気をつけましょう。表 lcsl の添字は「先頭から使う文字数」そのものを表しています。

## 設問4｜二重の繰返しを、表のマス数として数える

**時間計算量**とは、入力データ（ここでは文字列の長さ s や t）が大きくなったときに、計算にかかる処理回数がどのくらいの割合で増えるかを表したものです。O（オーダー）記法では、定数倍や影響の小さい項を省いて、増え方の最も支配的な項だけを書きます。

図4のプログラムの中心となる二重ループでは、外側のループで n を 1 から s まで動かし、そのそれぞれについて内側のループで k を 1 から t まで動かしています。つまり、s行×t列の **st 個のマス**を順番に計算しています。1つのマスを計算する処理は、末尾の1文字同士の比較、すでに計算済みの隣接マスの参照、1の加算や代入といった、文字列の長さによらない一定回数の基本操作だけで終わります。

例えば、s＝7、t＝6 なら計算するマスは 7×6＝42 個で、両方の文字列の長さを2倍（14 と 12）にすると 14×12＝168 個（もとの4倍）になります。このように処理回数は s と t の積に比例して増えるため、時間計算量は **O(st)** となり、O の括弧内の空欄キには **st** が入ります（s＋t ではありません）。

なお、ループの前に0行目と0列目を 0 で初期化する処理には s＋t 回ほどの処理（O(s＋t)）がかかりますが、s と t が1以上の文字列では二重ループの st 回の処理の方が支配的になるため、全体の時間計算量は **O(st)** とまとめられます。一度計算した部分問題の結果を表に残して使い回すことで、指数関数的な総当たりを避けて O(st) で求められるのが動的計画法の強みです。

## 次の問題でも使うこと

- **部分列と部分文字列の違い**：「部分列」は途中の文字を飛ばして選んでもよいが、順序は変えられない（連続する部分だけを取り出す「部分文字列」と混同しない）。
- **DP表の定義の確認**：表の行番号 n・列番号 k が何を表すかを先に言葉で整理してから、左上（n - 1, k - 1）・左（n, k - 1）・上（n - 1, k）のどのマスを参照するかを決める。
- **0始まりの配列とDP表の添字の対応**：0始まりの文字配列では「n文字目の文字」が添字 **n - 1** になる一方、空列（0文字）を含むDP表では「先頭 n 文字分」が添字 **n** になる。
- **二重ループの時間計算量**：外側の繰返し回数×内側の繰返し回数×1回あたりの処理量で見積もる。
