# 問5 クラウドサービスへのサーバ移行

## この問題は、何を考える問題だった？

A社は、これまで本社（DMZおよび内部LAN）で運用していたサーバ群を、クラウドサービス上の仮想ネットワーク環境 **BCL-A** へ移行します。ただし、次の3つの条件は移行前と変えません。

- **業務サーバ**はクラウドへ移さず、本社に残す
- 社員が社内PCを使うときの**操作方法や接続先の設定は変えない**
- インターネット側からアクセスするときに使う**公開IPアドレスも移行前と同じにする**

サーバの置かれている場所（ネットワーク）が変わっても、これまで通り通信できるようにファイアウォール、アドレス変換（NAT）、ルーティング（経路表）を設計する問題です。図に登場する機器が多く見えますが、**「誰（送信元）が、どのサーバ（宛先）へ、何の用途で直接通信するか」**を1つずつ分けて追いかけると、すっきり整理できます。

## まず、直接使うサーバと、その先の中継先を分けよう

通信において、**IPアドレス**は通信相手を特定するための住所、**パケット**は通信データを小分けにした単位です。異なるネットワークの間でパケットを届けるには、レイヤー3スイッチ（L3SW）やルータが**経路表（ルーティングテーブル）**を見て次の転送先を決めます。

まず、社内PCが**直接の通信相手（宛先）**としてアクセスするサーバと、さらにその奥で中継されるサーバの関係を整理しておきましょう。

| 用途 | 社内PCが直接通信する相手 | その先の通信の流れ |
| --- | --- | --- |
| Webサイトの利用 | **プロキシサーバ** | プロキシサーバが社内PCの代わりにインターネット上のWebサイトへアクセスする |
| メールの送受信 | **メールサーバ** | 社外とメールをやり取りするときは、さらに**メール中継サーバ**を経由する |
| 名前解決（DNS） | **内部DNSサーバ** | 内部DNSサーバが管理していない社外ドメインの問い合わせは、**キャッシュDNSサーバ**へ転送する |
| 社内業務 | **業務サーバ** | 社内PCとだけ通信し、今回の移行でも本社に残る |

特に**名前解決**（ドメイン名からIPアドレスなどを調べる仕組み）に関わる3つのDNSサーバは、役割がはっきり分かれています。

- **内部DNSサーバ**：社内PCからの問い合わせを最初に受け付け、社内用の名前解決を行う（社外の名前はキャッシュDNSサーバへ転送する）
- **キャッシュDNSサーバ**：内部DNSサーバから転送された問い合わせを受け、インターネット上のDNSサーバへ問い合わせて結果を返す
- **外部DNSサーバ**：インターネット上の外部から「A社.jp」に関する問い合わせを受け付け、公開サーバのIPアドレスを答える

また、インターネットと社内ネットワークの中間に設ける公開サーバ用の隔離領域を **DMZ（非武装地帯）** と呼びます。今回の移行では、本社のDMZにあったサーバ群と、内部LANにあったメールサーバ・内部DNSサーバをまとめてクラウド（BCL-A）へ移します。

## 設問1(1)｜設定を配る機器と、PCの出口を区別する

**DHCP（Dynamic Host Configuration Protocol）** は、ネットワークに接続したPCへ、IPアドレス・サブネットマスク・デフォルトゲートウェイなどの設定情報を自動で配付する仕組みです。本問では、本社の **L3SW1** 上で動くDHCPサーバが営業所のPCにも設定情報を配付しています。しかし、「設定を配ってくれる機器」と「実際に配られるデフォルトゲートウェイ（通信の出口）」は同じとは限りません。

- **デフォルトゲートウェイ**：PCが自分の属するネットワーク（同一セグメント）の外にある相手と通信するときに、最初にパケットを送り出す「出口」となるルータやL3スイッチのこと

図1を見ると、営業所のPCは **192.168.1.0/24** というネットワークに属しています。このネットワークから本社のネットワークやクラウドへ出ていく出口に接続されているレイヤー3スイッチ（ネットワークをまたぐ転送を行うスイッチ）は、営業所の **L3SW0** です。

なお、営業所PCのすぐ隣にはレイヤー2スイッチの **L2SW0** がありますが、L2スイッチは同じネットワーク（192.168.1.0/24）の中でフレームを中継する機器であり、ネットワークをまたぐデフォルトゲートウェイにはなりません。したがって、営業所のPCに配付されるデフォルトゲートウェイの機器名は **L3SW0** です。

## 設問1(2)｜防ぐべきメール中継を、送信元と宛先で特定する

DMZにあるメール中継サーバは、社内と社外の間でメールを受け渡しする役割を持っています。送信元と宛先の組合せを3つに分けて、どの通信を許可し、どの通信を拒否すべきかを整理しましょう。

| 送信元 → 宛先 | 本問での扱いと理由 |
| --- | --- |
| **A社のメールサーバ → 社外** | 社員が社外へメールを送信するために**必要** |
| **社外のメールサーバ → A社** | 社外からA社宛てのメールを受信するために**必要** |
| **社外のメールサーバ → 社外** | A社と無関係な第三者どうしのメール中継であり、迷惑メール（スパム）の踏み台にされるため**拒否すべき** |

このように、外部の第三者から送られてきた外部宛てのメールを無制限に中継してしまう状態を**オープンリレー（第三者中継）**と呼びます。もし「社外から送られてきたメールをすべて拒否する」という設定にしてしまうと、社外からA社宛てに届く正規のメールまで受信できなくなってしまいます。

したがって、「社外のメールサーバから送られてきた、社外宛てのメールを中継すること」に絞って拒否する必要があります。40字以内の公式解答例は、**「社外のメールサーバから送信された社外宛てのメールを中継する処理」（31字）**です。

なお、採点講評では **OP25B（Outbound Port 25 Blocking）** と混同した誤答が指摘されています。OP25Bは、プロバイダ（ISP）が自網内の動的IPアドレス等から他事業者のメールサーバへ直接送られるTCP/25番ポートの通信を遮断する「回線事業者側の対策」です。本問で問われているのは、A社のメール中継サーバ自身に設定されている「不正な第三者中継の防止処理」なので、送信元と宛先の関係から答えます。

## 設問1(3)｜通信の方向と、ポート番号を組み合わせる

**ポート番号**は、通信相手のコンピュータの中で「どのアプリケーション（サービス）宛ての通信か」を識別するための番号です。表1のファイアウォール（FW）のフィルタリングルールは、**「送信元（どこから）」「宛先（どこへ）」「プロトコル／ポート番号（何のサービスへ）」**の3つを組み合わせて読み解きます。

### 設問1(3) a｜インターネットから443番へ来る通信

**HTTP** はWebページなどのデータをやり取りするプロトコル、**TLS（Transport Layer Security）** は通信の暗号化や通信相手の証明書確認によって通信を安全に保護する仕組みです。この2つを組み合わせた **HTTP Over TLS（HTTPS）** では、標準で **TCP/443番ポート** を使います。

本文では「Webサーバ」と「業務サーバ」の両方がHTTP Over TLSを受け付けていますが、表1の空欄aの宛先は**DMZ内**の機器です。業務サーバは本社の内部LANにあって社内PCとしか通信しないため、インターネットからDMZへTCP/443でアクセスしてくる通信の宛先aは **Webサーバ** です。

### 設問1(3) b｜外部から名前を調べてもらう相手

**TCP/53・UDP/53** は **DNS（名前解決）** に使われるポート番号です。表1のこの行は「送信元：インターネット」から「宛先：DMZ内の［ b ］」への通信を許可しています。

冒頭で整理した3つのDNSサーバのうち、インターネット上の外部から「A社.jp」の名前解決の問い合わせを受け付けるのは **外部DNSサーバ** なので、空欄bには **外部DNSサーバ** が入ります（社内PCが使う内部DNSサーバや、内部DNSからの転送を受けるキャッシュDNSサーバと混同しないよう注意しましょう）。

### 設問1(3) c｜社内PCの代わりにWebサイトへ出ていく相手

表1の空欄cを含む行は、「送信元：DMZ内の［ c ］」から「宛先：インターネット」へ **TCP/80（HTTP）・TCP/443（HTTP Over TLS）** で出ていく通信を許可しています。

本文の条件より、社内PCはインターネット上のWebサイトへ直接アクセスせず、DMZ内のプロキシサーバを経由します。したがって、DMZからインターネット上のWebサイトへアクセスしに行く送信元cは **プロキシサーバ** です。

なお、表1の注記には「許可された通信に対する応答パケットは自動的に通過が許可される」とあります（ステートフルインスペクション機能）。そのため、表1の各行はすべて**「最初に通信の要求を開始する向き」**だけが書かれています。

## 設問2(1)｜公開アドレスから、移行先の実際の宛先へ対応させる

クラウド（BCL-A）への移行後も、インターネット側から見た各公開サーバの**公開IPアドレス（グローバルIPアドレス）**は移行前と同じものを使い続けます。一方、BCL-A内部に配置された各サーバには、組織内用の**プライベートIPアドレス**（172.20.0.0/20の範囲）が割り当てられています。

図2の **IGW（インターネットゲートウェイ）** は、インターネットとBCL-Aの境界でIPアドレスを変換する **NAT（Network Address Translation）** 機能を持っています。社外からA社宛てに送られてくるメール（SMTP通信）がどのサーバへ向かうかを、順番にたどりましょう。

1. 社外からのメールが最初に届く宛先は、公開されている**メール中継サーバ**です。
2. 図1の表を見ると、メール中継サーバの公開IPアドレスは **200.α.β.2** です。インターネットからIGWに届くまではこのアドレスが宛先になっているため、IGW通過前の宛先IPアドレスは **200.α.β.2** です。
3. 図2の表で同じ「メール中継サーバ」を探すと、移行後のプライベートIPアドレスは **172.20.1.14** です。IGWで宛先アドレスが変換されるため、IGW通過後の宛先IPアドレスは **172.20.1.14** になります。

ここで注意したいポイントが2つあります。

- **内部のメールサーバ（172.20.2.11）を選ばない**：172.20.2.11は社員のPCがアクセスする内部メールサーバであり、インターネットから直接SMTPを受け取るサーバではありません。
- **表の行の順番だけで選ばない**：図1の表と図2の表では、サーバの並び順が異なっています。必ず「メール中継サーバ」というサーバ名を対応させてIPアドレスを読み取ります。

## 設問2(2)｜クラウドへ届くパケットの、もとの送信元を読む

本社とクラウド（BCL-A）の間は、インターネットを介して **IPsecルータ2** と **IPsecルータ1** を結び、暗号化された仮想的な専用線（IPsecトンネル）で接続します。

この設問で問われているのは、IPsecルータ1を通ってBCL-A内のサーバへ届けられるパケット（トンネルの中を通ってきた元のIPパケット）の**送信元ネットワークアドレス**です。

移行後も社員の操作方法は変えないため、**営業所のPC**も**本社のPC**も、BCL-Aへ移行したサーバ群（プロキシサーバ、メールサーバ、内部DNSサーバ）へ通信します。図2から、それぞれのPCが属するネットワークアドレスを読み取ると次の2つになります。

- 営業所のPCが属するネットワーク：**192.168.1.0/24**
- 本社のPCが属するネットワーク：**172.16.128.0/20**

末尾の「/24」や「/20」は、32ビットのIPアドレスのうち先頭から何ビットがネットワーク部（ネットワーク全体のくくり）を表すかを示すプレフィックス表記です。設問は「送信元ネットワークアドレスをすべて答えよ」と求めているため、図中のネットワーク表記のままこの2つを答えます。

なお、本社にあるもう1つのネットワーク **172.16.0.0/24** は業務サーバのネットワークです。業務サーバは本社に残り、社内PCとしか通信しない（BCL-Aのサーバへ向かって通信しない）ため、ここには含めません。

## 設問2(3)｜PCが直接使う三つの相手の、場所の変化を追う

下線③では、サーバ移行に伴って営業所の **L3SW0** と本社の **L3SW1** の経路表（ルーティングテーブル）を変更します。その理由は「社内PCを送信元とする通信について、通信相手の場所がBCL-Aへ移ったため、転送先をIPsecルータ2へ向ける必要があるから」です。

では、**社内PCが直接の宛先として通信するサーバ**のうち、今回の移行で場所がBCL-Aへ変わったものはどれでしょうか。冒頭の表と照らし合わせて確認しましょう。

| 社内PCが直接通信する相手 | 移行前の場所 | 移行後の場所 | 社内PCからの経路変更が必要か |
| --- | --- | --- | --- |
| **プロキシサーバ** | 本社 DMZ | **BCL-A** | **必要**（宛先がクラウドへ移動したため） |
| **メールサーバ** | 本社 内部LAN | **BCL-A** | **必要**（宛先がクラウドへ移動したため） |
| **内部DNSサーバ** | 本社 内部LAN | **BCL-A** | **必要**（宛先がクラウドへ移動したため） |
| 業務サーバ | 本社 内部LAN | 本社 内部LAN（残留） | 不要（本社に残るため） |

したがって、答えは **プロキシサーバ、メールサーバ、内部DNSサーバ** の3つです。

メール中継サーバやキャッシュDNSサーバもBCL-Aへ移行しますが、社内PCはそれらへ直接パケットを送るわけではありません（メールサーバや内部DNSサーバが中継して通信します）。「BCL-Aへ移行したサーバ」を闇雲に選ぶのではなく、設問文の**「社内PCを送信元とする通信について」**という条件から、PCが直接アクセスする3つのサーバを特定するのが急所です。

## 次の問題でも使うこと

- **DHCPサーバとデフォルトゲートウェイの区別**：設定情報を配付するDHCPサーバ（本社L3SW1）と、各セグメントのPCが外へ出るときの出口となるデフォルトゲートウェイ（営業所L3SW0）は役割が異なる。また、L2スイッチはネットワークをまたぐゲートウェイにはならない。
- **メールのオープンリレー対策**：「社内→社外（送信）」と「社外→社内（受信）」は許可し、「社外→社外（無関係な第三者中継）」だけを拒否する。
- **3種類のDNSサーバの使い分け**：社内PCが向かう「内部DNS」、内部DNSが社外ドメインの問い合わせを転送する「キャッシュDNS」、社外から自社ドメインの問い合わせを受ける「外部DNS」を通信の向きで区別する。
- **直接の通信相手と間接的な中継先の区別**：PCからのルーティングやFWルールを考えるときは、PCが直接宛先に指定するサーバ（プロキシ・内部メール・内部DNS）に注目する。
