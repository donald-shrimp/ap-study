# 2分探索木

## この問題は、何を考える問題だった？

この問題は、データを素早く探し出すためのデータ構造である**2分探索木（Binary Search Tree）**と、木が片側に偏って探索が遅くなるのを防ぐ**平衡2分探索木（AVL木）**のアルゴリズムを題材に、**再帰呼び出しによる探索・挿入の仕組みと、木の「回転操作」によって左右の高さのバランスを保つ方法**を考える問題です。

2分探索木では、どのノード（節点）を見ても「**左側の部分木にあるキー値はすべて自分より小さく、右側の部分木にあるキー値はすべて自分より大きい**」というルールが成り立っています。そのため、根（一番上のノード）から探したい値と大小を比較していくだけで、1段降りるごとに探索範囲を半分ずつ絞り込むことができます。

ところが、小さい順や大きい順にデータを次々と挿入すると、木の枝が片側だけに長く伸びてしまい、せっかくの探索効率が落ちてしまいます。そこで、すべてのノードで「左右の部分木の高さの差を1以下にする」という条件（**条件Bal**）を設け、崩れたら**右回転・左回転**で枝をつなぎ直す仕組みを導入します。この大問では、次の3つのステップを順番に読み解いていきます。

- **探索・挿入の基本動作と探索の最悪時間計算量（設問1 ア・イ）**：枝が片側にだけ伸びた木と、左右均等に詰まった完全な2分探索木で、探索の手間（計算量）がどう変わるかを考えます。
- **回転操作の仕組みと関数balanceの条件式（設問2(1) ウ〜カ）**：大小関係を壊さずに高さを整える「右回転」「左回転」の動きと、1回の回転で済む場合・2段階の回転が必要な場合の見分け方をプログラム（図7）から特定します。
- **キー4と8を順番に挿入したときの木の変形と計算量（設問2(2)、設問2(3) キ）**：図1の木に「4」と「8」を挿入したときにどこでどの回転が起きるかをたどり、最終的な木の形と挿入全体の最悪時間計算量を求めます。

## まず、2分探索木のルールとプログラムの読み方を整理しよう

設問に入る前に、問題文と図1〜図8に登場するデータ構造と6つの関数の役割を整理しておきましょう。

### 1. ノードの構造（表1）と2分探索木の用語

- **根（ルート）**：木の一番上にあるノード（図1ではキー値 **6** のノード）です。
- **葉（リーフ）**：下に子ノードを持たない末端のノード（図1では **1**、**5**、**9**）です。
- **部分木**：あるノードを先頭（根）として、その下にぶら下がっているノードと枝のまとまりです。
- **構造体 Node（表1）**：1つのノードを表すデータ構造で、次の3つの要素を持ちます。
  - **key**：そのノードが持つ数値（キー値）
  - **left**：左側の子ノードへの参照（子がいなければ空のノードを表す **NULL**）
  - **right**：右側の子ノードへの参照（子がいなければ **NULL**）

### 2. 図2〜図8に登場する関数の役割一覧

この問題では、どの変更系の関数（**insert**、**rotateR**、**rotateL**、**balance**、**insertB**）も**「処理した後の部分木の新しい根への参照を return で返す」**という共通の形をしています。呼び出し元が「t.left ← 関数の戻り値」のように受け取ることで、親子のつながりが自動的に更新されます。

| 図番号 | 関数名 | 何をする関数か |
| --- | --- | --- |
| **図2** | **search(t, k)** | 根 t から大小比較で左（kが小さいとき）または右（kが大きいとき）へ再帰的にたどり、キー値 k のノードへの参照（なければ NULL）を返す。 |
| **図3** | **insert(t, k)** | 根 t から探索と同じ道順でたどり、NULL（空き場所）に到達したら new Node(k) を作ってつなぎ、木の根を返す（回転は行わない）。 |
| **図5** | **rotateR(t)** | ノード t を根とする部分木を**右回転**し、新しく根になったノード（元の t.left）への参照を返す。 |
| **図6** | **rotateL(t)** | ノード t を根とする部分木を**左回転**し、新しく根になったノード（元の t.right）への参照を返す。 |
| **図7** | **balance(t)** | ノード t の左右の部分木の高さの差を調べ、差が 2（または −2）になっていれば回転操作を行って条件Balを満たすように変形し、新しい根を返す。 |
| **図8** | **insertB(t, k)** | 関数 insert の末尾に「t ← balance(t)」を1行追加した関数。ノードを挿入したあと、再帰呼び出しから親へ戻る道筋の各ノードで順番にバランスを整える。 |

## 一度の比較で、次に調べる枝を選ぶ

ここでは、図2の探索関数 **search** と図3の挿入関数 **insert** の動きを確認したうえで、設問1の空欄 **ア**・**イ**（探索に掛かる最悪時間計算量）を求めます。

例えば、図1の木（根が6、6の左が3、6の右が9、3の左が1、3の右が5）からキー値 **5** を探す場面をたどってみましょう。

1. まず根 **6** と比較します。$5 < 6$ なので、右側の枝（9）は一切調べる必要がなく、左の子 **3** へ進みます。
2. 次に **3** と比較します。$5 > 3$ なので、左の子（1）は調べず、右の子 **5** へ進みます。
3. **5** と一致したため、探索成功として終了します。

このように、1回の比較で左か右のどちらか一方にしか進まないため、**1回の探索で調べるノードの個数は、最大でも「根から一番深い葉までの段数（木の高さ）」と同じ**になります。この性質を使って、ノードの総数が $n$ 個のときの最悪時間計算量を2つのケースで比べてみましょう。

**設問1 ア｜左右のどちらかにだけ子ノードが存在する場合**

葉を除くすべてのノードに「左か右の片方だけ」しか子ノードがない場合、木は枝分かれせず、1本の鎖のように縦に $n$ 段連なった形になります（例えば、空の木に 1, 3, 5, 6, 9 と小さい順で insert を繰り返すと、右の子ばかりが連なった高さ $n$ の木になります）。
このとき、一番奥にある葉のキー値や、木に存在しない大きなキー値を探索すると、根から葉まで **$n$ 個すべてのノード**を順番に調べることになります。したがって、最悪時間計算量は $O($**n**$)$ となり、空欄アは **n** です。

**設問1 イ｜すべての葉の深さが等しい完全な2分探索木の場合**

一方、葉を除くすべてのノードに左右両方の子ノードがあり、すべての葉の深さが等しい「完全な2分探索木」では、各段に置けるノード数が上から順に「1個、2個、4個、8個……」と2倍ずつ増えていきます。
木の段数（高さ）を $k$ とすると、入っているノードの総数 $n$ は次の式で表せます。
$$n = 1 + 2 + 4 + \dots + 2^{k-1} = 2^k - 1$$
これを段数 $k$ について解くと、$2^k = n + 1$ より $k = \log_2(n + 1)$ となります。例えば、ノード数が $n = 7$ 個なら高さは $3$ 段、$n = 1,023$ 個に増えても高さはわずか $10$ 段にしかなりません。
探索では各段で1つずつしかノードを調べないため、最悪でも調べる回数は木の高さである $\log_2(n + 1)$ 回に比例します。したがって、最悪時間計算量は $O($**log n**$)$ となり、空欄イは **log n** です。

## 大小関係を保ったまま、長くなった枝を短くする

完全な2分探索木でなくても、すべてのノードで「左右の部分木の高さの差が1以下」という**条件Bal**を保てば、木の高さが低く抑えられます。ここでは、条件Balが崩れたときに木を変形する「回転操作（図4〜図6）」と、それを使う関数 **balance**（図7）の空欄 **ウ**〜**カ**（設問2(1)）を読み解きます。

**なぜ「回転」しても2分探索木の大小関係が保たれるのか？（図4・図5・図6）**

図4(a)を見てください。根 **X** の左の子が **Y** であり、Yの左に部分木 $t_1$、Yの右に部分木 $t_2$、Xの右に部分木 $t_3$ があります。
2分探索木のルールから、これらのキー値の大小関係は必ず次の順になっています。
$$(\text{部分木 } t_1) < \mathbf{Y} < (\text{部分木 } t_2) < \mathbf{X} < (\text{部分木 } t_3)$$

ここで**右回転（rotateR）**を行うと、図4(b)のように左の子 **Y** を新しい根として持ち上げ、元の根 **X** を Y の右の子に下げます。このとき、もともと Y の右にあった部分木 $t_2$ は「Yより大きく、Xより小さい」値ばかりなので、**X の左の子（Yの右の下、Xの左）**に付け替えれば、回転後も大小関係が一切崩れません。
しかも、回転によって左端の $t_1$ は1段浅くなり（$d'_1 = d_1 - 1$）、右端の $t_3$ は1段深くなる（$d'_3 = d_3 + 1$）ため、「左側が高すぎた状態」を解消できます（左回転 **rotateL** はこれと左右対称の操作です）。

**設問2(1) ウ〜カ｜1回回転（外側の伸び）と2段階回転（内側の伸び）の見分け方**

図7の関数 **balance(t)** では、まず1行目で変数 **h1** を次のように計算しています。
$$\text{h1} \leftarrow \text{height(t.left)} - \text{height(t.right)}$$
つまり、**h1 は「左側の部分木の高さ − 右側の部分木の高さ」**です。条件Balを満たしていた木にノードを1つ挿入した直後、バランスが崩れたノードでは左右の高さの差が **2** になります。

**1. 左側の部分木の方が2大きい場合（空欄ウ・エ）**

- **空欄ウ**：左側の高さが右側の高さより2大きいとき、height(t.left) - height(t.right) である h1 の値は **2** になります。プログラムの他の条件式（図2・図3・図8の「〜が…と等しい」という表記）に合わせると、空欄ウの条件は **h1が2と等しい** です。
- **空欄エ**：左側の部分木（根は $U = \text{t.left}$）が高いときでも、次の2つのパターンがあります。
  - **外側（左の子のさらに左：t.left.left）が高い場合**：そのまま t を右回転（rotateR(t)）するだけで高さがそろいます。
  - **内側（左の子の右：t.left.right）が高い場合**：図4でいうと中央の部分木 $t_2$ が深い状態です。図4のとおり、t を1回右回転しただけでは **$t_2$ の深さは変わらない（$d'_2 = d_2$）**ため、高さの差が解消されません！そこで本文の手順(1)にあるとおり、「$U$（＝t.left）の右側の部分木の方が $U$ の左側の部分木よりも高い場合は、先に $U$ を根とする部分木に対して左回転（rotateL(t.left)）を行う」必要があります。
- 図7を見ると、「h2 ← ［ エ ］」の直後に「if(h2 が 0 より大きい) t.left ← rotateL(t.left)」と書かれています。「t.left の右側の高さが、t.left の左側の高さより大きいとき」に h2 が 0 より大きく（正に）なるように引き算を書けばよいので、空欄エは **height(t.left.right) - height(t.left.left)** です。

**2. 右側の部分木の方が2大きい場合（空欄オ・カ）**

- **空欄オ**：右側の高さが左側の高さより2大きいとき、「左の高さ − 右の高さ」である h1 の値は **-2** になります。したがって、空欄オの条件は **h1が-2と等しい** です。
- **空欄カ**：本文の手順(2)にあるとおり、「Tの右側の子ノード $V$（＝t.right）について、$V$ の左側の部分木（内側：t.right.left）の方が $V$ の右側の部分木（外側：t.right.right）よりも高い場合は、先に $V$ を根とする部分木に対して右回転（rotateR(t.right)）を行う」必要があります。
- 図7では「h3 ← ［ カ ］」の直後に「if(h3 が 0 より大きい) t.right ← rotateR(t.right)」と書かれているため、t.right の左側の高さから右側の高さを引く式にします。したがって、空欄カは **height(t.right.left) - height(t.right.right)** です。

空欄ウ〜カの4つを一覧表で整理して確認しましょう。

| 空欄 | プログラム上の役割 | 入れる適切な字句 |
| --- | --- | --- |
| **ウ** | Tの左部分木が右部分木より2高いかを判定する条件 | **h1が2と等しい** |
| **エ** | 左の子（t.left）において「内側（右）の高さ − 外側（左）の高さ」を求める式 | **height(t.left.right) - height(t.left.left)** |
| **オ** | Tの右部分木が左部分木より2高いかを判定する条件 | **h1が-2と等しい** |
| **カ** | 右の子（t.right）において「内側（左）の高さ − 外側（右）の高さ」を求める式 | **height(t.right.left) - height(t.right.right)** |

## 追加した場所から根へ戻って形を整える

ここでは、図8の関数 **insertB** を使って図1の木にキー値 **4**、続いて **8** を挿入する設問2(2)と、挿入全体の最悪時間計算量を求める設問2(3)（空欄 **キ**）を考えます。

**設問2(2)｜insertB(insertB(r, 4), 8) のステップごとの追跡**

関数 **insertB(t, k)**（図8）は、探索と同じ手順で葉の下の NULL まで降りて新しいノードを作ったあと、**再帰呼び出しから親へ1段ずつ戻りながら、通ってきた各ノードで「t ← balance(t)」を実行**します。なお、空のノード（NULL）の高さを **0**、葉（子を持たないノード）の高さを **1** として数えます。

**ステップ1：内側の insertB(r, 4) の実行（図1の木に「4」を挿入）**

1. **挿入位置の決定**：根 **6** からスタートし、$4 < 6$ で左の **3** へ、$4 > 3$ で右の **5** へ、$4 < 5$ で **5 の左の子**としてノード **4** が追加されます。
2. **親へ戻りながら balance を確認**：
   - **ノード 5 で balance(5)**：左の子が 4（高さ1）、右の子が NULL（高さ0）なので $h_1 = 1 - 0 = 1$。回転なし（ノード5を根とする部分木の高さは **2**）。
   - **ノード 3 で balance(3)**：左の子が 1（高さ1）、右の子が 5（高さ2）なので $h_1 = 1 - 2 = -1$。回転なし（ノード3を根とする部分木の高さは **3**）。
   - **ノード 6 で balance(6)**：左の子が 3（高さ3）、右の子が 9（高さ1）なので、**$h_1 = 3 - 1 = 2$** となり、ウの分岐に入ります！
3. **ノード 6 での2段階回転（左の子3で左回転 → 6で右回転）**：
   - 左の子 **3** の内側の高さ（右の子5：高さ2）から外側の高さ（左の子1：高さ1）を引くと、$h_2 = 2 - 1 = 1 > 0$ です。
   - まず **rotateL(3)** を実行します。すると **5** が持ち上がって 3 の親になり、もともと 5 の左にあった **4** は **3 の右の子**に付け替わります（この時点で 6 の左の子は **5**、5 の左の子は **3**［3 の子は 1 と 4］になります）。
   - 続けて **rotateR(6)** を実行します。すると **5** が木全体の新しい根になり、元の根 **6** は **5 の右の子**に下がります（6 の右の子は 9 のままです）。

**ステップ2：外側の insertB(..., 8) の実行（新しい根5の木に「8」を挿入）**

1. **挿入位置の決定**：新しい根 **5** からスタートし、$8 > 5$ で右の **6** へ、$8 > 6$ で右の **9** へ、$8 < 9$ で **9 の左の子**としてノード **8** が追加されます。
2. **親へ戻りながら balance を確認**：
   - **ノード 9 で balance(9)**：左の子が 8（高さ1）、右の子が NULL（高さ0）なので $h_1 = 1 - 0 = 1$。回転なし（ノード9を根とする部分木の高さは **2**）。
   - **ノード 6 で balance(6)**：左の子が NULL（高さ0）、右の子が 9（高さ2）なので、**$h_1 = 0 - 2 = -2$** となり、オの分岐に入ります！
3. **ノード 6 での2段階回転（右の子9で右回転 → 6で左回転）**：
   - 右の子 **9** の内側の高さ（左の子8：高さ1）から外側の高さ（右の子NULL：高さ0）を引くと、$h_3 = 1 - 0 = 1 > 0$ です。
   - まず **rotateR(9)** を実行します。すると **8** が持ち上がって **9** が 8 の右の子になります（6 の右の子が **8**、8 の右の子が **9**）。
   - 続けて **rotateL(6)** を実行します。すると **8** がこの部分木の新しい根になり、元の **6** は **8 の左の子**に下がります。この戻り値 **8** が、根 **5 の右の子**としてつながれます。
   - 最後に **ノード 5 で balance(5)**：左の子 3（高さ2）と右の子 8（高さ2）で $h_1 = 2 - 2 = 0$ となり、そのまま根 **5** が返されます。

4つの回転による木の移り変わりを表でまとめると、次のようになります。

| 段階 | 実行された操作 | 木全体の根 | 左部分木（根の左の子）の形 | 右部分木（根の右の子）の形 |
| --- | --- | --- | --- | --- |
| 初期状態（図1） | — | **6** | **3**（左に1、右に5） | **9**（子なし） |
| 4の挿入直後 | 5の左に **4** を追加 | **6**（$h_1 = 2$） | **3**（左に1、右に5［5の左に4］） | **9**（子なし） |
| 回転①・②の後 | **rotateL(3)** → **rotateR(6)** | **5** | **3**（左に1、右に4） | **6**（左なし、右に9） |
| 8の挿入直後 | 9の左に **8** を追加 | **5** | **3**（左に1、右に4） | **6**（$h_1 = -2$：右に9［9の左に8］） |
| 回転③・④の後（最終） | **rotateR(9)** → **rotateL(6)** | **5** | **3**（左に1、右に4） | **8**（左に6、右に9） |

完成した2分探索木を図示すると、次のようになります。

```text
5
├─ 左 3
│  ├─ 左 1
│  └─ 右 4
└─ 右 8
   ├─ 左 6
   └─ 右 9
```

親子関係を言葉で表すと、**根は5。5の左の子は3，右の子は8。3の左の子は1，右の子は4。8の左の子は6，右の子は9。** という完全な2分探索木になります。すべてのノードで左の子＜親＜右の子の大小関係と、条件Bal（高さの差が0）が成り立っていることが確認できます。

**設問2(3) キ｜関数insertBによる挿入の最悪時間計算量**

設問2(3)では、条件Balを満たすノード数 $n$ 個の2分探索木に対して関数 **insertB** を実行したときの最悪時間計算量 $O($**[ キ ]**$)$ を答えます（ただし、関数 height の処理時間は無視できるものとします）。

1. **条件Balを満たす木の高さ**：
   条件Balを満たす木では、どのノードでも左右の高さの差が1以内に保たれます。高さが $h$ の木を作ろうとすると、片方の子の部分木に高さ $h-1$、もう片方の子の部分木にも少なくとも高さ $h-2$ が必要になります。つまり、高さが2段増えるごとに必要な最小ノード数は少なくとも2倍以上に増えるため、ノード数が $n$ 個のときの木の高さは、完全な2分探索木と同様に **$O(\log n)$** に抑えられます。
2. **行き（挿入位置の探索）と帰り（balanceの実行）の手間**：
   - 根から葉まで降りていく「行き」の道筋では、木の高さと同じ最大 $O(\log n)$ 個のノードで1回ずつキー値を比較します。
   - 葉から根へ戻ってくる「帰り」の道筋でも、同じく通ってきた最大 $O(\log n)$ 個のノードで1回ずつ **balance** を呼び出します。
   - 設問の条件より関数 height の処理時間は無視でき、1回の balance で行われる回転（rotateL や rotateR）は最大2回、かつ各回転は図5・図6のとおり変数 a, b を使った定数回（$O(1)$）の参照の付け替えだけで完了します。

したがって、行きも帰りも木の高さに比例する回数しか処理を行わないため、挿入全体の最悪時間計算量は $O($**log n**$)$ となり、空欄キは **log n** です。

## 次の問題でも使うこと

- **2分探索木の高さと計算量の関係**：2分探索木の探索・挿入は「根から葉までの1本の経路」だけをたどるため、計算量は常に**木の高さ**で決まります。片側に偏った最悪の木では高さが $n$ になるため $O(n)$、完全2分木や平衡2分探索木（AVL木）では高さが対数に抑えられるため $O(\log n)$ になります。
- **回転操作（rotateR / rotateL）で付け替える枝の見つけ方**：
  - 右回転（左の子 $Y$ を持ち上げて親 $X$ を右下に下げる）では、$Y$ と $X$ の間の値を持つ「**元の $Y$ の右部分木（$t_2$）**」を「**$X$ の左の子**」へ移します。
  - 左回転（右の子を持ち上げて親を左下に下げる）では、逆の「**元の右の子の左部分木**」を「**元の親の右の子**」へ移します。
- **1回回転と2段階回転の判断基準**：高さの差が2になったノードから見て、高い方の枝が「**外側（左の左、または右の右）**」に伸びていれば1回の回転で解消できますが、「**内側（左の右、または右の左）**」に折れ曲がって伸びている場合は、先に子ノードを逆向きに回転させて外側の形に直してから親を回転させる**2段階回転**が必要です。
