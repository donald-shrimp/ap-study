# 問1 サイバー攻撃への対策

## この問題は、何を考える問題だった？

中古車販売会社C社のサーバにあるデータが、攻撃者によって暗号化され、使えなくなってしまいました。このようにデータを暗号化して利用不能にし、復旧と引き換えに金銭などを要求する不正なソフトウェアを**ランサムウェア**といいます。

今回の侵入の出発点は、業務でつながっていた提携先P社の機器でした。取引先や関連会社などを足掛かりにして標的の会社へ侵入する攻撃は、**サプライチェーン攻撃**と呼ばれます。本問では、次の3つの視点から事例を読み解きます。

- 攻撃者はどこから侵入し、どの経路でC社のサーバまで到達したか
- ログイン制限などの認証対策は、どのような攻撃に対して有効か（どこに限界があるか）
- 被害が起きたあと、復旧用のバックアップや調査用のログが使える状態で残っているか

**「対策を導入しているか」だけでなく、「その対策の仕組みが今回の攻撃方法や保存条件に対して本当に機能するか」を確かめる**のが、この大問の核心です。

## まず、登場する機器と攻撃の経路を整理しよう

本文にはPCやサーバが複数登場するため、最初にそれぞれの役割を整理しておきましょう。

| 機器 | この事例での役割 |
| --- | --- |
| P社のVPNルータ | 自宅など社外からP社のネットワークへ接続するための入口 |
| PC-P | P社内にあり、C社側のPCを遠隔操作するために使うPC |
| PC-R | C社内に設置された、P社からの遠隔接続を受け付けるPC |
| PC-S | C社の担当者がサーバの保守作業に使うPC |
| C社の各サーバ | 販売管理システムが稼働しており、今回データが暗号化された機器 |

**VPN**（Virtual Private Network）は、離れた場所から社内のネットワークへ安全に接続するための仕組みです。ただし、入口となるVPN機器そのものや認証の設定に弱点があれば、そこを突いて侵入されるおそれがあります。こうした保安上の弱点を**脆弱性**といいます。

調査で判明した事実と、本文で「可能性が高い」と推測されている入口の手口をつなげると、攻撃の全体像は次のようになります。

```text
P社のVPNルータの脆弱性を悪用してVPN接続（推定）
  → PC-Pへ辞書攻撃でログイン（攻撃手法は推定）
  → PC-Rへリモートデスクトップでログイン
  → PC-Sへリバースブルートフォース攻撃でログイン
  → PC-S内に保存されていたサーバのID・パスワードを窃取
  → C社の各サーバでランサムウェアを実行
```

この流れを押さえると、設問2が「侵入経路で使われた攻撃手法と通信プロトコル」、設問3が「その攻撃に対するログイン制限の有効性と限界」を問うていると見通せます。

### 設問2 b｜接続の説明と許可ルールを照合する

PC-PからPC-Rへどのように接続したかを確かめましょう。本文には「リモートデスクトップで接続した」とあります。リモートデスクトップは、離れた場所にあるPCの画面を手元のPCから操作する機能です。

ここで表1のFW（ファイアウォール）の許可ルールを見ると、PC-PからPC-Rへの通信として「TCP/3389（**RDP**）」が許可されています。RDP（Remote Desktop Protocol）は、リモートデスクトップ接続で使われる通信の取り決め（プロトコル）です。本文の記述と表1のルールが一致するため、設問2のbはRDPに対応する「**ウ**」が正解です。

なお、FWは送信元・宛先・通信の種類（ポート番号）などの条件に合う通信を通し、それ以外を遮断する仕組みです。表1のように**通信ルール上は許可されている経路であっても、正規のID・パスワードを奪われれば攻撃者の通り道になってしまう**点に注意しましょう。

## 同じ「ログインへの攻撃」でも、試し方が違う

一般的なログイン認証では、利用者を識別する「ID」と、本人であることを確認する「パスワード」を組み合わせます。設問2・設問3では、攻撃者が**「IDとパスワードのどちらを固定し、どちらを変えて試したか」**が判断の決め手になります。

違いが直感的に分かるよう、架空のID・パスワードを例に並べてみます。

| 攻撃の試し方 | 1回目 | 2回目 | 3回目 |
| --- | --- | --- | --- |
| 1つのIDに対し、パスワード候補を次々に変えて試す | ID: userA／PW: 候補1 | ID: userA／PW: 候補2 | ID: userA／PW: 候補3 |
| 1つのパスワードを固定し、IDを次々に変えて試す | ID: userA／PW: 候補1 | ID: userB／PW: 候補1 | ID: userC／PW: 候補1 |

### 設問2 a｜PC-Pへの攻撃をログから見分ける

PC-Pのログには、「同一のIDに対して、異なるパスワードで多数回ログインに失敗した」記録が残っていました。このように、使われやすい単語や文字列のリスト（辞書）をパスワード候補として次々に試す手法を**辞書攻撃**といいます。したがって、設問2のaは辞書攻撃に対応する「**オ**」を選びます。

一方、後半のPC-Sに対する攻撃は、本文で**リバースブルートフォース攻撃**と明記されています。こちらは逆に「1つのパスワードを固定し、多数の異なるIDに対して試す」手法です。

### 設問3（設定項目・理由）｜ロックアウトが効く条件を考える

ログイン試行を繰り返す攻撃への対策として使われるのが**アカウントロックアウト**です。あるIDでログイン失敗が一定回数に達したとき、そのIDを一時的にロックして利用できなくします。この制限が発動する基準の回数を「**ロックアウトのしきい値**」と呼びます。

- **PC-Pへの攻撃（同一IDに多数回試行）**：同じIDで失敗が積み重なるため、ロックアウトのしきい値を適切に設定していれば制限が働きます。PC-Pでは150回失敗したあとにログインを許してしまっており、「ロックアウトのしきい値」の見直しが必要です。
- **PC-Sへの攻撃（異なるIDに1回ずつ試行）**：1つのパスワードを別々のIDに対して試すため、**各IDでの失敗回数は1回ずつにとどまります**。C社のようにしきい値を「5回」に設定していても、どのIDも5回に達しないためロックアウトが発動せず、同じパスワードを使っているIDが見つかれば突破されてしまいます。

### 設問3（理由）の答案を作ってみよう

設問3の理由は、指定語句「**同一**」を使い、25字以内で答える問題です。次の順序で組み立てると、根拠の明確な答案になります。

1. **本文の事実**：1つのパスワードを使い、異なるIDに対してログインを試す。
2. **対策の仕組み**：アカウントロックアウトは、同じIDでの失敗回数を数えて発動する。
3. **防げない理由**：同じIDで失敗を繰り返さないため、しきい値に達しない。
4. **字数・指定語句に合わせてまとめる**：公式解答例の一つは「同一のパスワードで異なるIDにログイン試行するから」（25字）です。

「リバースブルートフォース攻撃だから」と攻撃名だけを書いても、なぜ設定が効かないのかという仕組みの説明になりません。また、「パスワードを複雑にしていないから」と書くと、設定項目（ロックアウト）が機能しない理由から外れてしまいます。**「攻撃がどのようにIDとパスワードを試すか」という動き**を書くのがポイントです。

## 復旧用のデータと、調査用の記録は残っている？

### 設問4(1)｜バックアップは「いつの状態を戻せるか」で考える

バックアップは、障害や被害に備えてデータの複製を保存しておくことです。本問では、ネットワーク接続型のストレージであるNASにバックアップを保存しています。

ここで重要なのが、バックアップの運用ルールです。C社では、月曜日に全データを保存する**フルバックアップ**、火曜日〜日曜日に直前のフルバックアップ以降の変更分だけを保存する**差分バックアップ**を行っています。そして、NASに保存するのは**1世代分のみ**で、月曜日のフルバックアップが実行されると前の世代に上書きされます。

設問4(1)は、「もし前日の日曜日に既にデータが暗号化されていたら」という仮定の問いです。時系列で追ってみましょう。

```text
日曜日：サーバのデータが既にランサムウェアで暗号化されていた（仮定）
  → 月曜日の午前0時30分～1時30分：月曜のフルバックアップが自動実行される
  → 暗号化された状態のデータで、前の世代のバックアップを上書きしてしまう
  → 復旧に必要な「暗号化前のバックアップ」が失われ、元に戻せなくなる
```

バックアップ処理自体は正常に完了していても、**中身が「暗号化された後のデータ」に上書きされてしまえば復旧には使えません**。そのため、公式解答例は「暗号化されたデータで上書きされている。」となります。

なお、実際の調査で判明した侵入時刻（月曜早朝）と、この設問が置いている「日曜日に暗号化されていた場合」という仮定を混同しないよう気をつけましょう。また、NAS自体に侵入されてバックアップが直接暗号化されるリスクは本文の別の箇所で触れられており、設問4(1)ではあくまで「定時のバックアップによる上書き」を答えます。

### 設問5 c｜イミュータブルと複数世代は、役割を分けて理解する

**イミュータブルバックアップ**（Immutable＝変更不能）は、一度書き込んだバックアップデータを後から変更・削除できないように保護する方式です。設問5のcは、これに対応する「**ア**」を選びます。

C社の対策案では、イミュータブル方式の導入とあわせて「複数世代の保存」も行うこととしています。この2つは守る対象が異なります。

| 対策の工夫 | 防ぎたい事態 |
| --- | --- |
| **複数世代を残す** | 直近のバックアップに暗号化後のデータが入ってしまっても、さらに前の正常な時点へさかのぼって復旧できるようにする |
| **書込み後の変更を防ぐ（イミュータブル）** | 保存済みのバックアップデータそのものを、攻撃者に後から書き換えられたり消されたりしないようにする |

いくら保存後に書き換えられない仕組み（イミュータブル）にしても、1世代しか残していなければ、暗号化後のデータがバックアップされた時点で戻れる先がなくなってしまいます。**「正常な時点の世代を残すこと」と「残したデータを改変させないこと」の両輪**で考えることが大切です。

### 設問4(2)｜ログも、上書きされれば調べられない

ログは、ログインの成否や機器の動作などを時系列で記録したデータです。本文では、ログの保存容量が上限に達すると**古い記録から順に上書きする設定**になっていました。

辞書攻撃やリバースブルートフォース攻撃のように大量のログイン試行が行われると、新しいログが大量に発生し、容量上限に達してしまいます。その結果、過去にさかのぼって侵入状況を確認しようとしても、必要な記録が押し出されて消えてしまいます。これが設問4(2)の「調査できなくなる理由」であり、公式解答例は「古い記録のログが上書きされるから」です。

### 設問1｜記録を保全して調べる方法の名前を押さえる

設問1で問われている**デジタルフォレンジックス**は、インシデント発生時にコンピュータやネットワークに残された電磁的記録を証拠として保全し、調査・分析する一連の取組です。

ここまで見てきたとおり、原因を調査するには「そもそも記録が消えずに残っていること」が大前提になります。初動対応で証拠を保全する話（設問1）と、ログが上書きされて調査できなくなる問題（設問4(2)）は、この「調査のための証拠を残す」という視点で一本の線につながっています。

## この大問から持ち帰ること

- **認証への攻撃と対策**：攻撃者が「IDとパスワードのどちらを変えて試しているか」を見る。ID単位で失敗を数えるロックアウトは、IDを分散させる攻撃には効きにくい。
- **バックアップとログの保全**：「取っているか」だけでなく、「戻したい時点の世代が残るか（上書きされないか）」「保存後に攻撃者から書き換えられないか」を確認する。
- **理由を問う記述問題**：攻撃名や対策名だけで終わらせず、「本文の事実（攻撃の動きや保存設定）」と「仕組み」をつないで説明する。

余裕があれば、「毎日バックアップを取っているのに復旧できなくなるのはどんな場合か？」を自分の言葉で説明してみてください。この事例のように「暗号化後のデータで正常な世代を上書きしてしまった場合」と「保存先のバックアップ自体を攻撃者に暗号化・削除された場合」の2つを区別して説明できれば、理解は万全です。
