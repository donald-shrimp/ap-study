# 問1 サイバー攻撃への対策

## この問題は、何を考える問題だった？

中古車販売会社C社のサーバにあるデータが、攻撃者に暗号化されて使えなくなりました。暗号化してデータを使えなくし、復旧と引換えに金銭などを要求する不正なソフトウェアを、**ランサムウェア**といいます。

侵入の出発点は、業務でつながっていた提携先P社の機器でした。取引先などを足場にして別の会社へ被害を広げる攻撃は、サプライチェーン攻撃と呼ばれます。本問では、次の三つを考えます。

- どこから侵入し、どのようにサーバまで到達したか。
- 設定を変える対策が、どの攻撃に対して働くか。
- 被害が出ても、復旧に使うデータと調査に使う記録を残せるか。

**「対策がある」だけでは安心できません。その仕組みと、今回の攻撃の仕方を対応させる**のが、この大問の中心です。

## まず、機器と攻撃の流れを整理しよう

PCが何台も登場しますが、ここでは役割を短い言葉に置き換えて読みます。

| 機器 | この事例での役割 |
| --- | --- |
| P社のVPNルータ | 自宅などからP社のネットワークへ接続する入口 |
| PC-P | P社内にあり、C社側のPCを遠隔操作するために使うPC |
| PC-R | C社内に置かれた、P社から利用するためのPC |
| PC-S | C社の担当者がサーバの保守に使うPC |
| C社の各サーバ | 販売管理システムを動かし、今回データが暗号化された機器 |

VPN（Virtual Private Network）は、離れた場所から組織のネットワークへ安全に接続するための仕組みです。ただし、入口の機器や認証に弱点があれば、それを利用して侵入されるおそれがあります。悪用され得る弱点を、**脆弱性**といいます。

攻撃の流れを、本文の調査で判明した内容と、X氏が推測した入口の侵入方法を合わせて並べます。最初のVPN接続とPC-Pへの侵入方法は、本文でも可能性が高いとされている部分です。

```text
P社のVPNルータの脆弱性を利用してVPN接続（推定）
  → PC-Pへ辞書攻撃でログイン（攻撃方法は推定）
  → PC-Rへログイン
  → PC-Sへログイン
  → PC-Sに残っていたサーバ用のID・パスワードを利用
  → C社の各サーバでランサムウェアを実行
```

この流れをつかむと、設問2は「途中の攻撃方法と接続手段」、設問3は「その攻撃を防ぐ設定の限界」を尋ねていると分かります。

### 設問2 b｜接続の説明と許可ルールを照合する

PC-PからPC-Rへの接続は、本文に「リモートデスクトップ」とあります。離れたPCの画面を操作するための接続です。表1の許可ルールにもTCP/3389（RDP）があります。RDP（Remote Desktop Protocol）は、その接続に使う通信上の取り決め、つまりプロトコルです。したがって設問2のbはRDPに対応する「ウ」です。

FW（ファイアウォール）は、送信元・送信先・通信の種類などの条件に従って、通信を許可・遮断する機器や機能です。表1では、**どこからどこへ、どの通信が許可されているか**を読みます。通信を許可していても、それを利用する人が正当な利用者であるとは限りません。

## 同じ「ログインへの攻撃」でも、試し方が違う

ログインでは、通常、利用者を区別するIDと、その利用者であることを確かめるパスワードを使います。設問2・3では、攻撃者がどちらを固定し、どちらを変えたかが決め手になります。

以下のIDとパスワードは、違いを説明するための架空例です。

| 試し方 | 1回目 | 2回目 | 3回目 |
| --- | --- | --- | --- |
| 同じIDにパスワード候補を変えて試す | ID: userA／パスワード: 候補1 | ID: userA／パスワード: 候補2 | ID: userA／パスワード: 候補3 |
| 同じパスワードを異なるIDへ試す | ID: userA／パスワード: 候補1 | ID: userB／パスワード: 候補1 | ID: userC／パスワード: 候補1 |

### 設問2 a｜PC-Pへの攻撃をログから見分ける

PC-Pの記録では、一つのIDに対して、異なるパスワードで多数回ログインに失敗しています。使われそうな単語などをパスワード候補として順に試す攻撃を、**辞書攻撃**といいます。本問の解答群では、PC-Pへの試行に対応する名称として辞書攻撃「オ」を選びます。試行回数の多さだけから、どんな攻撃でも辞書攻撃と決めるわけではありません。

一方、PC-Sへの攻撃は本文に「リバースブルートフォース攻撃」と明記されています。一つのパスワードを、複数のIDに対して試す方法です。

### 設問3（設定項目・理由）｜ロックアウトが効く条件を考える

ここで使う対策が、**アカウントロックアウト**です。あるIDでログイン失敗が一定回数に達したとき、そのIDを一時的に利用できなくするなどの制限をかけます。制限をかける基準の回数が「ロックアウトのしきい値」です。

同じIDに何度も試す攻撃なら、そのIDの失敗回数が増えるので、しきい値による制限が働きます。PC-Pでは150回失敗した後にもログインできており、この設定の見直しが必要だと読み取れます。

しかし、異なるIDに一回ずつ試す攻撃では、**各IDでの失敗は1回にとどまります**。C社側の「5回」という設定があっても、その回数に達する前に、同じパスワードを使うIDにログインされるおそれがあります。「パスワードを難しくする」という別の対策と、「この設定で防げない理由」は分けて考えます。

### 設問3（理由）の答案を作ってみよう

設問3は、「同一」という語を使い、25字以内で理由を答える指定です。

1. 本文から拾う事実：一つのパスワードを、異なるIDに試す。
2. 結び付ける仕組み：ロックアウトは、同じIDの失敗回数で働く。
3. 説明したい理由：同じIDで繰り返し試さないので、しきい値に達しない。
4. 指定に合わせてまとめる：公式例の一つは「同一のパスワードで異なるIDにログイン試行するから」（25字）。

「リバースブルートフォース攻撃だから」だけでは、攻撃の名前を示しているだけで、設定が効かない仕組みが伝わりません。**攻撃の動きまで書く**と、理由を説明する答案になります。

## 復旧用のデータと、調査用の記録は残っている？

### 設問4(1)｜バックアップは「いつの状態を戻せるか」で考える

バックアップとは、故障や被害に備えてデータなどの複製を保存することです。本文のNASは、ネットワーク経由でデータを保存する装置で、バックアップの保存先になっています。

この問題では、月曜日に全体を保存するフルバックアップ、火曜日から日曜日に直前のフルバックアップからの変更分を保存する差分バックアップを行います。NASに残すのは1世代分で、次の世代は前の世代へ上書きします。

設問4(1)は「前日の日曜日に既に暗号化されていた場合」という仮定です。その条件を時系列にすると、次のようになります。

```text
日曜日：サーバのデータが既に暗号化されている、と仮定
  → 月曜日の午前0時30分～1時30分：フルバックアップ
  → 暗号化後のデータを保存し、前の世代を上書きする
  → 戻したい暗号化前のバックアップが失われるおそれ
```

そのため、公式例は「暗号化されたデータで上書きされている。」です。単に「バックアップに失敗した」とは書かれていません。バックアップ処理そのものが動いても、保存する内容が暗号化後のデータなら復旧に困るのです。

本文の調査で判明した月曜の侵入時刻と、この設問が置いた日曜感染の仮定は、混ぜずに読みます。また、「NASへ直接侵入されて暗号化されるリスク」は本文でも別に挙げられています。設問4(1)では、上書きによって何が起きるかを答えます。

### 設問5 c｜イミュータブルと複数世代は、役割を分けて理解する

**イミュータブルバックアップ**は、保存後のデータを書き換えられないようにするバックアップです。設問5では、その方式に対応する「ア」を選びます。

対策案では、複数世代を保存することも決めています。二つの役割を対応させましょう。

| 工夫 | 守りたいこと |
| --- | --- |
| 複数世代を残す | 新しいバックアップの内容に問題があっても、さらに前の時点へ戻れるようにする |
| 書込み後の変更を防ぐ | 保存済みのバックアップ自体を、後から書き換えたり暗号化したりされにくくする |

変更できない保存先でも、保存した時点ですでに暗号化されていれば、それだけで暗号化前へ戻せるわけではありません。**戻せる時点と、保存後の改変防止の両方**を確認する必要があります。

### 設問4(2)｜ログも、上書きされれば調べられない

ログは、ログインや機器の動作などの出来事を記録したものです。本文では、保存できる量の上限に達すると、古い記録から上書きする設定になっています。

大量の攻撃で新しいログが増えると、過去の攻撃の記録が押し出されます。設問4(2)の「調査できなくなる理由」は、この保存条件から導きます。公式例は「古い記録のログが上書きされるから」です。

### 設問1｜記録を保全して調べる方法の名前を押さえる

設問1のデジタルフォレンジックスは、事故に関係する電磁的な記録を証拠として保全し、調査・分析することです。調べるためには、まず記録が残っていなければなりません。初動で証拠を保全する話と、古いログを失わない話は、この点でつながります。本文で指示されたPCの使用停止を、すべての事故で直ちに電源を切るという一般則にはしないでください。

## この大問から持ち帰ること

- 認証への攻撃は、IDとパスワードのどちらを変えて試すかを見る。対策の効き方は、その試し方によって変わる。
- バックアップは、複製の有無に加えて、戻したい時点のデータが残るか、保存後に変更されないかを確認する。
- 「理由」を答えるときは、本文の条件と仕組みをつなげて説明する。

余裕があれば、「バックアップを毎日取っていても、元に戻せないのはどんな場合か」を自分の言葉で説明してみましょう。この事例なら、暗号化後のデータで古い世代を上書きした場合や、保存済みバックアップ自体を暗号化された場合が挙げられます。
