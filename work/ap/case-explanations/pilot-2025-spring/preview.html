問1 サイバー攻撃への対策

この問題は、何を考える問題だった？

中古車販売会社C社のサーバにあるデータが、攻撃者によって暗号化され、使えなくなってしまいました。このようにデータを暗号化して利用不能にし、復旧と引き換えに金銭などを要求する不正なソフトウェアをランサムウェアといいます。

今回の侵入の出発点は、業務でつながっていた提携先P社の機器でした。取引先や関連会社などを足掛かりにして標的の会社へ侵入する攻撃は、サプライチェーン攻撃と呼ばれます。本問では、次の3つの視点から事例を読み解きます。

  • 攻撃者はどこから侵入し、どの経路でC社のサーバまで到達したか

  • ログイン制限などの認証対策は、どのような攻撃に対して有効か（どこに限界があるか）

  • 被害が起きたあと、復旧用のバックアップや調査用のログが使える状態で残っているか

「対策を導入しているか」だけでなく、「その対策の仕組みが今回の攻撃方法や保存条件に対して本当に機能するか」を確かめるのが、この大問の核心です。

設問2 b｜接続の説明と許可ルールを照合する

この解説の対象：設問2 b

設問2の設問文を確認

本文中の［a］に入れる適切な字句，本文中の［b］に入れる適切なプロトコル名をそれぞれ解答群の中から選び，記号で答えよ。

対応する回答欄：b

PC-PからPC-Rへどのように接続したかを確かめましょう。本文には「リモートデスクトップで接続した」とあります。リモートデスクトップは、離れた場所にあるPCの画面を手元のPCから操作する機能です。

ここで表1のFW（ファイアウォール）の許可ルールを見ると、PC-PからPC-Rへの通信として「TCP/3389（RDP）」が許可されています。RDP（Remote Desktop Protocol）は、リモートデスクトップ接続で使われる通信の取り決め（プロトコル）です。本文の記述と表1のルールが一致するため、設問2のbはRDPに対応する「ウ」が正解です。

なお、FWは送信元・宛先・通信の種類（ポート番号）などの条件に合う通信を通し、それ以外を遮断する仕組みです。表1のように通信ルール上は許可されている経路であっても、正規のID・パスワードを奪われれば攻撃者の通り道になってしまう点に注意しましょう。

設問2 a｜PC-Pへの攻撃をログから見分ける

この解説の対象：設問2 a

設問2の設問文を確認

本文中の［a］に入れる適切な字句，本文中の［b］に入れる適切なプロトコル名をそれぞれ解答群の中から選び，記号で答えよ。

対応する回答欄：a

PC-Pのログには、「同一のIDに対して、異なるパスワードで多数回ログインに失敗した」記録が残っていました。このように、使われやすい単語や文字列のリスト（辞書）をパスワード候補として次々に試す手法を辞書攻撃といいます。したがって、設問2のaは辞書攻撃に対応する「オ」を選びます。

一方、後半のPC-Sに対する攻撃は、本文でリバースブルートフォース攻撃と明記されています。こちらは逆に「1つのパスワードを固定し、多数の異なるIDに対して試す」手法です。

設問3（設定項目・理由）｜ロックアウトが効く条件を考える

この解説の対象：設問3（設定項目・理由）

設問3の設問文を確認

本文中の下線②について，変更した設定項目を，本文中の字句を用いて15字以内で答えよ。また，防御できないおそれがある理由を，“同一”という字句を用いて25字以内で答えよ。

対応する回答欄：設定項目・理由

ログイン試行を繰り返す攻撃への対策として使われるのがアカウントロックアウトです。あるIDでログイン失敗が一定回数に達したとき、そのIDを一時的にロックして利用できなくします。この制限が発動する基準の回数を「ロックアウトのしきい値」と呼びます。

  • PC-Pへの攻撃（同一IDに多数回試行）：同じIDで失敗が積み重なるため、ロックアウトのしきい値を適切に設定していれば制限が働きます。PC-Pでは150回失敗したあとにログインを許してしまっており、「ロックアウトのしきい値」の見直しが必要です。

  • PC-Sへの攻撃（異なるIDに1回ずつ試行）：1つのパスワードを別々のIDに対して試すため、各IDでの失敗回数は1回ずつにとどまります。C社のようにしきい値を「5回」に設定していても、どのIDも5回に達しないためロックアウトが発動せず、同じパスワードを使っているIDが見つかれば突破されてしまいます。

設問3（理由）の答案を作ってみよう

設問3の理由は、指定語句「同一」を使い、25字以内で答える問題です。次の順序で組み立てると、根拠の明確な答案になります。

  1. 本文の事実：1つのパスワードを使い、異なるIDに対してログインを試す。

  2. 対策の仕組み：アカウントロックアウトは、同じIDでの失敗回数を数えて発動する。

  3. 防げない理由：同じIDで失敗を繰り返さないため、しきい値に達しない。

  4. 字数・指定語句に合わせてまとめる：公式解答例の一つは「同一のパスワードで異なるIDにログイン試行するから」（25字）です。

「リバースブルートフォース攻撃だから」と攻撃名だけを書いても、なぜ設定が効かないのかという仕組みの説明になりません。また、「パスワードを複雑にしていないから」と書くと、設定項目（ロックアウト）が機能しない理由から外れてしまいます。「攻撃がどのようにIDとパスワードを試すか」という動きを書くのがポイントです。

設問4(1)｜バックアップは「いつの状態を戻せるか」で考える

この解説の対象：設問4(1)

設問4(1)の設問文を確認

［U社からC社への報告］について答えよ。 表2中の下線③について，バックアップデータに発生していたおそれがある事象を30字以内で答えよ。

対応する回答欄：事象

バックアップは、障害や被害に備えてデータの複製を保存しておくことです。本問では、ネットワーク接続型のストレージであるNASにバックアップを保存しています。

ここで重要なのが、バックアップの運用ルールです。C社では、月曜日に全データを保存するフルバックアップ、火曜日〜日曜日に直前のフルバックアップ以降の変更分だけを保存する差分バックアップを行っています。そして、NASに保存するのは1世代分のみで、月曜日のフルバックアップが実行されると前の世代に上書きされます。

設問4(1)は、「もし前日の日曜日に既にデータが暗号化されていたら」という仮定の問いです。時系列で追ってみましょう。

日曜日：サーバのデータが既にランサムウェアで暗号化されていた（仮定）
  → 月曜日の午前0時30分～1時30分：月曜のフルバックアップが自動実行される
  → 暗号化された状態のデータで、前の世代のバックアップを上書きしてしまう
  → 復旧に必要な「暗号化前のバックアップ」が失われ、元に戻せなくなる

バックアップ処理自体は正常に完了していても、中身が「暗号化された後のデータ」に上書きされてしまえば復旧には使えません。そのため、公式解答例は「暗号化されたデータで上書きされている。」となります。

なお、実際の調査で判明した侵入時刻（月曜早朝）と、この設問が置いている「日曜日に暗号化されていた場合」という仮定を混同しないよう気をつけましょう。また、NAS自体に侵入されてバックアップが直接暗号化されるリスクは本文の別の箇所で触れられており、設問4(1)ではあくまで「定時のバックアップによる上書き」を答えます。

設問5 c｜イミュータブルと複数世代は、役割を分けて理解する

この解説の対象：設問5 c

設問5の設問文を確認

本文中の［c］に入れる適切な字句を解答群の中から選び，記号で答えよ。

対応する回答欄：c

イミュータブルバックアップ（Immutable＝変更不能）は、一度書き込んだバックアップデータを後から変更・削除できないように保護する方式です。設問5のcは、これに対応する「ア」を選びます。

C社の対策案では、イミュータブル方式の導入とあわせて「複数世代の保存」も行うこととしています。この2つは守る対象が異なります。

対策の工夫防ぎたい事態
複数世代を残す直近のバックアップに暗号化後のデータが入ってしまっても、さらに前の正常な時点へさかのぼって復旧できるようにする
書込み後の変更を防ぐ（イミュータブル）保存済みのバックアップデータそのものを、攻撃者に後から書き換えられたり消されたりしないようにする

いくら保存後に書き換えられない仕組み（イミュータブル）にしても、1世代しか残していなければ、暗号化後のデータがバックアップされた時点で戻れる先がなくなってしまいます。「正常な時点の世代を残すこと」と「残したデータを改変させないこと」の両輪で考えることが大切です。

設問4(2)｜ログも、上書きされれば調べられない

この解説の対象：設問4(2)

設問4(2)の設問文を確認

［U社からC社への報告］について答えよ。 表2中の下線④について，調査ができなくなる理由を20字以内で答えよ。

対応する回答欄：理由

ログは、ログインの成否や機器の動作などを時系列で記録したデータです。本文では、ログの保存容量が上限に達すると古い記録から順に上書きする設定になっていました。

辞書攻撃やリバースブルートフォース攻撃のように大量のログイン試行が行われると、新しいログが大量に発生し、容量上限に達してしまいます。その結果、過去にさかのぼって侵入状況を確認しようとしても、必要な記録が押し出されて消えてしまいます。これが設問4(2)の「調査できなくなる理由」であり、公式解答例は「古い記録のログが上書きされるから」です。

設問1｜記録を保全して調べる方法の名前を押さえる

この解説の対象：設問1

設問1の設問文を確認

本文中の下線①の調査方法の名称を，片仮名12字以内で答えよ。

対応する回答欄：調査方法の名称

設問1で問われているデジタルフォレンジックスは、インシデント発生時にコンピュータやネットワークに残された電磁的記録を証拠として保全し、調査・分析する一連の取組です。

ここまで見てきたとおり、原因を調査するには「そもそも記録が消えずに残っていること」が大前提になります。初動対応で証拠を保全する話（設問1）と、ログが上書きされて調査できなくなる問題（設問4(2)）は、この「調査のための証拠を残す」という視点で一本の線につながっています。

この大問から持ち帰ること

  • 認証への攻撃と対策：攻撃者が「IDとパスワードのどちらを変えて試しているか」を見る。ID単位で失敗を数えるロックアウトは、IDを分散させる攻撃には効きにくい。

  • 理由を問う記述問題：攻撃名や対策名だけで終わらせず、「本文の事実（攻撃の動きや保存設定）」と「仕組み」をつないで説明する。

余裕があれば、「毎日バックアップを取っているのに復旧できなくなるのはどんな場合か？」を自分の言葉で説明してみてください。この事例のように「暗号化後のデータで正常な世代を上書きしてしまった場合」と「保存先のバックアップ自体を攻撃者に暗号化・削除された場合」の2つを区別して説明できれば、理解は万全です。

問2 企業の成長戦略

この問題は、何を考える問題だった？

化学品メーカーのD社は、かつてデジタル化の波で写真フィルムの需要が急減した際、培ってきた技術を医療や高機能素材へと応用して危機を乗り越えました。そして今、さらなる環境変化を見据え、会社全体として持続的・安定的に成長するための新たな経営計画を立てようとしています。

この大問では、「市場にどんな変化が起きており、自社のどんな強みを生かして、どの事業領域へ資源を振り向けるか」を考えます。経営戦略の用語を覚えるだけでなく、本文に書かれたD社の事実をフレームワークに当てはめて整理する力が問われます。

全体の流れは、「過去の成功要因の振り返り」→「現在の環境分析（SWOT）」→「今後の多角化と経営資源の配分」という3段階で進みます。「なんとなく新事業が有望そうだから」と雰囲気で選ぶのではなく、本文の条件を一つずつ対応させて読み進めましょう。

過去の成功は、何が支えていた？

設問1(1)｜複数の事業拡張に共通するコア技術を拾う

この解説の対象：設問1(1)

設問1(1)の設問文を確認

［D社の成長戦略の振返り］について答えよ。 本文中の下線①について，D社が過去にこれらの戦略を用いて事業を拡張させてきた内部環境上の最も重要な成功要因は何か。本文中の字句を用いて15字以内で答えよ。

対応する回答欄：成功要因

対応する回答欄：通信の種類

サブネットは、大きなネットワークを小さく区切った単位です。異なるサブネット同士の通信は、経路を判断して中継する L3SW（レイヤー3スイッチ） やルータを介して行われます。

ここで、同じサブネット内のすべての機器へ一斉に送る通信をブロードキャストと呼びます。L3SWやルータは、原則としてブロードキャスト通信を別のサブネットへは転送しません（そのまま通すとネットワーク全体に不要な一斉通信があふれてしまうためです）。したがって、サブネットを分割した結果として異なるサブネット間では届かなくなる通信は「ウ：ブロードキャスト」です。

なお、特定の1台へ宛てて送る「ユニキャスト」や、ファイル転送の「FTP」、ping などで使う「ICMP」は、L3SWで適切に経路設定されていればサブネットを越えて通信できます。

トラブル調査でまず使われた ping は、「相手の機器まで通信が届いて応答が返ってくるか（疎通確認）」を調べるコマンドです。本文では、キャッシュDNSサーバに対して ping の応答はありました。しかし、「サーバの機器に通信が届くこと」と「そのサーバの上でDNSの名前解決プログラムが正常に動いていること」は別問題です。

そこで、DNSサーバに実際の問い合わせを送って名前解決が機能しているかを確かめるコマンド nslookup を使います。したがって、cは「nslookup」です。

ping 192.168.11.41              → 機器まで通信が届くか（到達性）の確認
nslookup example.com 192.168.11.41 → DNSとして名前解決できるか（機能）の確認
（※ example.com はコマンドの使い方を示すための架空のドメイン名です）

調査の結果、nslookup で名前解決ができないことが判明し、キャッシュDNSサーバを再起動することで復旧しました。「疎通（ping）」と「サービス機能（nslookup）」を段階的に切り分ける王道の手順です。

対応する回答欄：名称・条件

ネットワーク機器の状態を監視・管理するプロトコルを SNMP（Simple Network Management Protocol）といいます。その中でも、異常やしきい値超過が起きたときに監視対象の機器側から管理者のサーバへ能動的に知らせる機能が SNMPトラップ です（管理側から定期的に尋ねる「ポーリング」と向きが逆になります）。

今回は「L3SWから運用管理者に通知する」仕組みなので、機能名は「SNMPトラップ」です。また、通知する条件は、障害発生時の原因調査で確認された基準に合わせて「トラフィック量が800Mビット／秒を超える」（25字以内）とします。

・監視する通信：ファイルサーバと社内LANの間の通信
・通知する条件：トラフィック量が800Mビット／秒を超えるとき
・通知の向き：L3SW（機器側） → 運用管理者（管理側）＝ SNMPトラップ

本文の記述が「800Mビット／秒を超えており」となっているため、条件を書く際も800ちょうどを含む「以上」に変えず、本文どおり「超える」と正確に表現しましょう。

ここが設問2の最大の山場です。小さな架空データを使って、なぜ結合方法に工夫が要るのかを見てみましょう（数値は仕組みを理解するための架空の例です）。

E00050

対応する回答欄：e

副問合せ UK の中では、キャンペーン種別ごとの「売上計」と「原価計」を計算しています。

・原価：商品個数 2個 × 商品表の商品原価  70円 ＝ 140円

問9 CCPMを用いたプロジェクトのスケジュール管理

この問題は、何を考える問題だった？

小売業のZ社は、老朽化した販売管理システムを刷新することにしました。開発コストを抑えるため、クラウド型のパッケージサービスである SaaS（Software as a Service）を導入し、標準機能に自社の業務を合わせる方針をとります。どうしても標準機能だけでは足りない部分だけを追加開発する方式で、この追加開発部分を本文ではSaaSアドオンと呼んでいます。

この大問では、プロジェクトの立ち上げから進行管理までを次の3段階で考えます。

  • 発注先（ベンダ）の選定：会社の方針を反映した重み付け評価と、足切り条件（最低基準）の確認

中核となる CCPM（Critical Chain Project Management：クリティカルチェーン・プロジェクトマネジメント）は、作業の前後関係だけでなく「担当チームの空き状況（資源の制約）」も考慮して重要な作業の連鎖を特定し、余裕時間をプロジェクト全体で一括管理する手法です。「どの作業が遅れると納期に響くのか」「その遅れをどの余裕時間で吸収するのか」という2点に注目して読み進めましょう。

問11 勤務管理に関連するシステムの監査

この問題は、何を考える問題だった？

W社では、従業員の勤務時間の記録から「超過勤務時間（残業時間）」を計算し、その結果を給与計算システムへ連携して毎月の給与を支払っています。もし途中のシステムで誤った情報が登録されると、超過勤務時間の計算が狂い、最終的に「給与の支給額が間違ってしまう」という重大な問題につながります。

システム監査とは、独立した立場から「情報システムにどんなリスク（望ましくない事態が起きる可能性）があり、それを防いだり見つけたりする仕組み（コントロール／統制）が適切に働いているか」を証拠に基づいて確かめる活動です。

この大問では、監査チームの視点に立って、「どのシステムに・どんな情報を入れる場面で誤りが起き得るか（リスク）」と「それをどう防ぎ、予定していた再発防止策が本当に実施されたかをどう確かめるか」を整理します。

  • リスクは「どのシステムの・何のデータか」まで具体化する：単なる「入力ミス」ではなく、「勤務管理システムへの標準勤務時間の手入力」と「人事管理システムへの職種の誤登録」をデータの流れに沿って区別する。
