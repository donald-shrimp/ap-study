## 読者と作成基準

資格の学習を始めたばかりで、ロックアウト、外部結合、クリティカルチェーンなどの用語・仕組みをまだ説明できない人を想定する。必要な知識は、使う直前に意味と具体例を示す。

- 最初に、会社が何をしたくて、どんな問題が起きたかを日常の言葉で説明する。
- 本文の事実、仕組みの説明、そこから導く判断をつなぐ。
- 計算は式の意味・単位・途中結果を示す。表や小さな架空例を使う場合は、原問のデータと明確に区別する。
- 答案例を少なくとも一つ、条件の抽出から字数確認まで説明する。非公表の配点・部分点・合否は作らない。
- 原問の全設問に対応する解き方を扱いつつ、欄別解説の全文を並べ直さない。
- 「初学者向け」を、易しい問題への変更や原文への解法の書き足しと読み替えない。

## 草稿の受け入れ方

今回の受け入れ形式はUTF-8のMarkdown。各ファイルの `##` を解説のまとまり、`###` をその中の小見出しとして扱う。導入と解き方を先に、詳しい知識・答案例・振り返りを後に置く。節数は問題に応じて変える。表・コード・太字は既存の限定表示へ移しやすい形にする。

各小問に対応する見出しは「設問2 d｜…」のように、設問番号と回答欄を明記する。[対応情報](explanation-links.json)は、現行caseの小問ID・回答欄IDと、Markdownの一意な見出し・移動用IDを結び付ける。11題の全96欄を88の解説箇所でカバーする。同時に説明する欄（例えば問7の設問4(1)のe・f・g、問8の設問4の出力機能・内容、問10の設問2(2)の実施内容・理由）は、一つの箇所へまとめる。問2のb・cは現行教材でも一つの順不同回答欄で、2欄には数えない。問3のア～クは内部ID a～hと区別し、原問と同じカタカナで表示する。

プレビューには、導入の後に「小問と解説の対応」を置く。リンクを押すと該当する折りたたみを開き、見出しへ移動する。各箇所では、対応する設問文を現行caseから表示し、一覧へ戻れる。同じリンクの再選択、箇所への直接URL、再読込、ブラウザの戻る・進むでも対象大問と表示位置を合わせる。全体を順に読む導線も維持する。

これは教材内容を検討するための編集用形式であり、現行アプリへそのまま取り込むJSON契約ではない。本番の `caseExplanation`、開示条件、保存再開の受け入れ仕様は画面実装時に確定する。

作者は `/root`。全11題は既存case version 1に対応する。公開用作成元・教材版・公式解答・既存の確認台帳は変更しない。草稿に解答を含むため、学習中の未解答者向けの資料としては表示しない。

## プレビューの再生成と確認

リポジトリのルートで実行する。

```sh
node work/ap/case-explanations/pilot-2025-spring/build-preview.mjs
python work/ap/case-explanations/pilot-2025-spring/verify-content.py
python work/ap/case-explanations/pilot-2025-spring/verify-additional-content.py
python work/ap/case-explanations/pilot-2025-spring/verify-strategy-system-embedded.py
python work/ap/case-explanations/pilot-2025-spring/verify-final-content.py
python work/ap/case-explanations/pilot-2025-spring/verify-preview.py
```

`verify-content.py` は元のSQLを公式例で補完してSQLiteで実行し、初回3題の架空例・PMの日数・評価値・答案文字数を検算する。`verify-additional-content.py` は次の3題の盤面・探索の例・境界、ネットワーク表の照合、勤務形態例、公式例の字数指定を確認する。`verify-strategy-system-embedded.py` はSLAの割合・上限・減額を十進数で検算し、状態遷移の小さなモデル・通信順序・再試行時間・答案指定を確認する。`verify-final-content.py` は最後の2題の答案指定、平均と割合の例、時刻と区間、全11題の収録を確認する。意味的な妥当性や情報の参照者・経路は別担当が確認する。いずれも例の検算であり、実機の通信・クラウド・車体・CRM・サービス負荷の試験や原問プログラムの実行ではない。

プレビュービルド時には対応IDの存在、全欄の網羅、重複のなさ、見出しの一意性を検証する。`verify-preview.py` は全88リンクについて、移動先の見出し・折りたたみの開示・元設問文・再読込・一覧への復帰を確認する。11題の切替、箇所への直接移動、ブラウザ履歴、キーボード操作と320／390／1440pxの横幅も確認する。スクリーンショットは結果JSONに記載した一時ディレクトリへ保存する。実行には環境のPlaywrightとChromiumを使う。

今回の確認環境ではChromiumの管理設定で `file://` の読み込みが拒否されたため、ブラウザ確認はローカルHTTP経由で行った。アプリ本体の学習記録へ書き込みは行っていない。
