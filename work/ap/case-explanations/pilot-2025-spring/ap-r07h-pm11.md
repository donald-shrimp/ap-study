# 問11 勤務管理に関連するシステムの監査

## この問題は、何を考える問題だった？

W社では、従業員の勤務時間の記録から「超過勤務時間（残業時間）」を計算し、その結果を給与計算システムへ連携して毎月の給与を支払っています。もし途中のシステムで誤った情報が登録されると、超過勤務時間の計算が狂い、最終的に「給与の支給額が間違ってしまう」という重大な問題につながります。

**システム監査**とは、独立した立場から「情報システムにどんなリスク（望ましくない事態が起きる可能性）があり、それを防いだり見つけたりする仕組み（コントロール／統制）が適切に働いているか」を証拠に基づいて確かめる活動です。

この大問では、監査チームの視点に立って、**「どのシステムに・どんな情報を入れる場面で誤りが起き得るか（リスク）」**と**「それをどう防ぎ、予定していた再発防止策が本当に実施されたかをどう確かめるか」**を整理します。

## 三つの確認事項を、情報の流れと時期で整理する

図1には名前の似たシステムが5つ登場するため、最初にそれぞれの役割とデータの流れを整理しておきましょう。

| システム名 | 管理する主な情報と役割 |
| --- | --- |
| **人事管理システム** | 従業員の「所属部店」や「職種」を管理し、勤務管理システムへ自動連携する |
| **勤務管理システム** | 「標準勤務時間」や日々の勤務記録を基に、超過勤務時間を算出する |
| **給与計算システム** | 勤務管理システムから勤務記録を取り込み、給与支給額を計算する |
| **TR管理システム** | 部店のタイムレコーダ（TR）でICカードから読み取った入退室時刻を提供する |
| **PC管理システム** | テレワーク対応として、PCの稼働開始・終了時刻を新たに提供する予定 |

監査部長から出された指示は、次の3つの確認事項です。

```text
・指示(1)：標準勤務時間を登録する際のリスクと、その防止策を確かめる（設問1）
・指示(2)：10月から始まるテレワーク拡大に向け、確認メッセージの表示条件が働き方に合っているか確かめる（設問2）
・指示(3)：4月に再発した給与支給額誤りについて、計画どおり対策が実施されていたか確かめる（設問3）
```

特に注意したいのは、設問1で扱う「**標準勤務時間**の入力ミス（勤務管理システム）」と、設問3で扱う「**職種**の誤登録（人事管理システム）」は、**対象の情報もシステムも別である**という点です。混同しないよう分けて読み進めましょう。

## 標準勤務時間の登録には、どんな確認が必要？

### 設問1(1) a｜人事部が行う登録方法を本文から拾う

「標準勤務時間」は、所属部店や職種、月ごとに定められた基準の勤務時間です。本文を読むと、人事管理システムから所属部店や職種は自動で連携される一方、この標準勤務時間については、人事部の担当者が「全社勤務時間管理表」を見ながら**勤務管理システムへ手作業で登録している**と書かれています。

したがって、空欄aに入る登録方法は「**手作業**」（5字以内）です。システム間連携の一部が自動化されていても、人が手で入力している箇所があれば、そこに打ち間違いや読み違いのリスクが潜んでいます。

### 設問1(2) b｜入力誤りを防ぐ・見つける仕組みを確かめる

手作業での入力がある以上、「表の数字を読み違える」「桁を間違えて入力する」といったミスが起こり得ます。このような入力ミスがそのまま登録されてしまうのを防いだり、おかしな値を検出して警告したりする仕組みを**入力コントロール（入力統制）**といいます。したがって、bには「**入力コントロール**」（10字以内）が入ります。

たとえば、月の標準勤務時間としてあり得る範囲（上限・下限）をあらかじめチェックする仕組みがあれば、「180時間」と入れるべきところに誤って「1800時間」と打ち込んだようなミスをシステム側で弾くことができます。システム監査では、「気をつけて入力しましょう」といった精神論ではなく、**システム上に入力コントロールが適切に組み込まれているか**を確かめます。

## テレワーク対応は、一日中同じ働き方とは限らない

### 設問2(1) c｜確認の対象となる「勤務形態」を拾う

W社では10月からテレワークの対象者を拡大するにあたり、PC管理システムから取得した「PCの稼働開始・終了時刻」と、従業員が申告した「勤務開始・終了時刻」を比較し、一定以上の差があれば確認メッセージを表示する仕組み（下線①）を導入しようとしています。

もし全員が「朝から晩まで1日中テレワークだけをする」のであれば、PCの稼働時刻と一日の勤務時刻を単純に比べれば済みます。しかし、本文には**「部店への出勤とテレワークという勤務形態の組合せ」**も認められると書かれています。そのため、メッセージの表示条件を設計するにあたっては、どのような「**勤務形態**」（c：5字以内）があるかを踏まえる必要があります。

### 設問2(2) d｜勤務形態の一定の組合せも想定する

なぜ勤務形態の組み合わせを考える必要があるのか、本文の例①（8〜12時は部店勤務、13〜17時は自宅等でテレワーク）で具体的にイメージしてみましょう。

この働き方をする従業員は、午前中は部店で仕事をし、午後のテレワークが始まる13時に初めてテレワーク用PCを起動します。もしシステムが「一日の勤務開始時刻（8時）」と「PCの稼働開始時刻（13時）」を単純に引き算してしまうと、正しく働いているのに「5時間もズレている！」と誤判定してしまいます。また、例②のように「テレワーク → 部店勤務 → テレワーク」と1日の中で移動するケースもあります。

したがって、監査部長の指示にある「cのdを想定しているか」という空欄には、cに「**勤務形態**」、dに「**一定の組合せ**」（10字以内）が入ります。両方をつなげて「**勤務形態の一定の組合せ**を想定しているか」と文が自然につながるか、また各欄の字数制限（cは5字以内、dは10字以内）に収まっているかをセットで確認しましょう。

## 再発した障害は、誤りの入口までさかのぼる

設問3は、過去に起きた「給与支給額の誤り」が4月に再発してしまった問題です。表1の記録から、何が直接の引き金（直接原因）で、そもそもどこで間違いが起きたのか（根本原因）をさかのぼって整理しましょう。

```text
1. 人事管理システムで、従業員の「職種」を誤って登録した【根本原因】
     ↓（誤った職種データが連携される）
2. 勤務管理システムで、違う職種の標準勤務時間を使って「超過勤務時間」を誤算出した
     ↓（誤った超過勤務時間が連携される）【直接原因】
3. 給与計算システムで、一部の従業員の「給与支給額」が誤って計算された【発生した事象】
```

たとえば本文にあるとおり、1月の店舗における標準勤務時間は「販売職なら140時間」「事務職なら160時間」と職種によって異なります。入り口の人事管理システムで職種を間違えて登録してしまうと、基準となる標準勤務時間がズレてしまい、結果として残業代（給与支給額）まで間違ってしまうわけです。

### 設問3(1) e｜改修対象は、職種を登録する人事管理システム

最終的に金額の間違いが発覚したのは給与計算システムですが、間違いの元凶（根本原因）は「職種を誤登録したこと」にあります。表1の恒久対応でも、職種を登録する入り口のシステムの入力コントロールを改修する計画になっていました。

空欄eの直後には「システム」という言葉がすでに印字されているため、eには5字以内で「**人事管理**」と答えます（誤って「人事管理システム」と書いて文字数オーバーや重複にならないよう注意しましょう）。

### 設問3(2) f｜防ぎたいのは、従業員の職種の誤登録

その人事管理システムの入力コントロールを改修する目的は、根本原因である職種の登録ミスを防ぐことです。したがって、空欄f（「fを防止するために適切な内容で」）には、15字以内で「**従業員の職種の誤登録**」が入ります。

「給与支給額の誤り」は最終的に起きた結果であり、人事管理システムの入力コントロールが直接防ぐ対象はあくまで「従業員の職種の誤登録」である点を正確に対応させましょう。

### 設問3(3) g｜確認する期限は、予定されていた3月末日

最後に、いつまでにその改修が行われているべきだったか（期限g）を時系列で確認します。

| 時期 | 本文と表1から分かる出来事 |
| --- | --- |
| **X年1月** | 1回目の「給与支給額の誤り」が発生 |
| **X年2月末時点** | 表1に「**X年3月末日まで**に入力コントロールを改修する」という恒久対応計画を記録 |
| **X年4月** | 同じ根本原因による障害が**再発** |
| **X年5月** | 監査チームが予備調査を実施 |
| **X年7月** | 監査チームが本調査を実施する予定 |

表1の計画で定められていた改修期限は「**X年3月末日**」（10字以内）です。したがって、gには「**X年3月末日**」が入ります（再発した4月や、本調査を行う7月を選ばないよう気をつけましょう）。

4月に同じ原因の障害が再発したということは、「予定していたX年3月末日までに改修作業が終わっていなかった」か、「期限までに改修はしたものの、チェック内容が不十分でミスをすり抜けてしまった」かのどちらかです。だからこそ監査部長は、**「適切な内容で（f）、期限までに（g）改修されていたか確認せよ」**と両面から指示を出しているのです。

### 設問3(1)～(3)の答案を、確認事項としてつなげる

3つの空欄（e・f・g）に公式解答例を当てはめて一文で読むと、次のようにすっきり意味が通ります。

```text
「人事管理【e】システムが、
　従業員の職種の誤登録【f】を防止するために適切な内容で、
　X年3月末日【g】までに改修されていたか、確認する。」
```

## この大問から持ち帰ること

- **リスクは「どのシステムの・何のデータか」まで具体化する**：単なる「入力ミス」ではなく、「勤務管理システムへの標準勤務時間の手入力」と「人事管理システムへの職種の誤登録」をデータの流れに沿って区別する。
- **業務ルール（働き方）とシステム判定条件の整合**：一部テレワークのような「勤務形態の組合せ」が認められているなら、システムの警告条件もその組み合わせに対応しているかを確かめる。
- **事象から根本原因へさかのぼる**：障害の表面的な発生場所（給与計算）ではなく、誤ったデータが生まれた入り口（人事管理）の対策を確認する。また、再発時には「期限どおり実施されたか」と「内容が適切だったか」の両面を確かめる。

余裕があれば、「給与の金額が間違っていたのに、なぜ給与計算システムではなく人事管理システムの改修を確認するのか？」を説明してみてください。「給与計算システム自体は渡されたデータどおりに計算しており、間違いの元をたどると人事管理システムで『職種』を誤登録したせいで標準勤務時間と超過勤務時間がズレたことが根本原因だから」と説明できれば、システム間のデータ連携と監査の視点がしっかり身についています。
