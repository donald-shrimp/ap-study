# 問11 勤務管理に関連するシステムの監査

## この問題は、何を考える問題だった？

W社では、勤務時間の記録から超過勤務時間を求め、その結果を使って給与を計算しています。関連するシステムの一つで誤った情報を登録すると、後の計算にも誤りが広がるおそれがあります。

システム監査は、システムの運用や管理が適切かを、根拠を集めて確かめる活動です。本問は、監査担当者として「どこに誤りが入り得るか」「その誤りを防ぐ・見つける仕組みはあるか」「予定した対策が実施されているか」を確認する問題です。

中心となるのは、**リスクと確認対象を対応させること**です。リスクは、望ましくないことが起きる可能性です。「入力ミスがあるかもしれない」で止めず、どの情報をどのシステムへ入れる場面かまで具体化します。

## 三つの確認事項を、情報の流れと時期で整理する

図1のシステム名が似ているので、役割を分けて読みましょう。

| 対象 | 主な情報・役割 |
| --- | --- |
| 人事管理システム | 従業員の所属部店や職種を管理し、勤務管理へ連携する |
| 勤務管理システム | 標準勤務時間や勤務記録を使い、超過勤務時間を求める |
| 給与計算システム | 勤務記録を取り込み、給与支給額を求める |
| TR管理システム | 部店のタイムレコーダで記録した入退室時刻を提供する |
| PC管理システム | テレワーク対応で、PCの稼働開始・終了時刻を提供する予定 |

TRはタイムレコーダのことです。本問では、従業員のICカードを読み取り、部店への入室・退室時刻を記録します。こうした機器の記録は、従業員が登録する勤務開始・終了時刻を確認する材料になります。

監査部長の指示は、三つの別の確認事項です。

```text
指示(1)：標準勤務時間を手入力するリスクを確かめる
指示(2)：10月からの複数の勤務形態に表示条件が合うか確かめる
指示(3)：4月に再発した障害について、対策の実施と内容を確かめる
```

設問1の入力ミスの対象は「標準勤務時間」、設問3で再発した原因は「職種の誤登録」です。どちらも入力に関する話ですが、**登録する情報も、対象システムも異なります**。

## 標準勤務時間の登録には、どんな確認が必要？

### 設問1(1) a｜人事部が行う登録方法を本文から拾う

標準勤務時間は、部店や職種、月によって定められた基準の勤務時間です。本文では、人事部が全社勤務時間管理表を見て、勤務管理システムへ手作業で登録しています。

したがってaは「手作業」です。人事管理システムから自動で送られてくるのは所属部店や職種の情報であり、標準勤務時間の登録とは区別します。

自動化されている部分があっても、すべての入力が自動で正しくなるわけではありません。どこで人が値を入力するかを、情報の流れに沿って特定します。

### 設問1(2) b｜入力誤りを防ぐ・見つける仕組みを確かめる

手作業の登録では、表を読み違えたり、数値を打ち間違えたりする可能性があります。誤った値が後の処理へ進むことを防ぐ、または誤りを検出するための仕組みが、入力コントロールです。bは「入力コントロール」になります。

例えば、説明用のケースとして「180時間を入力するところへ1800時間と入力した」場面を考えます。値の範囲を検査する仕組みなら、このような不自然な値の発見に役立つことがあります。ただし、165と180を取り違えたような、どちらもあり得る値の誤りまですべて防げるとは限りません。

本問でその検査が既に実装されているとは書かれていません。監査では、元の管理表や業務ルールに合う確認が**適切に組み込まれているかを確かめる**立場です。「注意するように伝える」といった一般的な呼び掛けだけで、システムの入力コントロールの確認を代用しません。

## テレワーク対応は、一日中同じ働き方とは限らない

### 設問2(1) c｜確認の対象は、勤務形態である

本文の下線①では、PCの稼働開始・終了時刻と、登録した勤務開始・終了時刻を比べ、差が一定以上ならメッセージを出すことを想定しています。このメッセージは、申告した時刻を確認するきっかけです。

一日中テレワークする場合だけを想定すれば、PCの開始とその日の勤務開始を比べるという考え方が出てきます。しかし、本文では部店勤務とテレワークを一日の中で組み合わせることも認めています。そこで、表示条件を考える際の対象として「勤務形態」を拾います。cは「勤務形態」です。

PCを使い始めた時刻が、その人の一日の勤務開始時刻と必ず同じとは限りません。**仕事の進め方と、記録を取る機器の使い方を対応させる**必要があります。

### 設問2(2) d｜勤務形態の一定の組合せも想定する

本文の例①は「8～12時は部店勤務、13～17時はテレワーク」です。例えばテレワーク用PCを13時に使い始めた場合、その時刻を一日の勤務開始8時とだけ比べれば5時間の差になります。しかし、8時から部店で仕事をしていた可能性があり、その差だけで申告誤りとはいえません。このPC開始時刻は、表示条件を考えるための説明上の仮定です。

例②のように、テレワーク→部店勤務→テレワークという組合せもあります。一日の最初と最後だけでなく、それぞれの勤務区間をどう確認するかが問題になります。

監査部長の指示「cのdを想定しているか」には、「勤務形態の一定の組合せ」が入ります。したがってdは「一定の組合せ」です。cとdを並べて文章を完成させてから、各欄の字数指定に収まるか確認しましょう。

実際のしきい値は本文にありません。5時間の差なら必ずメッセージが出ると断定したり、部店勤務の日は確認をすべて免除する仕様を作ったりはしません。認められた働き方に合う表示条件かを確かめます。

## 再発した障害は、誤りの入口までさかのぼる

表1は、給与支給額の誤りについて、直接原因・根本原因・対応を整理した記録です。目の前の事象を直接引き起こしたものと、その背景にある原因を分けて読みます。

```text
人事管理システムで職種を誤登録【根本原因】
  → 勤務管理で超過勤務時間を誤って算出
  → 誤った超過勤務時間を給与計算へ連携【直接原因】
  → 一部の給与支給額が誤る【事象】
```

### 設問3(1) e｜改修対象は、職種を登録する人事管理システム

最終的に金額の誤りが見えたのは給与計算システムですが、根本原因は人事管理システムへの職種誤登録でした。表1の恒久対応でも、人事管理システムの入力コントロールを改修する計画になっています。

空欄の後に「システム」と続くので、eは「人事管理」です。「人事管理システム」と全部入れて文章を重複させないようにします。

### 設問3(2) f｜防ぎたいのは、従業員の職種の誤登録

超過勤務時間の算出には、従業員の所属部店・職種と、それに対応する標準勤務時間を使います。職種が違えば、適用する基準を取り違えるおそれがあります。

例えば本文の1月の標準勤務時間は、店舗の販売職では140時間、事務職では160時間です。職種を取り違えると、同じ実勤務時間でも、どの基準を超えた分として計算するかが変わります。ここでは、本文にない給与単価まで仮定して金額を計算する必要はありません。

したがって、改修で防止したいfは「従業員の職種の誤登録」です。「給与の誤りを防ぐ」は最終的な目的を示しますが、この欄では、根本原因となったどの登録ミスを防ぐかまで具体化します。

### 設問3(3) g｜確認する期限は、予定されていた3月末日

時期を並べると、確認すべきことが見えます。

| 時期 | 本文で分かること |
| --- | --- |
| X年1月 | 給与支給額の誤りが発生 |
| X年2月末時点 | 3月末日までに入力コントロールを改修する計画を記録 |
| X年4月 | 同じ根本原因の障害が再発 |
| X年5月 | 監査チームが予備調査を実施 |
| X年7月 | 監査の本調査を実施する予定 |

gは、改修の計画期限である「X年3月末日」です。本調査をする7月や、再発した4月を答える欄ではありません。

4月に再発したので、期限までに改修が行われなかった可能性も、行われたが内容が不十分だった可能性も考えられます。再発だけで、どちらかを確定はできません。だから指示は「適切な内容で、期限までに改修されていたか、確認すること」となっています。

### 設問3(1)～(3)の答案を、確認事項としてつなげる

三つの欄の公式例を、指示文の中に戻して読みます。

```text
人事管理システムが、
従業員の職種の誤登録を防止するために適切な内容で、
X年3月末日までに改修されていたか、確認する。
```

この形にすると、対象・防ぐリスク・確認する期限がそろいます。eは5字以内、fは15字以内、gは10字以内という各欄の指定も、別々に確認します。

監査担当者が確認する資料の例としては、変更内容の記録、改修後の検証結果、適用日が分かる記録などが考えられます。これらは確認方法を理解するための補足で、原問の空欄へ追加する解答ではありません。

## この大問から持ち帰ること

- リスクは、登録する情報と対象システムまで具体化し、防ぐ・見つける仕組みと結び付ける。
- 業務の変更に対応するときは、実際に認められる働き方の組合せで条件を確かめる。
- 障害は、最後に誤りが見えた場所から、原因となった情報の入口へさかのぼる。
- 再発の事実から、未実施・対策不十分のどちらかを断定せず、記録で確認する。

余裕があれば、「給与計算で誤りが出たのに、なぜ人事管理システムの改修を確認するのか」を説明してみましょう。「給与計算へ渡す超過勤務時間の誤りをさかのぼると、人事管理で職種を誤登録したことが根本原因だから」と説明できれば、システム間の関係をつかめています。
